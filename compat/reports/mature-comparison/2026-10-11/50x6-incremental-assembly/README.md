# 50x6 增量装配（P2 首刀）——ABBA 与 KKDIAG 证据

## 实验

P2 首刀：装配主环与房间查询的干净行增量维护。解码器（kkpv.js）给
变更行（新建/就地更新/签名重建）打 `CHANGED_TICK` 符号戳、归并/清扫
收集消亡 id（跨块活行经 SEEN_TICK 区分，不算消亡——跨房移动时旧房块
的归并不得误报消亡）；装配（game.js）按戳差分：干净行只做 `_` 前缀
记忆逐拍清空（tickResidentMemo），变更行按常驻元数据走值行格位迁移
（moveCell）或房整建；Room 实例与分桶数组/查询索引跨拍常驻（分类/
回填/清扫按差分驱动）；rawById 持久增量。`_` 前缀记忆保持**无条件**
逐拍清空（玩家直接挂 `_` 键不经 getter/setter、无法标记跟踪，条件跳过
曾被棘轮 UNDOC-IDENTITY-005 打回）。回退轮（跳拍/重试/块数变动）解码
器自然全量打戳，装配自动退化全量。

- 夹具：50×6 成熟房（mature-rcl8-v1，与 L1b/row-dirty 批同款
  `/tmp/l1b-fixture.json`，20,629,408 字节）。
- 协议：冻结 release 双二进制，2 个丢弃窗预热后 O,N,N,O；每窗独立进程
  warmup=5、ticks=100、concurrency=4。代理保持静默（单次通知收单）。
- 二进制：old `de51f845`（HEAD `b7341615` 期 release，stash 后构建）、
  new `670c730d`（工作区实现，含 `_` 无条件清空修正）。

## 结果（abba-summary.json）

new/old 均值：wall P50 **0.859（−14.2%）**、run P50 **0.785（−21.5%）**、
CPU core-ms/tick **0.834（−16.7%）**、RSS 峰值 **0.933（−6.7%）**、
project 0.938、settle 0.936。两对相邻窗方向一致（old1→new2 wall 0.834；
new3→old4 wall 1.131 即旧更慢）。公平门：CPU 大幅同向改善。

绝对值：old wall 503.6/487.3 → new 420.0/430.7 ms；run 219.9/224.0 →
169.0/179.3 ms；RSS 峰值 ~3.14-3.18 → ~2.93-2.96 GiB。

MEMO_MARK 条件清空的盲区）；修正为无条件 `_` 清空后复核
**2905 passed / 9 failed / 0 skipped、转红 0**（ratchet-recheck.log），
9 失败=既有豁免例，回基线。

## 结论

保留。机理落点（装配相差分）与端到端收益方向、幅度一致；CPU 同向
改善（公平门过），内存峰值更低。观察面扩展：Room 实例同一性跨拍保持
（与 wrapper/记录常驻同属已接受观察面）；Game.creeps 等分类表每拍仍为
新对象（玩家自挂键不跨拍），键序保持官方扫描序；`_` 前缀键逐拍清空
语义与旧实现逐位一致。
