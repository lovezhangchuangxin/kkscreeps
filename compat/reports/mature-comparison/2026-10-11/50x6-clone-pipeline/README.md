# 克隆-结算流水重叠：流式逐房派发（现行实现）

## 机制

R09-lite 并行结算的克隆阶段原本是相位屏障：主线程先把 300 房全部克隆
（clone 段 ~8.2ms）再连续块分片派发，工作者在克隆期间空转。本片改单
队列流式：主线程克隆一间即交付 `Mutex<Receiver>` 共享队列一间，工作者
取房即结算，克隆与结算重叠；完成消息经独立通道带回房序索引，合并仍
严格按房序（完成序不进入产物）。故障注入点按房序进入合并（与串行首
失败同位同消息），注入点之后不交付。

确定性依据不变：资格门、锁内可交换累计、serial_only 串行重做、事件房
序归并——新增重复运行确定性测试直接锁定完成序无关。流式队列同时是
R09 跨拍流水线的通道基建。

## 归因（冻结 ABBA，old=a0200227（=dddd819b 二进制），12 分钟冷却，2 丢弃+O,N,N,O）

| 量 | old | new | 判定 |
|---|---|---|---|
| **settle 相 p50** | 64.1/64.6（弃 60.8） | **58.3/58.6（弃 57.8）** | **相邻对双确认 + 丢弃对一致，−6ms（比 0.907）** |
| wall p50 | 207.2/207.7 | 196.2/201.0 | −6.7ms 中枢（0.968），量级内方向一致 |
| 工作者 settle 段（CPU 和） | 37.9-38.6 | 46.8-49.3 | **+9ms：重叠争用（分配器/缓存竞争）吃掉部分隐藏收益** |
| clone 段 | 8.1-8.3 | 9.9-10.1 | +1.8ms（通道开销+争用） |
| CPU core-ms | 100.7-101.0k | 101.9-103.4k | **+1~2%（争用的真实代价）** |
| RSS 峰 | ~3.4G | ~3.4G | 持平 |

净账：隐藏克隆 ~10ms，争用回吐 ~4ms，净 wall −6ms。低于"克隆全隐藏"
的乐观估计（重叠型收益上限 = min(被隐藏相, 窗口) 的又一实证：重叠本身
引入新成本）。project/run 相 ±3ms 摆动无机制解释，按噪声归档不采信。
