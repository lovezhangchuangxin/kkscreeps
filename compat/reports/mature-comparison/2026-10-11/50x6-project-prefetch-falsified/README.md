# 投影预取流水：两版证伪（撤回，无行为变化入库）

## 假设

相位分析显示 project 42.6 + run 108.3 + settle 66.4 ≈ wall 的 96.5%，
推断"装配（每玩家 ~0.9ms）落在派发路径上形成流水气泡 ×50 累积"，
预取（v1：一档；v2：并发+2 有界库存、循环补满）应把装配藏进等待窗，
wall −10~40ms。

## 证伪（冻结 ABBA，old=f0036d82 口径，2 丢弃+O,N,N,O，状态门放行）

- **v1（一档预取）**：丢弃对 wall 198.4 vs 197.9、project 33.2 vs
  34.2——零收益。机理：单线程上"阻塞等回执"与"装配"无法重叠，一档
  预取只是把装配挪到 recv 阻塞之前，唤醒后下一档装配仍落派发路径。
- **v2（有界库存）**：丢弃对 wall 194.4 vs 194.3——分毫不差。库存版
  确实让装配离开派发路径，但 wall 仍不动。

两版收敛结论：**project 相从未在关键路径上**。相位和 ≈ wall 是记账口径
的巧合——run_ns = 窗口 − project_ns，装配本来就嵌在 run 相窗口内的
主线程空隙里；窗口由 4 个 V8 工作者吞吐决定（50 玩家 × ~11.6ms / 4 ≈
145ms，工作者满载），主线程工作免费。把装配在窗口内挪位置不改变墙钟。

## 方法论教训（入研究档案）

"相位 p50 之和 ≈ wall"不等于各相位串行占满 wall——project ⊂ run 窗口
同样给出和≈wall。判定某相是否在关键路径，先核对该相消耗的资源是否
饱和（工作者满载 ⇒ 主线程工作已被隐藏），再决定优化方向；ABBA 丢弃对
是最终仲裁。
