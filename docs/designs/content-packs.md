# 官方内容包与玩法预设

## 状态与目标

本设计落实 [ADR-016](../decisions/ADR-016-official-content-packs.md)：官方游戏内容逐步按可选包交付，其中一部分直接使用公共 JS SDK，实现用户可选的内容组合并检验作者体验。**新世界启动期的显式包选择（下述第 1、2 步与第 5 步的场景报告部分，逐包 ID 形态）已实现**，见[内容选择](../architecture/mod-content-selection.md)；玩法预设语法、世界 manifest 记录（随持久化落实）与存量世界卸载/迁移/升级仍是目标设计。

截至 `90b670f`，JS 包装载、冻结与选择展开已实现，但 [realm.rs](../../crates/kk-mod-host/src/realm.rs) 仍固定调用 `freeze_with_builtin(builtin::link(), ...)`——builtin 内建贡献不可经选择关闭（过渡范围，随 N2/N3 逐族迁移）；[install.rs](../../crates/kk-engine/src/settle/install.rs) 依赖内建绑定和规则；其他原生阶段也未按内容选择完整门控。当前运行范围见[Mod 执行](../architecture/mod-execution.md)，首片开发见[完整玩法计划](../plans/mod-complete-gameplay.md)。

N1a 已提供[clockwork 官方生命周期原型](../../mods/official/clockwork/README.md)，经同一公共 SDK 与 sim 显式包加载验证自主对象 tick、玩家类和查询。它没有按官方 ID 提权，也尚不具备资源生产、建造或完整内容选择能力；N1b 另提供[nursery 对象操作原型](../../mods/official/nursery/README.md)，验证自主生成/更新/到期删除；这两包仍是接口原型，默认 builtin 固定装配的过渡范围仍保留。

## 职责与交付形态

| 层 | 职责 |
|---|---|
| 基础宿主 | VM、候选与发布、ID/索引、字段编码、存储、通用资源/对象/领域能力；不隐式强制启用某套游戏内容 |
| 官方内容包 | 对象与资源、动作与规则、生命周期、玩家 API，按阶段提供服务/客户端/类型/迁移；使用公共 SDK |
| 第三方内容包 | 使用同一注册与操作契约新增或替换玩法，遵守相同权限、预算与恢复边界 |
| 玩法预设 | 声明包选择和配置，供加载器展开依赖；本身不执行隐藏规则 |

经济、化学、市场、NPC 等是候选业务边界，实际拆分先核对依赖；基础内容也可以是被其他包依赖的包。“最小宿主”不自动等于一个可玩的世界，精简预设仍需选择必要基础内容。

包沿用[Mod 系统](mod-system.md)的 manifest、ESM、贡献计划和玩家/后台执行域。具体预设语法、包 ID、目录、锁文件格式尚未冻结，不能把本文当作现成配置指南。官方发行可附带包，不因此在所有世界中启用它。

## 新世界选择与依赖

装配目标顺序：

1. 读取预设、用户请求启用/排除的包与配置；解析到固定版本和实际内容。
2. 展开必需依赖并报告自动加入的包。显式排除与必需依赖相撞时拒绝该配置，列明依赖路径，不静默重新加入被排除内容。
3. 校验版本、配置、缺失依赖、循环、冲突和替换中心；冻结完整贡献计划。
4. 从实际启用的贡献生成资源/对象目录、有效规则、玩家 API/常量/类型以及服务与客户端 manifest，再开放执行。
5. 在场景报告和世界 manifest 中记录预设输入、展开后的包清单、内容/配置/计划与执行身份；预设名称或版本字符串单独不足以复现。

默认完整预设提供 vanilla 玩家契约；精简预设与自定义组合发布实际能力。未选内容的类型、动作、常量、类、图形和生命周期不得从默认包或原生阶段泄漏；非法引用在装配期诊断，玩家调用未启用能力按对应 API 契约处理。

可选依赖及能力协商若后续实现，仍须区分“包存在”和“能力启用”，并记录解析结果。当前不承诺任意内容包都能独立运行。

## 公共 SDK 与原生实现

正式官方 JS 包负责实际声明和玩法逻辑，通过公共事务能力操作候选。不得按官方包 ID 设置特殊执行权限、跳过字段校验、直接修改原生内部状态或调用第三方不可用的业务通路。

通用 native 操作或可选默认实现可以加速；其权限、表示限制、候选写面、拒绝和异常恢复必须公开。第三方同样能使用这些能力或替换策略，且不能被隐藏的默认校验再次否决。公开能力第一次需要 Rust 接线，后续同类 JS 内容应复用它。

保留已有兼容性键、数字常量和玩家类名称时，所有权与冲突按公开注册契约处理；不能用双重对象表示或覆盖保护规避装配。运行时不开动态注册，包变化只能通过已定义的安全边界重建计划。

## 四种不同操作

| 操作 | 目录/规则与数据 | 处理方式 |
|---|---|---|
| 新世界未选择某包 | 不安装该内容贡献，无该包的初始对象/行为 | 加载器根据完整选择冻结 |
| 故障后停用执行 | 当前机制保留 schema、有效规则、玩家 API 和 namespace 数据 | 屏蔽处理器及依赖闭包，使用现有缓存重试；不算内容卸载 |
| 已有世界卸载内容 | 可能存在对象、字段、库存、账户/Mod state 和依赖者 | 显式迁移/导出/删除策略与依赖检查，准备成功后整体发布 |
| 升级或切换预设 | 数据版本、目录、规则、API 与资产可能变化 | 校验新计划、迁移和重建 bundle，失败保持旧版本 |

停用、卸载与升级产生不同的执行/内容身份。引用其他包的资源、对象或字段，以及客户端/玩家旧 bundle，也需要迁移或拒绝变更。不能仅删除包文件、清空 namespace 或保留未知对象但静默失去行为。

第一版内容选择以新建世界和停服升级为主；持久恢复、缺包只读导出、迁移和 tick 边界更新依赖 N4/N6。安全边界必须没有开放或待重试轮次；不能在玩家已读取旧规则后替换本轮计划。

## 易用性与官方包验收

作者应能用模板和类型提示创建包，以公开 CLI 加载真实场景；SDK 不要求作者手工同步空间索引、回滚库存或重建状态。CLI 报告解析后的依赖、贡献链、有效规则来源、能力清单与故障绑定。工具名称和具体参数随实现冻结。

首个官方 JS 包分阶段验收：N1a 自主 tick；N1b 自主创建/删除；N2 新资源生产建筑。第一阶段没有建造/资源能力时明确登记，不能把自动计数例子当成完整生产玩法已完成。官方示例先证明接口，正式官方内容再进入常规发行与测试。

| 验收面 | 最低条件 |
|---|---|
| 独立内容 | JS 包包含声明及实际玩法逻辑；移至普通包加载位置后仍运行，没有官方专用通路 |
| 未选/选中 | 未选时无该内容 API、类型、行为或初始数据；选中后实际产生动作与状态变化 |
| 依赖与组合 | 自动依赖可解释；明确排除、缺失/循环/冲突可诊断；与至少一个其他包组合通过 |
| 公共能力充分 | 第二个独立同类包通过相同 SDK 实现不同内容，无新增专用 Rust 分支 |
| 当前内存恢复 | decline（已开放的动作）、异常、超时与晚期写回失败不泄漏候选；缓存重试不重复玩家执行 |
| 持久恢复与内容变更 | 冷恢复状态一致；缺包拒绝可写恢复；卸载/迁移失败保旧版，成功结果与依赖清理可核验 |
| 默认兼容与玩家面 | 完整默认预设持续满足兼容棘轮；精简组合的玩家 API、常量和 JSON/KKPV 投影一致 |
| 服务与客户端 | 到 N5 后由包提供服务/资产/显示与版本发布；不能用服务器侧投影代替客户端通过 |

每项注明阶段与实际完成状态。包选择迁移需要覆盖原生派发、放置/建造、玩家预检、常量、投影、存储和客户端全部消费者；只从冻结表删除一个声明不构成内容卸载。

## 性能与兼容性口径

| 配置 | 用途 |
|---|---|
| 当前原生默认基线 | 保存迁移前的功能与性能参考，注明引擎版本和工作量 |
| 完整官方预设，零第三方包 | 迁移后的默认兼容与运行成本；官方 JS 包会进入 VM |
| 功能等价的 native/JS 配置 | 核验加速实现与 JS 实现的行为差异及成本，仅在两者真实提供时比较 |
| 官方预设加第三方包 | 测组合和扩展的增量成本，记录同功能工作量 |

既有“无 Mod”历史报告保留其原配置含义。新报告显式列包清单、Native/JS 入口、计费和构建身份，不将官方 JS 调用归零或通过减少游戏内容获得性能优势。默认兼容与内容选择的验收分别进行。
