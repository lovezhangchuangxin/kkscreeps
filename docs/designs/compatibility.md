# 默认玩法兼容性要求

默认 vanilla 配置应保持官方玩家脚本可见的 API 与游戏行为。内部表示、存储和调度可以优化，但不能以性能收益为由改变返回值、指令效果或可见性。依据见 [ADR-003](../decisions/ADR-003-player-compatibility.md)。这是一项验收要求，不表示当前实现已完全兼容。

服主显式启用的玩法 Mod 可以改变规则，须发布能力与内容版本，见 [JS Mod 设计](mod-system.md)。官方 Node 进程内部的 Mod 源码兼容不在默认玩家 API 契约内；本项目以 JS SDK 提供业务扩展能力。

## 1. 玩家行为契约

| 范围 | 要核对的行为 |
|---|---|
| API 与常量 | 名称、签名、错误码、缺省值、数值范围、属性是否存在及可写性；常量从采用的上游数据生成 |
| 指令与结算 | 预检查、延迟生效、覆盖与队列规则、冲突优先级、最终状态和事件；返回 OK 不代表最终动作一定执行 |
| 对象与生命周期 | 同轮对象身份、跨轮旧引用、所有权和视野、全局集合、死亡与衰减；不能只比较序列化后的字段值 |
| CPU 预算 | limit、tickLimit、桶余额、回充、停跑、附加指令费用、超时和 halt；分别核对账单与可观察读数 |
| Memory 与 segments | 惰性解析、异常和非对象 JSON、RawMemory._parsed、写回顺序、段请求及授权、字符串长度限制 |
| 模块与沙箱 | CommonJS 包装器、require 名称处理与缓存、循环加载、代码更新、lodash、二进制模块和宿主暴露面 |
| 寻路 | 目标归一、矩阵语义、回调时序、异常、预算、结果形状与逐点路径，包括同成本路径的选择 |

API 范围以[功能盘点](../research/notes/game-api-inventory.md)和采用版本的源码为依据；旧盘点数量不能代替当前覆盖表。上游行为应记录仓库版本、文件与符号，行号只用于辅助定位。

不能用 Node 常识替代官方模块行为。例如官方循环 require 抛错，不返回半成品 exports；当前实现见 [commonjs.js](../../crates/kk-runner/src/prelude/runtime/commonjs.js)。同属 V8、复用 C++ 寻路源码或通过有限夹具，都不能单独证明完整兼容性。

## 2. 允许优化的内部机制

二进制编码、空间索引、类型分桶、存储后端、任务并行和增量传输都可以改变。验收须比较玩家实际能观察到的结果：API 返回值与异常、字段与对象身份、控制台、指令效果、世界状态和事件。非确定性输入须采用可比条件，不能要求不同机器的实际耗时逐毫秒相同。

共享内存须先按玩家权限过滤；不能把私有字段交给玩家后仅通过 getter 隐藏。并行任务完成顺序不能改变 ID、动作竞争或事件顺序。机制要求见[快照契约](../architecture/snapshot-contract.md)和 [tick 契约](../architecture/tick-contract.md)。

客户端协议另行验收 HTTP、sockjs 订阅与渲染数据，不能因玩家 API 测试通过就视为官方客户端可连接。当前网络与前端尚未实现，见[前端架构](../architecture/frontend.md)。

## 3. 边界情形的决策

| 事项 | 要求与边界 |
|---|---|
| CPU 读数 | 保持预算与计费口径，实际数值可以随机器和执行成本变化；账单与服务器资源指标分开报告 |
| Memory 优化后的计费 | ADR-003 要求按官方等价工作量保持经济语义。虚拟计费是目标政策，当前尚无完整实现或校准模型；实现时须明确公式与误差，不能宣称当前账单已等价 |
| tick 速率 | 可以调整；仍须保持逐 tick 规则，涉及墙钟的玩法单独验证 |
| 附加 API、ESM 或测试全局 | 默认关闭，显式启用时说明扩展行为；不能计作默认兼容能力 |
| 非确定性输入 | 玩家时间和随机行为与引擎结算重放分别处理；固定 seed 不保证重新执行任意玩家代码得到相同结果 |
| 官方 bug 与套件期望冲突 | 按锁定源码和上游实跑结果逐项判断；有玩家依赖或套件覆盖的行为须保留依据。不能仅为通过测试实现与官方相反的行为 |
| 宿主与基础设施故障 | 正常玩家结局与线程失联、结算失败分开报告；当前内存候选回退不承诺 V8 全局、跨线程或磁盘事务恢复 |

字符串限制要注明单位。当前 RawMemory.set 与 segment 校验按 UTF-16 码元计数，Memory 自动序列化没有同一长度检查路径；“2MB”或“100KB”不能作为所有写入方式的统一字节保证。计费、模块和内存机制见[沙箱说明](../architecture/sandbox.md)。

## 4. 当前已核实的差异与限制

以下是已按当前代码核实的重要边界，包含缺失能力和可观察的行为差异；不是全部失败用例清单。修复时须同步更新说明与验证依据。

| 范围 | 当前行为及影响 | 依据 |
|---|---|---|
| 玩家寻路 | PathFinder.search/Room.findPath/moveTo 已接原生搜索与同步回调（结构/creep/道路矩阵、嵌套、原值异常与预算终止）；stable vanilla 的 findClosestByPath 固定 range=1、疲劳+路径绘制仍重算与套件预期不同，已登记 parity；未注册房按全墙边界处理（起点在墙环外抛 `Could not load terrain data`），垃圾数值选项的确定性归一与官方未定义行为不同 | [地形直通设计](pathfinder-terrain.md)分歧表、[回调接入设计](pathfinder-callback.md)、crates/kk-runner/src/pathfinder.rs |
| 地图数据 | 出口按坐标推导，缺少官方地图连通标记；getRoomStatus 只覆盖 normal/closed，getWorldSize 固定为 1，距离不实现完整环绕世界语义 | prelude/game/game.js 的地图接口 |
| halt 生命周期 | 中断执行并跳过写回，当前不生成费用，但继续复用 V8；不能视为官方销毁实例的完整等价实现 | [沙箱说明](../architecture/sandbox.md)、sandbox.rs::after_halt |
| CPU 与堆统计 | getUsed 使用墙钟；堆统计在本轮开始时采样，堆外内存不构成完整限额或峰值报告 | kk-runner 的 sandbox.rs、ops.rs 与玩家 cpu 接口 |
| 常量可变性 | 部分玩家全局对象常量被就地深度冻结；玩家修改或 strict 模式报错行为与上游未冻结副本不同 | prelude/game/creep.js、structures.js 的 freezeConst |
| RoomPosition 构造器 | 当前采用 class，无 new 调用的错误文案与 prototype 整体重绑行为不能按上游函数构造器保证 | prelude/game/room-position.js |
| 通知 | Game.notify 在内存中保留有界记录，没有邮件或外部通知发送通路 | kk-engine::PlayerState.notifications 与 publish_tick |
| 结算时间 | 同轮签名等处理共用 TickInput.now_ms；上游各动作单独读取 Date.now，跨毫秒边界可能观察到差异 | kk-engine::TickInput 与 sign_controller |
| suicide 后续指令 | 对象删除后，当前后续动作重新查找对象并跳过；上游仍可能持有先前对象引用，后续指令行为不同 | settle/creep/lifecycle.rs::intent_suicide |
| 失败恢复 | 结算返回错误时缓存玩家输出并保留旧状态；V8 全局不回退，CPU 提交通信错误不回滚世界，执行阶段基础设施失败也没有完整恢复状态机 | [tick 契约](../architecture/tick-contract.md)、kk-runtime::EmbedEngine |
| 快照与场景输入 | 查询投影、沙箱投影和二进制编码是不同契约；管理查询不按玩家视野过滤，受信场景输入也不能当作玩家 API | [总体架构](../architecture/overall.md)、kk-runtime::EmbedEngine |

墓碑、废墟、多资源槽、玩家身份清洗和私有宿主句柄等已有实现，不能再沿用早期“尚未支持”说明。其完整覆盖仍以源码与行为测试核实，不因旧记录写有修复就推导全部用例通过。

## 5. 差异登记与验收

新增或修改差异时应写清：触发条件、官方行为、本项目行为、玩家可观察的影响、采用的源码版本与验证方法。已经修复的条目说明修复后的机制，过程和旧结论保存为历史证据；纯性能成本不应伪装成 API 差异。

- `screeps-ok` 使用锁定版本、重新构建的引擎和完整报告，检查通过数下限及逐用例回归。
- bot 验收同时查看缺失 API、异常、桩调用和实际游戏进展。固定世界的 bot-check 不执行结算，不能证明 bot 全功能可玩。
- 网络与客户端接入单独验证认证、代码管理、订阅、控制台和渲染，不能由环境测试或占位包证明。
- 性能对照先核对功能工作量和关键状态，不能通过跳过兼容用例或减少预算获取性能结果。

机器报告、预期差异、跳过和回归豁免的作用各不相同，具体规则见[验收工具说明](../../compat/README.md)。登记 expected_failures 不会自动豁免回归；通过率下限也不能证明每个 API 都已正确。

原来的完整登记表与后续追加行保存在[兼容性历史登记](../research/notes/compatibility-register-history.md)。其中有已修复、重复和待复核条目，查某项问题时应连同对应提交和当前实现核实；历史登记不直接作为当前完成或未完成状态。
