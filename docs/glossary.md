# 术语词典

本词典解释注释中容易混淆的游戏与架构概念，配合[代码注释规范](contributing/comment-style.md)使用。收录术语不等于允许用它替代具体说明；注释仍须写清对象、条件和结果。不将词典当作专业术语白名单，也不要求把 Rust、JavaScript 的通用术语逐一登记。

## 游戏概念

| 术语 | 含义 |
|---|---|
| tick | 游戏推进的一轮。世界的 tick 值表示推进次数，不是 Unix 时间 |
| intent | 玩家发出的动作指令，由结算阶段处理；API 返回成功不代表动作最终一定执行 |
| creep / spawn / controller | 游戏单位、孵化结构和房间控制器，具体行为以玩家 API 与结算规则为准 |
| RCL | 房间控制器等级（Room Controller Level） |
| energy | 游戏资源“能量”，不是余额的单位 |
| credits | 市场货币。当前本项目 `PlayerState.money` 使用整数千分之一 credit；玩家 API 读取时除以 1000。不要将此表示推广为所有资源或上游存储的统一单位 |
| CPU 桶（bucket） | 累积的玩家计算配额。当前默认容量上限为 10000；正常结算加入 limit 并扣除计费量。轮次开始时余额为负则停跑；停跑恢复量和何时提交分别由预算与协调层处理 |
| 桶下限 | 停跑恢复公式使用的 −2×limit。它不是余额在所有时点都不会低于的硬下限，正常计费可能产生更低余额 |
| power / powerCreep | Screeps 的能力机制和对应游戏对象；实现范围查当前能力记录，不在词典中绑定易过期的里程碑 |
| shard | 世界分片；inter-shard 表示跨分片 |

## 当前实现中的架构概念

| 术语 | 含义 |
|---|---|
| 候选状态 | 已计算、尚未提交的数据。失败时如何处理取决于候选类别，不能统称“全部丢弃”，见下文 |
| 已提交状态 | 当前生效的状态，不意味着已写入磁盘 |
| 统一提交点 | 协调玩家执行结果与世界结算的提交边界。当前 `EmbedEngine.run_players` 在世界结算成功后提交玩家 Memory 和 CPU 计费；结算返回错误时保留运行结果供重试。此处不保证 panic 或进程崩溃时具备磁盘事务恢复 |
| generation（内容版本） | `World` 的版本标识，供缓存失效和恢复检查使用。可变访问也可能保守增加版本；整房提交在结算尾统一增加版本，不是“每个字段改动都加一次” |
| worker epoch / RunEpoch | 玩家派发与回执的轮次标识，由 tick 和 generation 组成。协调器检查回执是否属于本轮；不能与单个 generation 值混用 |
| 墙钟时间 | 系统实际时间；`TickInput.now_ms` 使用 Unix 毫秒，与游戏 tick 不同 |
| 确定性重放 | 在相同初始状态、指令和外部结算输入下重复得到相同结算结果。这里描述引擎结算，不承诺再次执行任意玩家 JS 也必然相同 |
| 二进制房间快照 | `kk-schema` 编码的房间数据 |
| 查询快照 | 适配器查询使用的 JSON 输出，由 `snapshot.rs` 等构造 |
| 沙箱世界数据 / 投影 | 注入玩家运行环境的 JSON，由 `world_json.rs` 等构造；按查看者过滤时只提供其可见数据，与查询快照字段可能不同 |
| 上游源码引用 | 用仓库、文件、符号或辅助行号定位行为依据；行号本身不能证明结论 |
| 兼容性差异记录 | 记录与采用的上游行为不一致之处，见 [compatibility.md](designs/compatibility.md)。用例 ID 与内部评审编号含义不同，不能一并删除 |
| 棘轮 | 防止指标变差的检查机制。兼容性通过数下限已实现；注释问题基线只减不增仍是提案。具体数值读取实际基线文件，不在词典中复制 |
| 测试判别力 | 测试区分正确与错误实现的能力。可以解释哪种错误会使断言失败；是否需要变异测试依改动决定，不对每次断言修改强制要求 |
| 测试开关 / 故障注入 | 用于构造测试条件或模拟失败的接口。是否公开、是否只在测试构建编译，按实际实现说明；`doc(hidden)` 仅隐藏生成文档 |
| isolate | V8 的隔离运行实例。当前玩家线程持有自己的沙箱；生命周期与销毁约束见运行时实现 |
| prelude | 注入玩家沙箱的预置 JavaScript，包含游戏 API 实现 |
| FFI / ABI | 跨语言调用接口 / 二进制调用约定；安全条件须在具体接口附近说明 |

### 失败时保留什么

当前 `Engine` 结算失败时，丢弃尚未提交的房间、玩家状态副本和市场候选。`EmbedEngine.run_players` 则将玩家运行结果和首次 `TickInput` 缓存在 `pending` 中，重试复用它们，不再次执行玩家代码。显式放弃该轮时才清除这份缓存。

这些说明针对上述入口及返回错误的路径；基础设施故障、直接结算入口、panic 和进程崩溃不应自动套用同一保证。

### 内容版本的边界

当前成功结算在提交尾调用 `World.advance_ticks(1)`，内容版本增加一次。`room_mut`、`get_mut` 等方法取得可变访问时也会保守增加版本，即使最后没有修改数据。`commit_room` 本身不增加版本，调用者须按提交协议更新版本。版本不能简单等同于字段修改次数。

## 设计中的扩展概念

| 术语 | 含义与状态 |
|---|---|
| 贡献平面 / ContributionPlan | [ADR-014](decisions/ADR-014-contribution-plane.md)提出的 Mod 贡献合并与启动冻结机制，属于目标架构，不表示当前完整实现 |
| EffectiveRules | ADR-014 中用于承载可覆盖数值规则的数据表，与 ContributionPlan 是不同概念 |
| slot | ADR-014 中具名的行为槽位，可对应默认实现或处理链；具体实现与验收仍按相关设计推进 |

## 状态与数据表示的区别

候选与已提交描述数据是否生效；沙箱世界数据、查询快照和二进制快照描述用途或表示。数据库写入和磁盘持久化另行说明。它们不是“候选 → 已提交 → 沙箱 → 查询 → 磁盘”的固定流水线，查询也不是写盘的前置步骤。
