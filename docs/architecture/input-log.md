# 持久输入与玩家结果日志

本页是 G25.a 交付的输入日志（input log）契约：每个**成功提交的结算轮**
之后，把该轮的全部外部输入与消费的玩家写回追加到一份可校验的 JSONL
文件，作为未来确定性回放（G25.b）的权威输入源。检查点的整体机制见
[基础检查点](checkpoints.md)，逐域状态清单见[状态域清单](state-inventory.md)，
玩法侧的确定性时间/随机协议见[确定性玩法时间与随机协议](gameplay-determinism.md)。

## 目标与边界

- **记录**（本批）：轮输入的持久化与完整性校验。文件能证明「这轮以什么
  输入提交」且任何事后改动可检。
- **回放**（G25.b，未实现）：从检查点 + 日志重建世界并逐轮重放。本批
  只保证回放所需的输入面完整落盘，不实现消费端。

回放一个已提交轮需要的输入恰好是四件事：恢复点（检查点，已有）、
墙钟 `now_ms`（订单过期与控制器签名用）、意图批、玩家写回中的 CPU 新桶
（口径见 ADR-013 决策 5：墙钟等输入首次执行采样、重试和重放使用记录值；
回放直接消费记录的桶，不从实测值重推）。日志按此清单记录，不记录诊断面
（expr/console——`last_console` 已随检查点）。

完整性边界要如实表述：哈希链能证明「读到的前缀逐段未被改写」，但**不能**
证明前缀之后没有内容被截掉——删除任意后缀（含只删最后一段）后的文件
仍然合法，与崩溃丢尾段（RPO=1 轮）不可区分。后缀完整性由与检查点的
配对规则（见下）与外部留存承担；篡改检测针对改写、插入、删中段、换头。

## 文件协议

单文件 JSONL，每行一个 JSON 对象，逐段 `fsync`：

- **头段**（首行，seq 0）：`format: "kkscreeps-input-log"`、`version: 1`、
  `kind: "header"`、`prev_hash: null`、`identity`（启用时的引擎版本/
  世界种子/PlanHash/执行策略/停用集）、调用方 `metadata`（sim 放场景与
  可执行文件摘要；仅诊断，不参与链）。
- **段**（后续行，seq 从 1 连续递增）：轮身份（`tick`/`generation`/
  `source`）+ `now_ms` + `intents` + `players` + 逐段 `identity` 快照 +
  `prev_hash` + `sha256`。

**链与摘要**：`sha256` 覆盖「去掉自身后整行再序列化」的字节；`prev_hash`
直接取上一行的 `sha256` 字段值（即上一行体的摘要）。键序由 serde_json 的
BTreeMap 排序决定，写入与读回两侧同序，因此复算不需要保留原始行。改写
任何**字段值**会同时破坏自身摘要与后续链接；不改变解析后 JSON 值的字节
级重排（空白、`\u` 转义、键序）不会被摘要发现，但对回放语义无损。头段
的 `metadata` 被头段摘要覆盖（篡改可检），但不像段那样参与逐段身份。

**读取器**（`kk_runtime::embed::read_input_log`）逐行校验：JSON 合法性、
摘要复算、seq 连续、链衔接、必需字段形状、头段形状。撕裂只可能发生在
未换行结尾的尾块（写序=行体、换行、fsync）：尾块非法 UTF-8（切进多字节
字符）或末行呈三种**物理撕裂签名**（解析失败/摘要不符/缺 `sha256`）收敛为
`TornTail` 并携带完整前缀段数——截断恢复的依据；其余错误（段号断链、链
断裂、未知版本等）即使落在末行也保留具体变体，因为截断不可能改写段号或
指针。头段行的失败保持 `BadHeader`（含末行位置），不收敛撕裂。能整体
解析且校验通过的无换行尾块作为末段接受（内容已完整，仅换行未落盘），
但**续接写入**要求文件以换行结尾——append 会把新段拼进缺换行的旧行、
静默毁掉日志，此形态拒绝续接并指明修复方式。未知 `version` 显式拒绝、
无迁移（与检查点格式版本的纪律一致）。

## 段内容

`source` 有三种，对应库层三个提交咽喉：

| source | 触发入口 | `intents` 形态 | `players` 形态 |
| --- | --- | --- | --- |
| `players` | `run_players`（含缓存轮重试成功） | 每个请求句柄一列沙箱**原始**意图报告（`RunResult.intents_raw`，对象 ID 直键；自报键原样保留） | 每玩家：CPU 新桶整桶、`cpu_billed_ms`（实测佐证，回放不消费）、RawMemory 候选、段写回候选 |
| `external` | `settle_external` | `IntentBatch::to_json` 的玩家键规范形态（`from_json` 的逆；房间/通知/市场在各自容器分组） | 空对象（外部轮不提交玩家状态） |
| `advance` | `tick`（每轮一段） | 空对象 | 空对象 |

`intents` 与 `players` 对三种来源都是必需的对象字段（空轮记空对象），
读取器按此形状硬校验。

玩家轮记录**原始**报告而非清洗后的批：回放要把同一份字节喂回
`IntentBatch::from_json` 重走清洗，才能证明清洗规则本身没有漂移。

每段自带 `identity` 快照（PlanHash/执行策略/停用集）：运行中的包切换
（见 [Mod 切换](mod-switching.md)）后，后续段以新身份自描述，读回时
逐段可判。头段身份只是启用时刻的快照，不是全文件约束。

## 写入时序与崩溃语义

写序在**引擎提交之后**：段写入失败或进程崩溃时，最多丢最后一轮的段
（RPO=1 轮），世界可能领先日志头一个 tick。由此的配对规则（G25.b 回放
入口实施）：**检查点不得领先日志头**——从检查点恢复后重放，必须从日志中
第一个 `tick` 不小于检查点时间的段开始。

日志写入失败（I/O 错误）时：本轮世界**已经提交**，日志被立即摘除停用
（链已与世界脱节，不可续写），调用收到带「已提交、不得重试结算」字样的
错误。这是诚实上报，不是可重试故障。

失败轮/被丢弃轮**不记段**；缓存轮重试成功只记一次（重试复用首次的
`now_ms` 与轮身份，不重新采样）。RNG 无需记录抽值日志：玩法随机流自
G22.b 起无状态（见协议页），重放同输入即同抽值。

## 生命周期

- **挂载**：`EmbedEngine::enable_input_log(path, metadata)`。门禁：无
  开放轮次（失败轮缓存/恢复态均拒绝）；一个分片运行期只挂一份。文件
  不存在则新建写头段；已存在则**先整读校验**（撕裂/断链/坏段拒绝）且
  要求以换行结尾（缺换行＝末行未完整落盘，拒绝续接防 append 拼接毁
  日志），从末段续接，seq 延续。段数计数按整个文件（含续接时既有的段）。
- **摘除**：`teardown`、重建分片、包切换、检查点恢复都会摘除运行期日志
  （磁盘文件保留，可再次挂载续接）。摘除是静默的——这些操作改变世界
  连续性，续接配对由调用方用检查点显式表达。

## 调用面

- **sim**：`sim run --input-log PATH`。分片就绪后、首轮执行前挂载；
  报告 v8 顶层 `input_log` 字段（段数、读回段数、首末 tick、校验结果）。
  两种降级形态如实区分：setup 阶段失败（含损坏日志拒绝续接）报
  `status: "setup_failed"`；运行期日志被摘除（包切换/检查点恢复/重建
  分片，或写入失败——后者错误文案见 `failure`）报 `status: "detached"`
  并对磁盘上已有的段照常读回校验。运行结束整读校验一次并写入报告。
  路径守卫与报告/检查点同规：不得位于任何 Mod 包根内，也不得与报告、
  场景或检查点路径相同（临时文件+原子替换写会互相覆盖）。
- **embed RPC**：`enableInputLog {path, metadata?}` 与
  `inputLogSegments`；语义与库面一致。

## 变更纪律

- `LOG_VERSION` 升版＝新文件格式：读取器拒绝旧版，写入器不写旧版；
  没有迁移（仅本地开发，无存量文件可迁）。
- 段字段属协议面：增删字段升版；`metadata` 与诊断字段除外。
- 篡改矩阵（字节翻转/删行/乱序/撕裂尾/换头/未来版本/空文件）在
  `embed_tests/input_log_family.rs` 逐变体钉死具体错误；改动读取器
  须保持每个变体仍命中可区分的错误。
- 外部轮的意图线格式经 `IntentBatch::to_json` 规范化：价格毫单位的
  反解发射保证 |milli| < 2^52 内往返逐位精确（`to_json_tests` 以混叠带
  扫描+抽样钉死）；线字段增删同 `LOG_VERSION` 升版口径。
