# 房间快照与共享视图契约

本文区分现行房间快照、KKPV 玩家投影与共享直读的目标格式。当前已有类型化世界、顺序二进制编解码、KKPV 共享块通路及独立的[完整状态检查点](checkpoints.md)。KKPV 投影与权威持久快照采用不同格式，当前仍需沙箱解码与对象装配；下文的列式共享直读、多文件 manifest 与房间二进制历史迁移是目标设计。设计依据见 [ADR-004](../decisions/ADR-004-core-architecture.md)和 [ADR-013](../decisions/ADR-013-architecture-review-coordinator.md)。

## 当前版本与编码边界

`World.generation` 表示整个世界的内容版本。受控编辑成功和整轮房间提交均推进版本，账户/市场编辑也会失效旧回执。外部不再取得整房可变引用；`commit_tick_rooms` 先验证完整候选再同时更新时间和缓存，错误不会发布房间前缀。引擎发布路径走 `_prevalidated` 变体，仅跳过与引擎验证阶段重复的对象不变式扫描，先验证后写入的语义不变。generation 不等于对象实际修改次数，详见[权威状态编辑](state-editing.md)。

`terrain_epoch` 用于地形缓存失效。`RoomVersionHandle` 保存房间名、tick 和世界 generation 等标识，不持有固定的不可变字节；其他房间的变化也会影响其世界版本。`WorldSource` 同时提供 JSON 投影、KKPV 束及信封读取入口。

KKPV 路径将公开地形束以不可变共享句柄交给玩家沙箱；房间对象编码按代际与资格复用，同可见集玩家在世界资格满足时复用私有束，权限相关内容走逐查看者投影。runtime 的 `KkpvBlockStore` 管理发布与旧读者保留，不能原位覆写仍被引用的字节。沙箱仍解码并维护常驻记录、行脏位与查询索引，未实现目标中的字段 getter 直接读取共享列。Mod/扩展/私有字段不满足共享资格时保留通用裁切路径；共享资格与代际失效由现行实现检查，不仅依据房间可见性。

`kk-schema` 使用声明顺序的紧密编码，字符串为 UTF-8，整数为小端；宏偏移只覆盖简单定长字段前缀。完整快照解码检查魔数、版本、载荷和尾部字节，但业务坐标、ID 唯一性及独立的解码资源限额仍需调用方处理。它不是下文所述的列式共享格式。

Generic 的 `data` 在内存中使用 `GenericData`：Arc 共享不可变原始 JSON 文本，惰性缓存少量类型/归属、observer 与衰减门字段；不保留完整解析树。候选克隆共享载荷，写入通过新文本整体替换（`String::into()`），旧候选/世界的缓存不受影响。无效 JSON/非对象、转义键、重复键及字段类型读取保持 serde_json 语义。二进制 data 仍为原 String 的长度与 UTF-8 字节，不改变 tag/版本；缓存不保存，恢复后按需重建。动态字段与 Mod 建筑载荷仍完整保存，权限与规则目录在消费层处理；Generic 载荷共享本身不等于整房写时复制或沙箱共享直读。取舍见 [ADR-019](../decisions/ADR-019-generic-payload-metadata.md)。

首个持久化版本发布前可调整实验布局；发布后布局与升级规则必须作为格式契约维护。

## 目标格式：一个版本、两种使用方式

2026-10-11 的[重构目标](performance-target.md)进一步区分权威内存页、授权玩家内容与持久化格式，并拆分本次投递 epoch 和内容版本。下列单段快照布局仍可作为 full 编码参考，不要求新 RoomStore、玩家增量页和检查点三者物理同形；具体替换由 R04/R06 的版本与生命周期验收决定，不能提前视为已实现。

每个房间的已提交版本是一段**不可变字节**加一个 `SnapshotHandle`（房间名、tick、
代际号、字节长度及共享存活句柄）。检查点保存完整权威版本；沙箱只读取其中已授权的公共字节和私有视图。二者绑定同一世界版本，不要求向玩家暴露完整检查点载荷。
Rust 的 typed world 是构造与结算视图，不能因此把 Rust struct 的进程内内存布局
直接写盘。编码格式的小端字节序、字段宽度与边界校验是跨平台契约。

目标布局分四段，具体常量由同一份 schema 声明生成给 Rust 与沙箱 getter：

| 段 | 内容 | 访问要求 |
|---|---|---|
| Header + terrain | magic、版本、总长度、tick、代际号、各段偏移；50×50 地形 | 固定宽度，可直接定位 |
| Object directory | 按全局对象 ID 排序的 `(id, type, row)` | 二分查找；禁止重复 ID |
| Type buckets | 每类型的字段表及固定宽度数值列 | getter 由类型、列偏移和 row 定位，不逐字段回调宿主 |
| Variable arena | 名称、body、Store 扩展项及其他变长载荷 | 固定区只保存 `(offset, length)`；首次访问再解码 |

所有偏移和长度都相对快照起点，不能指向段外、溢出总长度或彼此覆盖到非法区域。
一个对象的 `id/type/row` 只能指向自身类型的有效行；对象坐标必须在 0..49。
长度、行数与房间字节上限均在解码前检查，拒绝畸形输入；上限值在共享视图原型中
依据官方可导入的最大房间与内存基准确定。内部 `Generic` 透传对象可以保留不透明
载荷，但不得绕过目录、坐标与长度检查。

**固定宽度字段**的 getter 读共享字节并按 schema 类型转换。字符串和数组需要按
arena 描述符惰性解码与按代际缓存；文档中的“约 2 纳秒属性读取”只可用于相应的
原始字段微基准，不能外推至字符串、对象包装或完整 tick。类型分桶与列布局的
收益须按[性能验收](performance-acceptance.md)的端到端场景确认。

## 代际、双缓冲与旧引用

已发布的 `V_t` 在本轮玩家读取期间绝不原位修改。结算器构造 `V_(t+1)`、校验后
一次切换**世界级版本指针**（它引用各房的 `SnapshotHandle` 和玩家状态版本）；
读取方先固定世界级版本，再取得带代际的房间只读句柄，直到本轮结束再释放。
“双缓冲”指相邻两个**逻辑版本**，不是强行复用两个物理内存槽：若慢读者仍持有旧
版本，旧字节须保留；运行时应记录被固定的代际和字节数，并对超时读者执行既定
沙箱终止流程，防止无限积压。

玩家缓存的游戏对象包装器保存 `id` 与可见性上下文，**不长期保存裸偏移**。
跨 tick 访问时按当前已提交代际重新查目录：对象仍存活则读新版本，已删除则按
官方行为使引用失效；对象跨房时按全局 ID 路由到新房间。具体失效时的 getter
返回值与错误形态以 screeps-ok 对照锁定，不能仅凭 Rust 的 `Option` 自定。
同一 tick 内所有 getter 必须绑定同一个版本，不能一半读旧房、一半读新房。

每个玩家只收到其有权看到的房间句柄和世界级数据通道。房间可见也不代表其中所有字段公开；owner/server-only 字段须在宿主侧分离或裁切，不能先把完整 buffer 交给玩家，再靠 getter 隐藏。公共字节可以共享，私有 overlay 必须与查看者和代际绑定。玩家代码不能获得未授权字段、任意房间的原始缓冲区或宿主可写句柄。视野改变
时，下一代视图重新核准权限，旧引用仍受当前可见性检查。

## 世界级提交与磁盘恢复

房间字节并不包含全部世界持久状态。一次检查点还需要 manifest，至少记录已提交
tick、世界种子、全局下一个对象 ID、玩家持久状态及市场状态版本、房间名到快照版本/校验值
的映射。先写完所有候选数据，再原子切换 manifest；恢复时只接受完整且校验通过
的 manifest。休眠房可合法复用旧房间字节，但必须由该 manifest 明确引用；不能从
各房独立选“最新”而拼成未提交过的世界。

若持久化只使用定期检查点，崩溃后最多丢失上一个完整检查点之后的进度；该 RPO 必须
按实际间隔报告。要达到“接近零丢失”，还需持久化足以重放的 tick 输入与玩家
持久状态变化，并规定日志与 manifest 的写入顺序。**玩家 JS 不在恢复时重新运行**；
回放输入是已采集的指令、运行结局、引擎种子与必要的全局操作。这里描述完整耐久恢复的目标；现行[输入日志 v2](input-log.md)只保存玩家 Memory 摘要，结算回放用于核对，目录恢复则回滚到检查点、截断未确认分支并重新执行玩家代码，不能承诺直接恢复到日志尾。

首个持久化版本发布后，任何字段或布局变化必须提升 schema 版本，提供旧版读取、
升级和重新写入路径；变体 tag 不可重用。升级函数须在隔离工作区完成，并与普通
解码一样执行完整边界和对象不变量检查。未知未来版本明确拒载。

## 冻结格式前的验收

1. 同一房间在 typed world → 字节 → typed world 往返后，所有已支持字段与对象序
   一致；沙箱 getter 与 JSON 参考投影逐字段对照。
2. 字符串、空数组、最大 body、Generic、对象增删/跨房、旧引用存活/失效分别覆盖；
   坏偏移、截断、重复 ID、越界坐标、未知版本均拒载且不触发越界读取。
3. 慢沙箱固定旧代际时，新代际可发布但旧字节不被覆写；超时终止后固定量归零。
4. 在检查点各写入阶段注入崩溃，只能恢复到某个完整的已提交 tick，玩家状态与
   全局 ID 不能领先或落后于房间集合。
5. 同房不同玩家读取公共字段一致，私有字段仅向授权者提供；直接读取缓冲区、旧引用和权限撤回均不能越权。
6. 报告每房字节数、编码/校验耗时、一次 tick 的复制字节数与峰值固定代际内存；
   未达到共享直读收益时允许调整布局，再冻结首次持久化版本。
