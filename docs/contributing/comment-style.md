# 代码注释规范

本规范规定代码注释的内容、表达、来源引用与审查要求，帮助维护者准确理解代码行为、设计原因和使用限制。

## 1. 目的与适用范围

注释面向熟悉 Rust 或 JavaScript、了解基本 Screeps 概念的维护者，不以参与过项目开发或评审为阅读前提。

质量判断的优先顺序为：事实正确、信息必要、含义明确、容易阅读、形式统一。简短不能弥补事实错误；解释安全条件所需的长注释可以保留。

本规范适用于本项目维护的 Rust、JavaScript、TypeScript、C/C++、脚本和配置中的注释。第三方源码、许可证和已归档的原始实验记录保留原文；生成文件的注释应在生成器中修改。项目自行维护的实验代码适用本规范。

## 2. 基本原则

1. **事实准确**：注释描述当前实现，不将设计意图、历史状态或未经核实的推断写成事实。
2. **信息必要**：优先解释代码本身不容易表达的原因、限制和特殊行为，不重复明显的操作。
3. **表达明确**：写清对象、条件和结果，不要求读者了解开发批次、评审过程或会话背景。
4. **依据可查**：外部行为和设计约束有可定位的来源，引用不能代替解释。
5. **边界完整**：保留单位、取值范围、缺省值、执行顺序、安全条件与兼容性例外，不为缩短文字删掉关键信息。
6. **同步维护**：行为、接口或文件位置变化时，同步更新注释及其引用。

详细规则见第 3 节，正反例见第 9 节。

## 3. 内容与表达规则

注释应符合以下规则。规则编号用于审查和示例引用。

| 编号 | 规则 | 不合格示例 | 合格方向 |
|---|---|---|---|
| C01 | **现状性**：注释描述当前实现；过期声明、已移除的限制、已实装的"桩面"说明必须删除或改写 | "M1 不结算市场"（实际已结算） | 描述现有职责；剩余限制写具体功能并链接跟踪记录 |
| C02 | **不依赖开发背景**：不依赖批次号、切片号、评审轮次、模型名或会话背景；检查编号须就地解释。稳定的用例 ID、问题链接和 ADR 编号可以作为辅助来源 | "B0-6 P2-2 清偿"、"GPT 复审"、"门④可信侧兜底" | "玩家已有生效的安全模式时，Rust 结算根据已提交的世界状态丢弃其再次激活指令" |
| C03 | **开发历史另存**：变更叙事（曾 / 此前 / 原实现 / 第一版 / 重构前 / 勘误史）不进注释，归 commit 与批次文档。**边界**："为什么不能写成另一种样子"的反例说明属于约束而非考古，保留——但写成现在时约束句 | "勘误（双房批外部复审 P0）：原实现 (bucket+limit).max(−2×limit) 是先加再钳……" | "注意顺序：先将原余额与 −2×limit 比较，再选择恢复方式。写成 `(bucket+limit).max(−2×limit)` 会在余额属于 (−3×limit, −2×limit) 时得到不同结果（make.js:77）" |
| C04 | **上游可核验**："官方"断言必须跟随 `文件名:行号` 或 `路径/文件+符号`；禁止裸 `:行号`（脱离上下文无法定位）；本地路径引用必须当前可解析 | "官方 :192"、"按硬约束①" | "此函数检查控制器等级和所有权；无主结构由调用方另行处理。来源：上游 utils.js 的 checkStructureAgainstController" |
| C05 | **判断有据**：绝对措辞（不可达 / 零开销 / 全链已锁 / 完全兼容 / 逐字一致）必须指明机制边界（类型/可见性/配置/测试覆盖）；测试证据须说明场景与覆盖范围，不能将有限测试当作普遍保证。依据不足时缩小断言或标记待核实 | "生产面不可达"、"零差异" | "该入口仅 `cfg(test)` 编译（真正隔离）；`#[doc(hidden)]` 只隐藏文档、不阻止调用" |
| C06 | **状态词精确**：区分候选状态 / 已提交状态，以及沙箱数据 / 查询输出 / 磁盘数据的用途；这些不是连续五个状态；"落库"只用于实际数据库写入，"落盘"只用于实际磁盘持久化；描述内存更新时写明对应结构与提交时点 | "Game.notify 落库"（实为内存 Vec） | "加入保存于 `PlayerState` 的通知列表（跨 tick 保留；当前未写入数据库）" |
| C07 | **必要技术信息不丢**：单位、取值范围、缺省与特殊值、例外路径、执行顺序、安全条件不因追求简洁而删 | "与官方一致" | 说明哪个行为一致，尤其容易被误改的特殊输入（undefined vs 0） |
| C08 | **来源不代替解释**：先说明当前约束，再引用设计依据；较长引用单独成行。ADR、设计和稳定计划条目均可引用，不能要求读者先读批次历史才能理解 | "见评审 2 P1 清偿" | 先解释为什么重试复用墙钟输入，再链接 ADR-013 的相关决策 |
| C09 | **句式**：先结论后出处，一段主要解释一个要点。避免连续嵌套括号和过长句子；多步流程可使用列表或箭头。长句按项目格式规则自然换行，不设机械的箭头、括号或行宽硬限制 | 一句话混合多个条件、例外与评审历史 | 拆句、拆段或列表；保留必要条件 |
| C10 | **不复述代码**：不解释下一行在干什么（`// 加一`）；无信息的模板注释不写 | `// 遍历 rooms` | 删；或写业务原因 |
| C11 | **推断标记**：未核实的上游断言明确标"待核实"并给定位途径，不把推断写成事实 | "官方永远不会这样调用" | "尚未验证此输入在上游是否可达（待核实：engine/src/processor/）" |
| C12 | **同步维护**：路径、符号、单位、状态随代码同改；**注释-only 改动不得夹带行为变更**（发现代码错误另立修复提交） | 搬移后仍引用 `creep.rs` | 指向当前模块 |

"必须 / 不可 / 不能"可以用于真实的安全或业务约束，但须写出适用条件——禁止的是无依据的保证，不是表达强度本身。

## 4. 语言与术语

### 4.1 语言约定

说明性文字默认简体中文；代码标识符、标准技术术语、兼容性要求的原始字符串保持原样；许可证与逐字引用不翻译。中文句子尽量完整：先对象和行为，再原因，最后限制或来源。不强制"用途/原因/风险/来源"四标签，不要求每个函数都有注释。

### 4.2 术语

- **长期架构概念**可在[词典](../glossary.md)解释，在具体注释中仍须写清对象、条件与结果：tick、intent、候选状态、已提交状态、统一提交点、generation（内容代际）、worker epoch、棘轮、差异登记、官方锚、判别力、测试旋钮、isolate、FFI 等。
- **一次性黑话**改写为具体行为，不需要建立词条：收口/清偿/销账→删除交付过程叙述，保留当前行为；真化/转真→"改为调用真实实现"；读面/消费面→"读取方/调用点"；同门/门④→写出检查条件；壳/幽灵壳→"缓存的对象引用（对象可能已不存在）"；同形/同构/口径一致→写出具体相同的字段、顺序或计算方法；回血/深负钳→"恢复桶余额/限制到下限"；本片/本批→删除。
- 高频消歧（完整版见词典）：**"地板"**在测试语境是"棘轮通过数下限"、在预算语境是"桶下限"，二义都必须展开；**generation（世界内容版本）与 epoch（worker 轮次）**是两个概念不可混用；**"快照"**必须区分二进制房间快照（kk-schema）/查询快照（snapshot.rs）/沙箱世界数据（world_json.rs）三种输出。

改写表用于人工审查，不做全仓字符串替换；"模式匹配分支""孵化""看门狗"等在准确上下文可保留。检查器不对所有"臂/门/壳"一律报错。

## 5. 信息归属

| 信息 | 首选位置 | 代码中保留什么 |
|---|---|---|
| 当前行为、特殊输入、失败条件 | 函数/类型文档 | 调用者必须知道的契约 |
| 不明显的算法原因、顺序、缓存失效 | 相邻行注释 | 为什么这样做、误改后果 |
| 跨模块取舍、长期限制 | ADR / designs / architecture | 一句当前约束 + 一行指针 |
| **评审轮次、模型名、整改批次、勘误史** | 提交说明、计划或评审记录 | **通常不保留；教训的实质改写成约束句保留**（见 C03） |
| 上游与测试预期不一致 | compatibility.md 差异台账 | 当前行为 + 台账 ID + 关键用例 |
| 性能实测数字 | 基准报告 | 复杂度与影响因素；结论引用场景 |
| 待办 | 计划条目 | `TODO(<可定位条目>): 缺失行为。当前影响。`——不写无锚点的"后面补/归下一批" |

跨会话需要的处理状态放评审记录或计划；代码注释只保留当前约束和原因。必要时链接记录，不以评审编号代替解释。

## 6. 各类注释的写法

### 6.1 模块头（`//!` / 文件头）

说明当前职责、主要输入输出和影响使用的边界。通常一到三段；复杂 FFI/并发模块可附较长安全说明。不强制每个模块写“不做”或“不变量”，不追加里程碑日志，也不罗列易过期的全部能力清单。

```rust
//! 协调玩家执行与世界结算。
//!
//! 玩家执行生成指令、Memory 和 CPU 计费的候选结果。
//! 世界结算成功后提交；失败时保留玩家运行结果供重试，
//! 重试时不再次执行玩家代码。
```

### 6.2 函数与类型（`///`）

首句描述用途，再按需补输入含义、结果、状态变化、失败条件。`Result`/panic/`unsafe` 必要时用 `# Errors`/`# Panics`/`# Safety`。简单私有函数不写模板文档。公开接口补类型与名字表达不了的行为（失败是否改变状态、能否重试、空值语义、长度单位）。JS 用 `//`，契约用 `/** */`，不机械补 `@param`。

### 6.3 数据字段

优先写**单位、取值范围、缺省与特殊值、生命周期、更新方**。计时字段必须说明绝对时间还是剩余时间；容量限制说明计数对象。

```rust
/// 玩家余额，单位千分之一 credit；玩家 API 读取时 ÷1000 返回 credits。
pub money: i64,
```

### 6.4 兼容性例外与局部说明

先写具体行为与误改风险，来源放后。用源码依据解释为什么保留反直觉行为，不只写"官方如此"：

```js
// RCL 为 0 时不返回 progress；RCL 为 0 或 8 时不返回 progressTotal。
// 不要把缺失值改成 0——玩家代码可以区分 undefined 和 0。
// 来源：上游 engine/src/game/structures.js 的 StructureController 属性定义。
```

同一复杂规则多处使用时，完整解释放共享实现，调用点只写本地差异并指向它；但安全调用条件不得全部移远。

### 6.5 测试

说明场景、刺激和可观察结果。断言消息应帮助判断失败；有价值的错误实现对照可以保留，但应写具体错误行为，不依赖旧评审历史。例如 `typeof` 能检查接口不存在，而 `Object.isFrozen(undefined)` 不能区分该情况。函数名优先体现被测性质；不以"第 N 道锁/某模型复审"命名场景。

### 6.6 安全、并发与事务

不因篇幅删掉 FFI 指针生命周期、别名、同步机制、panic 边界、释放责任（正面样板：`kk-pathfinder/src/ffi.rs:3-21`）。`# Safety` 写调用方前提；`// SAFETY:` 写当前 unsafe 为何满足前提。事务说明写候选范围、提交点、失败边界。严格区分返回 `Err`、panic、进程崩溃、磁盘恢复。

### 6.7 TODO

```text
TODO(<可定位跟踪项>): <具体缺失行为>。当前 <影响或临时处理>。
```

已完成的 TODO 必须删除。

## 7. 上游引用与事实核验

- 就近保留：行为、`文件名:行号` 或文件+符号、关键测试/台账 ID。禁裸行号、绝对个人机器路径、过期本地路径。
- 引用应能确定上游仓库、版本和文件或符号。版本信息可以引用统一的来源说明或现有锁定入口，无须在每条注释中重复完整提交哈希。
- 上游行号只是定位辅助；比较上游一致性时注明比较的是**玩家可见行为、内部数据格式还是算法步骤**——内部实现不同但结果一致不能写"逐字一致"。

## 8. 审查标准

1. 这条注释说了名字和代码看不出来的信息吗？（C10）
2. 不读阶段计划与评审记录，能知道对象、条件和结果吗？（C02）
3. 能在实现、调用方、测试或可靠来源中核实吗？"官方"有锚吗？（C04/C05/C11）
4. 单位、缺省、时序、失败边界、例外、安全条件保住了吗？（C07）
5. 删掉历史叙述后，真正防止误改的原因留下了吗？（C03）
6. 状态词与实际数据层级一致吗？（C06）
7. 相邻代码、文件头、引用路径与当前实现一致吗？（C12）

验收不使用注释行数、术语命中数或固定长度作质量分数。目标：维护者能回答"做什么、为什么、什么情况下不能改"，无需先了解开发流水账。

## 9. 正反例与改写理由

示例分为项目原文节选和通用反例。省略号表示省略原文；正例用于展示符合规范的写法，不表示对应源码已经修改。每组说明问题、建议写法和必须保留的信息。

### 9.1 内部术语掩盖简单用途

项目原文：

```rust
//! store 领域语义：正量键集共核（两投影的契约折叠各自定型）。
```

**问题**：“正量键集”“共核”“契约折叠”要求读者先猜内部含义，没有直接说明输入、结果以及两种输出的区别。

建议写法：

```rust
//! 构造资源存储的 JSON 字段，只加入数量大于 0 的资源。
//!
//! 查询快照和沙箱世界数据共用这段过滤逻辑。
//! 沙箱世界数据还会补充 energy 字段，即使其值为 0。
```

**改写要点**：资源过滤条件和输出差异。删掉的是难以理解的简称，而不是技术内容。对应 C02、C07。

### 9.2 评审历史代替重试契约

项目原文节选：

```rust
/// 上轮世界结算失败的候选缓存……
/// 输入钉子（B0-6，ADR-013 决策 5）……
```

**问题**：“输入钉子”和开发批次无法直接告诉读者重试时是否重新执行代码、哪些输入保持不变、何时释放缓存。

建议写法：

```rust
/// 缓存世界结算失败时的玩家运行结果。
///
/// 重试不再次执行玩家代码，而是复用首次尝试的指令和 TickInput。
/// 这样控制器签名时间不会随重试改变。提交成功后清空缓存。
```

**改写要点**：重试行为、确定性原因和缓存生命周期。需要追溯设计时另加 ADR 引用，不能用编号代替解释。对应 C02、C03、C08。

### 9.3 文档隐藏不等于调用隔离

项目原文节选：

```rust
/// #[doc(hidden)]：仅集成测试消费，生产面不可达……
```

**问题**：`doc(hidden)` 只影响生成文档；公开方法仍可被代码调用。该说法把接口用途写成了访问保证。

建议写法：

```rust
/// 测试用故障注入：使下一次世界结算返回错误。
/// 此公开方法在生成文档中隐藏，但仍可由代码调用。
```

**改写要点**：接口用途，同时准确说明保证范围。如果需要禁止发布版本调用，须修改编译或 API 边界，不能靠注释实现。对应 C01、C05。

### 9.4 简短但遗漏调用限制

通用反例，针对项目的 `isKnownStructure` 帮助函数：

```js
// 检查结构是否存在。
```

**问题**：这个函数使用原始数据的 type 判断，而 source、mineral 也可能使用 `type='structure'`。这条短注释容易让调用者误以为它完成了全部类型验证。

建议写法：

```js
/** 检查 id 是否仍存在于当前 tick 的结构数据中。
 *  source 和 mineral 也使用 raw type='structure'，本函数不能独立验证类型。
 *  调用方必须另外检查对象类型，或排除这两类对象。 */
```

**改写要点**：函数实际判断的范围和调用者的责任。好的注释可以更长，只要这些信息能阻止误用。对应 C05、C07。

### 9.5 “官方如此”不能解释兼容性风险

通用反例，针对控制器属性：

```js
// 与官方一致，不要修改。
```

**问题**：没有说明什么行为一致，也没有解释哪些看似合理的修改会破坏兼容性。

建议写法：

```js
// RCL 为 0 时不返回 progress；RCL 为 0 或 8 时不返回 progressTotal。
// 不要将缺失值改成 0，玩家代码可以区分 undefined 和 0。
// 来源：上游 engine/src/game/structures.js 的 StructureController 属性定义。
```

**改写要点**：特殊等级的返回值、误改后果和可定位的依据。来源引用应包含可核实的上游版本。对应 C04、C07、C08。

### 9.6 重复操作不如解释选择原因

通用反例：

```rust
// 增加计数。
count += 1;
```

**问题**：代码已经表达这件事，注释没有增加信息，应直接删除，不需要为了配对而强行补一句。

若代码确实涉及容易误改的设计选择，可以参考项目的默认对象命名场景：

```rust
// 用单调递增的对象 id 生成默认名字。
// 对象数量会随死亡减少，用它生成名字可能与已有对象重名。
```

**改写要点**：选择依据，以及替换为另一种计数方式的风险。是否需要注释取决于额外信息，不取决于代码行数。对应 C10。

### 9.7 测试结果不能代替断言理由

通用反例，针对玩家全局宿主接口的测试：

```rust
// 宿主面已收口，全链已锁。
```

**问题**：“收口”“已锁”是过程结论，既没有说明测试观察什么，也暗示了超出单条测试的保证。

建议写法：

```rust
// 玩家全局不应暴露宿主生命周期接口。
// 用 typeof 检查属性是否存在：Object.isFrozen(undefined) 也返回 true，
// 因此不能用它判断接口是否被正确隐藏。
```

**改写要点**：被测性质和选择断言的理由。这能防止维护者换成看似相近、实际无法区分错误实现的断言。对应 C05、C07。

### 9.8 “持久”必须说明数据保存在哪里

项目原文节选：

```rust
/// Game.notify 落库……
```

**问题**：对应实现保存的是内存中的通知列表。跨 tick 保留不等于已经写入数据库或磁盘。

建议写法：

```rust
/// 玩家通知列表，保存于内存并跨 tick 保留。
/// 容量为最近 100 条通知；这里不执行数据库写入。
```

**改写要点**：保存位置、生命周期与容量。容量只属于示例所描述的实现，数值必须与代码一致，不是所有通知实现的统一要求。对应 C01、C06、C12。
