# 全面架构重构与性能验收计划

日期：2026-10-11。状态：**方案完成，实施未启动**。依据用户本轮授权：为性能全面领先 xxscreeps、内存更低、Mod 同等灵活，可进行必要的任意改造。具体架构见[目标设计](../architecture/performance-target.md)，取舍见 [ADR-020](../decisions/ADR-020-incremental-world-runtime.md)。当前状态仅由[接手台账](mod-next-batches.md)维护，本计划不以文档完成代替实现。

实施从 R00 和边界明确的首片开始；局部 JS 并行、多 isolate 共线程与紧凑存储全量扩张须分别通过机制验证和性能实验，不能直接默认启用。

本方案扩展此前“近期只做 50×6”限制后，又于 2026-10-11 经用户收敛：50×6（B0）恢复为唯一性能验收锚点，规模/热点/混合 Mod/少核等降为登记场景库（按片敏感性抽查或随部署线），不构成性能线门禁。既有 G01–G30 能力缺口继续负责，重构批次 R00–R12 是底座与验收任务，不取代玩法补齐。

## 1. 成功的定义

三个目标同时过关：性能、内存、能力。单项领先不抵消另一项退化；纯 native 领先不抵消真实 Mod 路径未验收；有限玩法差异不能被拿来减少工作量。

### 工程建议数值（2026-10-11 用户收敛后口径）

用户给出了方向并**于 2026-10-11 收敛验收口径**：三目标保留，但性能验收锚定 B0（50×6）单一场景；开发与批次验证使用分钟级短窗快速迭代，不为验证等待小时级窗口；原"全面发布最低门槛 × 全矩阵"与 0.70×/0.75× 主攻档降为非承诺参考。以下为收敛后的验收线，比值为 kk/固定 xxs：

| 指标 | 验收门槛（B0 同机同窗） | 进取参考（非门槛） |
|---|---|---|
| wall P50 | ≤0.90；连续两个独立配对窗复现，多窗取中枢并报热态 | ~0.80 |
| wall P95/P99 | 不劣化；疑似差异落在波动内时补独立窗而非拉长单窗 | ≤0.90 |
| 总 CPU core-ms/tick | 不显著劣化；"CPU 小超 + wall 大赢"按既定仲裁（同进程交替对照 + 冻结 ABBA，必要时受限核抽查）裁决，不作绝对否决线 | ≤0.90 |
| 稳态/峰值驻留内存 | 峰值 <1（含检查点窗口抽查） | ≤0.85 |
| 正确性/Mod | 兼容棘轮零新增回归；重构前后状态与语义等价；按变更影响选择 Mod 回归 | — |

同资源容量、真实 JS preset 全矩阵性能对照等原 B1–B7 项**不再构成性能线门禁**：作为登记场景库，按片敏感性在批次内抽查或移交部署里程碑（Linux 少核、72h 长跑、服务对照随 G27.b/G28/M5 线执行）。目标未达成可以继续调整实现，不能临时删除失败场景或放宽为平均领先。

表中 tick 指标适用于 R00 事先登记的可比闭环负载/资源档，不直接套用冷恢复耗时、纯 VM 计算微基准和无 tick 的 provider API。B6/B7 另冻结恢复时延/RPO、持久化停顿、最大队列与容量 SLO；核心服务相关指标同样要求不劣化。每类哪些项适用、负载强度、硬件与误差判据必须在优化前固定。当前缺失共同消费者的项目仍阻塞全面结论，不能测完才删掉不利档或把达不到的真实 bot 改叫诊断微基准。

纯 JS 计算基准用于验证玩家预算、VM 执行效率和瓶颈上界，不要求消除宿主开销后还对同代 V8 获得固定 30% 优势；若产品实际负载以纯 JS 为主，报告该类容量与极限，不把它排除后宣称任意脚本领先。原生缺少对应 Mod 功能的比较不得纳入通过项。

### 比较身份与公平条件

- 首基线冻结本仓 `525ec789` 与本地 xxs `5ff0d1a682170f6b5f9c8bac3e703767625988e0` 的**实际源码、dist、配置、依赖与二进制哈希**；实施开始重新核验 HEAD/工作区，不能只认提交号。xxs 未来升级另建基线。
- 玩家代码、输入世界、随机/时间口径、tick 数、游戏 CPU 预算、堆限额和实际动作负载对齐。保留既有允许的玩法差异签名；新差异必须解释。优化前后自身对照要求更严格，不能借旧跨引擎容差引入退化。
- 资源公平以相同核/内存限额为主，两端分别合理调并发；另保留并发 4 的连续历史锚点。对照双方调优花相同精力，不刻意保留 xxs 不利配置。
- 算全部相关进程、中间件、后台 I/O、RSS/PSS 和 V8 external；单进程嵌入对照只声明内核范围。完整服务对照须相同持久化承诺、网络工作量与恢复窗口。
- Linux 多进程总驻留优先用汇总 PSS/可解释的共享页去重口径，并同时保留各进程 RSS；V8 heap/external 是归因子项，不再次加到已含它们的 RSS/PSS。双方同一采样法；峰值加入 tick 内与检查点/迁移窗口采样并报告分辨率、开销，只有 tick 后取样不能宣称捕获真实峰值。
- 开发 Mac 是日常验证环境。受控 Linux 少核（建议 2 核）与多核环境、固定内存上限容量随部署里程碑（G27.b/G28/M5）执行，不阻塞 B0 性能线；2GiB 是容量档，不恢复为所有场景强制硬门槛。

### 测量分层（2026-10-11 用户拍板：快速开发，不为验证等数小时）

- **开发日常**：`compare-probe` 短窗（5+100，分钟级）与进程内交替 A/B（`--interleave`，块长可变以避开活动周期混叠）；一律后台跑 + 代理静默协议。
- **批次收口**：≥3 个独立短窗取中枢 + 冻结二进制 ABBA（丢弃窗热协议）；效应小于分辨率时按证伪纪律撤回，不追加小时级窗口。
- **里程碑/最终验收**：一次 500 预热 + 3000 tick × 2 独立窗的长窗（不再 ×5）+ 等价签名收尾 + 一次真实 bot/混合 Mod 抽查；小时级窗口只在本档出现。

正式主窗须确保包含出生/死亡、衰减和周期活动；不得超过夹具有效生命周期后仍把耗尽资源的空转当稳态；既有成熟夹具总窗上限 3750 tick，长跑另建可持续供需夹具，不宿主偷偷补给。

统计以独立 run 为重复单元，保留各 run P50/P95/P99、配对比值及不确定性，不把相关 tick 当独立样本制造窄区间。疑似领先落在波动内时增加独立重复，不能凭五窗硬给显著性。交替先后、后台静默、报告温度/频率/负载；进程内 A/B 用平衡块长与周期检查，避免和 20/25 tick 活动混叠。

## 5. 关键实施细则

### R03/R04：避免大爆炸式换世界

先给现有房对象提供受控读写 facade；批量机械迁移规则访问点并记录未转换路径。转换完成前保留全量校验，不把缓存命中率当覆盖证明。

同一个逻辑 RoomAccess 可由旧对象树和新 RoomStore 实现，测试向两者送相同已记录意图/时间输入，比较完整逻辑状态、事件、ID、索引顺序和 Mod state。序列化字节可因版本不同而不同，必须规范化比语义，不能忽略键序等玩家可观察差异。

shadow 双执行只放诊断：JS handler 不能在同一 realm 运行两次来比较。两个独立 realm 必须从相同会话起点执行相同输入前缀；在中途只加载相同 checkpoint 不会恢复相同 JS 模块全局。冷恢复比较则两端都重建，不能将一个暖 realm 与一个冷 realm 的差异归咎于存储重构。外部副作用禁止重复发出。生产选择一个后端；旧 checkpoint 可以迁移到新后端，不要求新存档自动可被旧二进制读取。回退部署依赖保留的旧检查点/旧二进制与明确升级边界。

R00 建立两套不同裁判：**确定性结算裁判**给 old/new 完全相同 RunResult（含 Memory/CPU 写回）、TickInput、RNG/注入流和执行身份，在不触发资源上限的诊断条件下比完整状态；**真实执行裁判**照常运行玩家与预算，比较行为/实际工作量和性能，CPU 账单、玩家 Date/Math.random、超限结果不能要求自然逐位一致。资源超限另测额度/归属/恢复不变量，不伪造实测 CPU 使性能报告好看。

现有确定性契约登记了处理器 randomInjection 失败后重试未保留注入流的缺口。R00 必须复现并登记该项，R09 支持此路径前须保存正确尝试输入并验证；不能把原来的例外当成已经成立的全路径重试证明。生产输入日志 v2 不携带完整 Memory，不能把它当作本裁判所需完整 RunResult 的替代；诊断输入采集独立且有界，不改变 ADR-018。

### R09：先证明哪些工作可以独立

建共享操作分类表：ID 分配、RNG 流、GCL/账号限额、玩家资源、namespace state、跨房队列、市场、事件序。为每项记录已有消费者、可观察顺序、合并运算和局部资格。不能把所有共享数据换成 Mutex 后称为并行架构完成。

通用 Mod 保留共享 realm 的有序路径，首版不并行 JS handler。host capability 不能拦截闭包/模块全局写入；局部 JS 资格须先设计实际隔离/状态作用域机制，再作独立试验，不是 R09 首片前置。合法跨域 Mod 继续有序执行。不可观察前提未证明时，不用临时 ID、推测重跑或复制模块全局。

先验证纯房候选的串/并行等价，再接玩家回执驱动；任何阶段失败都不发布房前缀。超时/异常/空结果有明确完成语义；同玩家多房、多个玩家同房与跨房到达同拍出生顺序均需测试。

必须包含两类否决反例：A 房 GCL/ID/Mod state 写入影响 B 房读取，先完成 B 再排序提交仍应被调度依赖阻止；提前执行 Mod 后另一玩家线程失联，必须停止/排空候选、重建已参与 realm、保留确认回执并停顿，不能伪装普通结算重试。now_ms 仍在玩家齐备后采样，提前计算不依赖它的段；改变采样点需另行协议迁移。

### R06：缓存是派生物，恢复不依赖命中

给 full/patch 协议显式版本；与检查点 schema 分别管理。每次更新绑定 base/target/view identity；沙箱没有正确基线就 full，不在旧记录上猜测应用 patch。重试同 tick、失败后继续、包切换和视野撤销必须覆盖。

必测“前半 patch 有效、后半损坏/中断”、确认丢失/重复/迟到、恢复后 tick 重用、同 tick 管理编辑、视野退出后重入。安装失败只能保留旧完整基线或进入无效待 full 状态，不能对半更新常驻表继续 patch。另测无权威字段写入而 TTL/事件有效期变化，证明派生失效不漏。

增量编码先产 full 保持参考，之后独立切 wire patch。散页零拷贝与一次 pack 同窗对比，选择整体 CPU/RSS 更好者。删除现有 prev 全块保留、preencode 房深克隆前，证明新基线足以替代，避免新旧缓存叠加吃掉内存优势。

## 6. 内存预算与避免假收益

R00 报告总量并分桶，之后各片有预算而不是笼统“RSS 大致正常”：当前世界、候选增量、undo、视图、私有索引、V8 heap/external/code、预编码、旧版本、检查点/服务队列。

预算以同负载 xxs 的实测稳态/峰值乘第 1 节目标形成总上限；各桶份额根据归因分配，不能无依据承诺每玩家固定多少 MiB。新增缓存须记录被替代的内存，不能只算自身命中收益。单个过渡片可明确登记暂时峰值债务和删除前置，但在收敛前不切最终默认、不宣布低内存达标。

长期运行同时看趋势和负载周期：稳定世界下保留字节不持续增长，玩家入退/对象高 churn/包切换后能回落，检查点 backlog 不增加。单次 RSS 波动不能证明泄漏；对象数或实际载荷增长也不能冒充泄漏。比值与绝对量同时给出。

禁止通过少执行玩家、缩短生命周期、降低玩家 CPU/堆预算、提前销毁 isolate 全局、少跑 Mod hook、延后应发生的定时动作来取得成绩。

## 8. 风险与必须保留的替代路径

| 风险 | 早期证据/检测 | 应对 |
|---|---|---|
| COW 元数据/碎片大于克隆成本 | R04 dirty 密度×对象规模对照 | 小页/覆盖日志/独占副本阈值，必要时混合存储 |
| 增量漏脏导致静默旧数据 | ChangeSet 对全量 diff、跨域故障用例 | 覆盖未证明路径 full；封住所有裸可变入口 |
| 零拷贝旧页被 V8 长期钉住 | retained bytes/代际年龄、旧引用压力 | 私有稳定句柄、受限页、copy fallback，不提前释放 |
| Mod 并行改变模块全局/调用顺序 | 共享全局包、交叉读写/随机调度测试 | 通用有序 realm；局部模式显式 opt-in |
| 更快规则挤掉编码重叠收益 | 跨 tick trace、编码 miss 与总 wall | 合并调度预算或移除 L1a，不累加局部收益 |
| 紧凑 schema 丢掉动态字段/键序 | 非内建资源/深嵌套/转义/缺失/null | 通用动态值路径与逻辑快照差异测试 |
| 新旧路径双持有导致峰值回退 | 同时存活表示清单 | 生产只选一个后端，阶段末删除过渡缓存 |
| 少核容量回退 | 限核 CPU/wall 与 backlog | 预算重标定，少核 inline/低并发，不能靠 OS 自动保证 |
| 对照版本/动作不同制造假领先 | 双端哈希、handler/动作/状态账本 | 冻结对照，差异披露，缺功能不计通过 |

## 9. 测试与每片交付纪律

实现影响面选择单元/集成/属性测试；核心随机化测试覆盖增删/转房/重用槽、任意字段变化、嵌套 savepoint、late failure、视野/权限/包变化及序列恢复。同输入在不同 worker 数、完成顺序和注入故障位置下比较完整权威状态。并发正确性不能只靠成熟房性能夹具证明。

按仓库规则重新构建测试二进制；完整无参数 `pnpm run check` 是提交前门禁；改 Rust doctest 另测；行为/兼容相关运行 release 棘轮，真实 Mod 和恢复链不能省略。性能证据绑定实际 release，新增开关默认值和回退路径均验证。

每片产出：具体问题/行为、改动范围、状态与恢复契约、实际检查及失败项、端到端前后对照、内存债务、剩余消费者、保留/撤回决定。普通小修不额外铺一套报告；大机制与原始测量按研究目录归档。没有测的项目明确写未测。

所有权威写域当批补保存/恢复与格式策略；新协议当批补 full fallback；公共 SDK 改动当批补文档与第二同类样例。ADR 中仍待实验的参数，不以文档批准跳过验证。

## 10. 当前接手点与结束条件

本轮仅完成方案、ADR 草案及索引/路线同步，没有运行实现变更或新增性能结果。下一工作为 R00：冻结当前基线、低扰动成本与内存账本、写入口/Mod 领域核查；随后 R01/R02 可先交付，R03 开始统一事务底座。

最终交付应能回答：哪些场景领先多少、置信与波动如何、总内存为何更低、全部 Mod 领域如何实际运行、恢复/升级如何保障、还有哪些不支持与未达标。性能线以 B0 长窗（500+3000×2）+ 等价收尾为核心收口；登记场景未执行的如实挂账并移交部署线，不阻塞性能线宣布，也不能把挂账场景说成已验收。方案文档完成、某个优化有收益或 B0 一次领先都不够。
