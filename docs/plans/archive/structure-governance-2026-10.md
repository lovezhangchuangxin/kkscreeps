# 维护结构优化

2026-10-07 用户授权执行职责治理；本方案替代旧 S03–S06 的纯移动白名单。S01（`e0b457b`）和 S02（`5a25bc2`）已完成，继续保留测试目录成果。当前进度只维护在[任务台账](../mod-next-batches.md)。

## 目标与边界

保留现有 crate 分层；按领域、状态所有权及变化原因组织内部代码。700/1000 行仅为复审信号和兜底门禁。允许建立构造入口、收紧内部状态并迁移调用方；不要求物理目录严格镜像。旧公开模块路径通过重导出兼容。

候选及局部恢复由 engine 负责；runtime 编排玩家执行、VM 生命周期和领域适配；mod-host 负责 JS 转换、能力有效期及 VM 调用。JSON/KKPV 共用领域值与权限判断，保留各自编码和查询快照语义。

## 执行顺序

1. 精简贡献规则和当前台账，移出过时交接指令，文档检查使用 Git 文件清单。
2. 移动领域在 mod-api、engine、mod-host 中归拢；runtime 已有移动委托继续沿用。内部消费者使用领域路径，旧路径保持重导出。
3. 建立 Working 构造入口，将候选操作按对象、变更日志和移动归属组织；将首触恢复能力从 runtime 归入 engine，避免重复维护恢复规则。
4. 世界 Generic 数据建立共享访问入口；runtime 执行器离开 lib.rs；串行场景提供逐场景诊断和定向运行，保持原默认顺序和 V8 生命周期约束。
5. 合并移动/战斗契约，归档已完成计划；研究工具与工具测试归入 scripts。执行完整门禁、适用 doctest、release 兼容棘轮及恢复身份检查。

## 身份约束

builtin.rs 和 builtin/store.rs 字节参与 PlanHash；本轮保持两者字节不变，避免目录整理改变恢复身份。将内容身份、宿主行为协议与构建来源分开属于需要版本迁移设计的协议变更，不在无行为重构中放宽恢复检查。Mod 包源码摘要仍验证完整包内容。

## 验收

领域职责有唯一导航；候选构造与局部恢复不要求调用方复制字段清单；旧公开路径编译兼容。默认串行场景注册及顺序保持，选择场景时不能冒充完整生命周期验收。JSON/KKPV、拒绝、失败重试及冷恢复沿既有真实场景验证。

完整 `pnpm run check`、受影响 doctest 与 release ratchet 绑定最终工作树；不更改通过数下限或豁免。记录实际执行的命令和结果，不以文件行数降低宣称架构优化完成。
