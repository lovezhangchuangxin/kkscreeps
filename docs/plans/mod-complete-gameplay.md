# 独立 JS Mod 完整玩法开发计划

## 目标与适用关系

根据用户 2026-10-05 确认的目标，独立 JS 包应能创造完整玩法，覆盖调研版本 xxscreeps 的扩展领域，并提供更完善的组合、恢复和开发工具。现状与源码依据见[现状复查](../research/09-mod-capability-current-audit.md)；原则沿用 [ADR-007](../decisions/ADR-007-mod-system.md)、[ADR-014](../decisions/ADR-014-contribution-plane.md)和 [JS Mod 设计](../designs/mod-system.md)。

本计划调整未完成工作的优先级，不替代[贡献平面批次](archive/mod-plane-batches.md)已经记录的实现和证据。N 编号用于本轮完整玩法工作；不把既有 D4/D6 改名或重新判定为未完成。除下文标记已交付的切片外，其余为目标；当前机制以 architecture/ 为准，现状报告保留调研时结论。

具体后续切片、当前接手位置和每批更新要求见[Mod 后续任务台账](mod-next-batches.md)。该文件持续更新 G01–G30 的实际状态和证据，本计划维护总体目标与阶段范围；两者交付状态变化时同步，不在聊天中单独维护另一份进度。

2026-10-11 用户明确三项并列目标：性能全面超过 xxscreeps、内存更低、Mod 具备同等灵活扩展性，并授权必要的任意架构改造。[全面重构计划](performance-rearchitecture.md)安排底座 R00–R12，与本页 G/N 领域补齐合并执行；不减少十一贡献领域，不以全 native 默认路径代替真实 JS 内容性能验收。通用有序 Mod 能力保留；首版 JS handler 全部保持有序，局部 JS 并行待可执行隔离/状态作用域机制与独立实验，不只凭 capability 或声明开放。完整默认 JS preset、第三方组合、共享全局/跨域 Mod 都进入最终验收。完整目标尚未收口，局部性能交付不改变台账中的玩法缺口。

2026-10-06 路线复审明确：G 父编号不是严格执行顺序，按台账的执行队列及子片依赖推进。作者 CLI/类型、覆盖清单和同功能性能参考前置；新增状态域当批扩展检查点/版本，不等完整迁移系统；异步后台宿主先于 JS storage，持久 outbox 再依赖输入日志与原子耐久发布，避免循环。网络和客户端的真实基础实现列入对应子片，不能当作已经存在的前提。

验收以业务闭环为单位：作者只改 JS 包及其配置、声明、资产，安装包后运行，不要求改 Rust 或重编服务器。宿主第一次实现通用能力需要 Rust 开发，但后续第二种玩法不能再靠新增专用 Rust 分支。

[ADR-016](../decisions/ADR-016-official-content-packs.md)要求项目自身以公共 SDK 开发官方 JS 内容，逐步提供可选内容包与玩法预设。交付要求见[内容包设计](../designs/content-packs.md)。首片的生命周期示例作为官方内容候选，后续扩成真实生产建筑；示例和正式发行内容的成熟度分别记录。

## 建议实施顺序

| 批次 | 交付与范围 | 完成条件 |
|---|---|---|
| N1 自主对象与作者入口 | 自有对象生命周期；同房候选对象读写/创建/删除；JS handler 依赖与有效规则读取；sim 装载 Mod | 一个 JS 包无玩家指令也能周期更新、自主创建及到期删除对象；有玩家 API 和场景断言；依赖/冲突可诊断 |
| N2 新资源与对象能力 | 开放资源目录、库存能力、建造配方与对象 trait；逐片开放伤害公式/移动仲裁等策略 | 新资源生产建筑可以建造、生产、搬运、受击维修、影响寻路；至少一种深层算法由 JS 替换且没有隐藏默认规则否决 |
| N3 房间/玩家/世界规则 | 对应域的意图与生命周期；服务端发射；地图初始化/NPC/周期输入；跨房和账户命令 | JS 世界事件跨两房生效并更新玩家状态；声明访问范围且实际检查；全局阶段与异常提交边界清晰 |
| N4 耐久恢复与升级 | 全状态检查点、manifest、包/schema/规则与执行策略身份；迁移、缺包恢复、输入日志与 outbox | 冷恢复连续运行与未中断参考一致；崩溃只恢复完整版本；迁移失败保旧版；缺包默认拒绝可写启动并可显式只读导出 |
| N5 服务与客户端贡献 | 后台 JS 服务、provider、路由/订阅/管理；资源资产、渲染与面板；玩家类型生成 | 同一 Mod 包贡献玩法、玩家 API、服务和客户端；至少一个业务 provider 与一个 JS storage provider 可替换；两类客户端分别验证 |
| N6 完整作者工作流 | init/test/watch、组合图/trace、故障夹具、回放与 tick 边界更新 | 作者用公开 CLI 重现冲突/拒绝/异常、定位绑定、保存恢复；更新失败保旧计划；报告绑定输入与执行身份 |

N1 的 sim 装载/诊断和 N4 的状态清单先行；每个新域当片提供保存恢复，不必等待 N3 或完整 N4。已有基础检查点、JSON 载荷显式迁移、输入日志/结算回放与 sim 周期保存/恢复选择；服务常驻调度、内容级迁移和耐久输入/outbox 仍未实现，具体机制见[检查点](../architecture/checkpoints.md)及[输入日志](../architecture/input-log.md)，早期基础首片证据见[交付记录](../research/notes/basic-checkpoints-2026-10-05.md)。N5 契约在首次存储/网络设计时落实，N6 测试和诊断随各片交付。

N2 移动静态通行已贯通计划级墙、静态对象与私有 rampart 声明及默认玩家/NPC 寻路；G03 已提供准入及障碍追加后的同源链预演，障碍摘要提供与结算同源的安全模式主人。逐房粒度和 G02 其余子片仍未完成，现行机制见[移动契约](../architecture/movement.md#静态对象通行声明g02d3-后续)。

默认玩法兼容与真实 bot 的 M2B 工作继续推进；不能为开放 Mod 放松零 Mod 棘轮，也不能以默认玩法达到通过率门槛替代 Mod 的独立验收。

## 全量覆盖台账

下表按 xxscreeps 的贡献领域安排归属。一个领域中存在可用入口，只能证明该入口；实施时继续细化为实际业务能力和消费者，逐项记录已实现/部分实现/未实现、JS 样例、验收证据与剩余限制。

| 领域 | 本项目必须提供的业务能力 | 批次归属 |
|---|---|---|
| config | 包配置校验、加载顺序、版本与能力发布 | N1/N5/N6 |
| constants | 可扩展资源/类型/数值规则目录，玩家与服务端一致消费 | N1d/N2 |
| schema | 新类型、字段/枚举、内建挂载、状态版本与迁移 | N1/N2/N4 |
| processor | 对象 preTick/tick、动作、房间/世界阶段及默认规则替换 | N1/N2/N3 |
| game | 玩家类/方法/全局、查询/集合、预检、初始化和类型声明 | N1/N2/N3/N5 |
| driver | 玩家运行连接器、输入/输出/持久数据的宿主集成；维持玩家隔离 | N3/N4/N5 |
| main | 服务器初始化、生命周期、周期调度和管理入口 | N3/N5 |
| terrain | 地形/地图生成与初始化，投影与寻路一致 | N3 |
| storage | 业务存储和底层 JS provider，原子发布与恢复 | N4/N5 |
| backend | 路由、订阅、认证/消息等 provider、管理、版本/资产与客户端贡献 | N5 |
| test | 作者场景、断言、故障复现、包测试与开发工作流 | N1/N6，贯穿各片 |

processor 台账还须覆盖资源采集/再生、spawn 与寿命/死亡、塔、实验室/工厂/生产、终端/市场、控制器、power 与跨房/跨 shard 等规则。N2c 的“至少一种深层算法”只是首个验收切片，不表示其余默认算法可保持永久封闭。完整目标收口须覆盖调研版本已经具备的业务规则与替换能力，或明确仍未完成；不能仅凭几类示例宣布全量达标。

## 玩法验收要求

新增领域须贯通声明、玩家预检、意图清洗、结算、投影和保存恢复。写入域当片接线，不能延后到远期恢复任务。生命周期、动作出生/删除顺序及拒绝范围逐槽定义；不能将一个示例算作全领域完成。

资源和建筑验收至少包括新资源生产建筑及第二个同类包：成本、库存搬运、完工、生产、伤害/维修、障碍/道路/寻路、玩家查询和冷恢复。行为策略至少由两种独立 JS 实现及原生对照验证。官方内容使用公共 SDK，不按包 ID 特判，不允许只有验收示例能运行。

距离、价格、部件效果、公式和竞争优先级属于可替换玩法；坐标有效、ID 唯一、索引一致、数值表示及编码上限是宿主不变量。typed 表示无法表达规则时提供扩展及对应消费路径，不能要求作者修改 Rust 或依赖隐藏 native 否决。

## N3–N5 的契约前置

世界级规则在串行屏障执行；room/player/world 的权限和读写域可核验，不能只信作者 `parallelSafe` 声明。现行房间结算可在资格门内并行，含 JS 宿主贡献槽的轮次仍有序串行；共享操作触发串行重做，见[tick 契约](../architecture/tick-contract.md)。后续性能改造不得减少玩法表达能力。

2026-10-10 用户再次确认：与固定 xxscreeps 对照范围相当的 Mod 灵活扩展能力是性能架构改造的硬约束。共享/缓存、紧凑对象、轻量候选和流水线不得以固定类型/资源/字段、禁止目标跨域能力或跳过 Mod 生命周期来换取性能。现有 API 语义保持，未开放领域仍按本计划接线；安全约束与等价通用/有序路径见[总体架构](../architecture/overall.md#性能改造与-mod-扩展能力)，按影响执行[Mod 正确性回归](../architecture/performance-acceptance.md#架构优化的-mod-正确性前置)。这些回归不增加近期唯一 50×6 性能场景的组数。

N4 先建立数据清单：rooms/扩展字段、players/Memory/segments/CPU/通知、market、ID、namespace state、有效规则与包身份、执行停用策略及 tick。存储每个阶段只承诺已经接线的域；增加 RNG、外部输入、outbox 后加入版本和一致性门。关闭某 Mod 的处理器仍保留 schema 与规则，因此 PlanHash 单独不足以标识执行策略。

恢复区分内存错误重试、检查点重启和确定性回放。检查点先证明完整已提交版本可恢复；回放另外固定玩法时间/随机、遍历序、外部输入和玩家执行结果。不能在重放结算时重新运行玩家代码来替代输入日志。故障注入包含写数据未完成、manifest 切换前后和重启，报告所选耐久策略/RPO。

外部 I/O 使用后台域，改变玩法的响应进入有身份/顺序的输入队列；输出走提交后的 outbox，定义去重或幂等处理。JS provider 包括业务服务和存储后端，不能把 native 默认后端的便利当作禁止 JS storage provider 的理由。首次发布存储格式和网络协议时预留真实可执行的贡献入口。

## 开发工具与最终验收

工具逐片开放：N1 有 Mod 场景装载与断言；N1c 有组合图；N2 有完整样例包与类型描述；N4 有 save/load、故障重启与持久输入复现；N5 有客户端资产与协议验证；N6 完成作者工作流和边界更新。更新和迁移只能在无开放轮次的 tick 边界进行，失败保留旧计划与世界。

目标完成必须提交以下证据：

1. 对 xxscreeps loader 的全部领域逐项映射到本项目的可执行入口、独立 JS 示例和测试；Node 源码兼容明确排除，未实现领域仍为缺口。
2. 至少生产建筑、规则变体、世界事件、服务/存储/客户端四类包可安装，所有创作代码位于包内。
3. 两个包组合时顺序可解释、冲突明确；decline、异常、超时、停用、升级与缺包分别验收；冷恢复和未中断参考比较完整状态。
4. 作者可用公开工具加载包、推进真实玩法、定位绑定、复现失败、保存恢复和安全更新，无须编写内部 Rust 测试。
5. 默认世界持续通过既有兼容性门禁；Mod 开销按原生默认参考、完整官方预设、简单包/密集包/真实混合链的同功能口径报告。没有正式对照就不宣称整体比 xxscreeps 快或工具已优于它。2026-10-10 近期只做 50×6 满功能成熟房共同负载，以更快且内存更低为成功条件，2GB 为参考；玩法有限差异在报告量化披露，完整执行与真实活动校验仍必须通过。该对照不替代默认兼容性棘轮或全领域开放验收。
6. 官方 JS 内容实际使用公共 SDK，第二个同类包无需专用 Rust 分支；每个已迁移包验证未选时无残留行为、依赖组合与存量内容变更。默认预设、原生/JS 等价配置、第三方增量开销按[内容包口径](../designs/content-packs.md#性能与兼容性口径)分别记录。

按变更影响更新现行契约、SDK 和适用样例；普通内部重构不要求新增交付文档。按仓库贡献指南执行对应 crate 测试、重建测试二进制、兼容性棘轮与必要真实场景；开发中可用 `pnpm run check -- <crates>` 限定子集加速迭代，提交前仍须运行无参数完整 `pnpm run check`。所有源码/测试文件继续遵守 1000 行门禁。完成后先 code review、清偿问题，再提交。

G27.a 首片已接独立后台线程/V8、start/request/stop、有限只读探针与作者 CLI，读取真实已提交世界副本；全局与队列为进程态。N5 的业务 provider、storage provider、耐久 outbox 与实际 HTTP/WS 仍未交付，现行边界见[后台服务](../architecture/background-services.md)。
