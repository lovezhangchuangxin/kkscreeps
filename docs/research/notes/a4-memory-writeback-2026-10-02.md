# A4 玩家状态统一发布

本次从 `54d692b` 开始，落实 [A4](../../plans/mod-plane-batches.md) 的玩家状态统一发布：RawMemory、segments 及 CPU 桶候选与房间、市场共用发布点。现有状态的候选子步故障矩阵、显式工作者重建及真实回执身份验证已补齐。并发调度、命令期限和线程 CPU 时钟仍属于 P1；Mod namespace 尚未接入，进程及磁盘恢复仍属于 E。

## 实现

CPU 桶算法移到 `kk-core::cpu`；runner 保留重导出，独立沙箱与 bot 诊断路径继续使用同一算法。`PlayerState.cpu` 保存嵌入式引擎的已提交桶。协调器通过 `RunBudget` 从该值制定计划，沙箱使用预算快照并报告用量，不能修改宿主余额。正常轮增加 limit 后扣除向上取整用量，硬中断报告完整预算，halt 不计费也不回充，负余额轮只提交回充。非有限或负用量按协议错误拒绝。

`RunJob` 在一条玩家线程命令中携带世界、已提交内存及段窗口、预算、代码与 RunEpoch，合并内存注入、世界注入、表达式求值和结果导出。协调器核对回执的 tick/generation、执行尝试编号和工作者编号。尝试编号由协调器单调分配，工作者重建时分配新编号，重建中途失败也不复用已分配的编号。每条命令使用独立回执通道，runner 可先派发再按任意顺序等待；嵌入式入口仍顺序执行，尚未实现有界并发调度和命令期限。玩家用量仍按原墙钟加指令费用计算，线程 CPU 时钟属于 P1。

引擎新增 `tick_with_writebacks`，接收按玩家身份绑定的 `PlayerWriteback`。旧结算入口传入空写回表，保留调用方式。写回玩家必须存在于已提交玩家表中；未知玩家使整轮返回错误。

房间及市场结算完成后，在 Validate 阶段将桶候选、RawMemory、段内容及请求合并到玩家候选。写回仅修改对应字段，保留同轮规则产生的 GCL、余额和资源变化。校验与所有权检查完成后，原有 `publish_tick` 一起发布房间、玩家、市场及事件并推进时间。嵌入式生产路径删除发布后的 settle_bill/discard_bill 通信；独立 runner 诊断通道保留本地计费接口，不代表宿主桶权威。

`SegmentWriteback` 将 runner 的 JSON 输出转换为字段明确的请求。延续原合并行为：写入只接受 0..=99 的 ID 及字符串，同一段最后一次合法写入生效；缺省请求保留旧值，显式 null 清除默认公开段或外部段请求。runner 仍负责字符串长度、活动段数量等 API 检查，此转换器不替代完整沙箱校验。

## 失败处理及边界

协调器缓存世界结算失败轮的 RunResult 与首次 TickInput。重试复用报告中的固定用量和内存结果，从未改变的已提交桶重新计算同一候选，不重新执行代码或采样墙钟。V8 全局变量不会回滚。

执行阶段的基础设施故障与结算失败分开处理：保留已确认结果及原因，阻止正常运行、外部结算及相关管理修改，禁止盲目重派已经执行的玩家。可显式丢弃故障轮，或通过 `rebuild_player_workers` 放弃故障轮并重建全部玩家线程。新线程保留配置和模块，全部初始化成功后才换入；失败时保留原工作者表与故障门。下一轮注入已提交内存、segments 和 CPU 桶，V8 全局变量重新初始化。单纯丢弃不撤销 V8 全局变量、不补扣未发布用量，也不修复死亡线程。

实际恢复回归曾发现：执行阶段失联没有进入引擎 NeedsRecovery，重建若无条件调用 abandon_recovery 会报错。现仅在引擎确有结算恢复状态时解除它；执行故障门在全部替代线程建立后才解除。

本次不捕获 panic，不提供进程或磁盘恢复；引擎公开字段仍可被直接调用方修改，重试输入一致性由调用方负责。子步故障注入发生在市场处理后及玩家桶、RawMemory、segments 合并后，仍只修改候选；实际发布函数不插入可返回错误的中途检查。因此返回错误时保留旧完整版本，成功时发布新完整版本。真实线程无回执退出、部分重建失败和异步读取的旧回执已验证；这不代表已经覆盖进程级崩溃或原生宿主永久卡死。

## 验证

工作区测试通过 386 项，0 失败，5 项按原配置忽略；clippy 全工作区、全目标通过。格式、diff 空白及文档链接检查通过。

引擎回归在 Prepare、Settle、Market、Validate、Publish 阶段入口及市场、CPU 桶、RawMemory、segments 候选子步完成后分别注入失败，检查整张玩家表、市场、时间、版本及 ID 游标保持旧值；重试后验证桶值、内存写回与市场扣费同时生效。另检查未知写回玩家拒绝整轮，以及非法 ID 不截断、重复写入、缺省请求和显式清除语义。

真实沙箱回归检查结算失败后完整已提交玩家状态不变，缓存重试只执行一次脚本；下一轮读取新内存和段内容。原有负桶回充轨迹、失败后重试或丢弃等回归继续通过。新增纯预算测试覆盖亚毫秒取整、完整预算费用、halt、−41 回充及非法用量；线程协议回归验证每次 RunJob 都使用宿主快照，报告后不留待提交线程桶账。两玩家执行轮分别在第一、第二回执后注入故障，验证旧持久状态保持、自动重派被拒、显式丢弃后的全局执行计数没有重复增加。

重新构建 release 后，完整 screeps-ok 为 1854 通过、153 个既有失败、907 跳过，共 2914；与 `54d692b` 的报告逐用例比较，没有通过转失败、转跳过或缺失。能力声明和跳过配置未修改。

三个 bot 夹具中 tooangel、overmind 各完成 2000 tick，wasm 完成 10 tick，硬中断和停跑均为 0。完成数、console error 数及 missing_api 与 A3 报告一致；overmind 仍有 1 轮既有 console error，其余两者为 0。工具判定通过不意味着 bot 的所有业务行为已验证正确。本轮未重新进行性能矩阵测量，不作性能改善结论。

真实线程恢复回归在第二名玩家的 RunJob 前退出线程，验证第一名玩家已经运行但其 CPU、内存和段候选均未提交。首个替代工作者就绪后注入重建失败，故障门及已提交状态保持；再次重建成功后，两玩家从旧持久值继续，旧 V8 全局变量均消失。模块保留、健康分片拒绝误重建也有回归。

真实回执验证先派发两条命令，先读第二条，再读第一条；各自结果仍绑定原 token。将第一条真实回执交给第二条的校验入口时拒收。另一条命令完成后保留其回执，重建工作者，再用相同世界轮次和尝试编号、不同工作者编号检查该真实旧回执，同样拒收且不带入指令或费用。
