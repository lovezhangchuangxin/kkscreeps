## 0. 引擎选型：为什么是 quickjs-ng

任务书允许「quickjs-ng 或其默认 quickjs 分支」。实测确认：**rquickjs 0.14.0 已不提供后端开关，quickjs-ng 是默认且唯一的后端**。证据：

1. `rquickjs-sys` 0.14.0 的 `Cargo.toml`（crates.io 发布包 + GitHub master `sys/Cargo.toml）`features` 段没有任何 `quickjs` / `quickjs-ng` 之类的后端选择 feature；
2. 仓库 `.gitmodules` 将子模块 `sys/quickjs` 指向 `https://github.com/quickjs-ng/quickjs.git`；
3. 本机 cargo registry 中 vendored 源码头文件 `quickjs.h:1450-1452`：`QJS_VERSION_MAJOR 0 / MINOR 16 / PATCH 2`；
4. 运行时二进制自报 `JS_GetVersion() = 0.16.2`，与头文件一致。

选 quickjs-ng 的理由（除"没得选"外仍然成立）：quickjs-ng 是社区活跃维护的分支（持续性能优化与新语言特性，如本次实测中出现的 Float16Array/DisposableStack/Iterator helpers），而 rquickjs 上游已全面押注 quickjs-ng，旧 Bellard quickjs 路径在 0.13→0.14 已移除。

## 1. 精确依赖版本（Cargo.lock）

| crate | 版本 | 说明 |
|---|---|---|
| rquickjs / rquickjs-core / rquickjs-sys / rquickjs-macro | 0.14.0 | 2026-09-18 发布的最新稳定版；features：默认 `std` + `macro` |
| （内嵌 C 引擎）quickjs-ng | 0.16.2 | 由 rquickjs-sys 0.14.0 vendored 编译，无独立 crate 版本 |
| sysinfo | 0.39.6 | RSS 测量 |
| libc | 0.2.189 | 传递依赖 |

关键 API 实测签名（rquickjs 0.14.0 源码 `core/src/runtime/base.rs`）：

- `Runtime::set_memory_limit(&self, limit: usize)`（base.rs:158，返回 `()`，不是 Result）
- `Runtime::set_interrupt_handler(&self, handler: Option<InterruptHandler>)`（base.rs:124），`InterruptHandler = Box<dyn FnMut() -> bool>`（无 `parallel` feature 时非 Send）；**handler 返回 true 即触发不可捕获中断**（源码注释 base.rs:121-122）
- `Context::full(&runtime)` 启用全部内建 intrinsics（JSON/Date 等，跑 jsonchurn 必需）
- `Ctx::catch()` 取回 JS 异常详情 —— 重要实践：eval 失败时 rquickjs 只给 `Error::Exception`（Display 为笼统的 "Exception generated by QuickJS"），真实原因（如 `InternalError: interrupted` / `InternalError: out of memory`）必须用 `catch()` 拿

## 3. 实验A 性能基准

**方法**：三个工作负载 JS 源码逐字使用（见 `spikes/rquickjs-spike/src/main.rs` 常量 `WORKLOAD_JS`），一次 eval 定义后，Rust 侧 `std::time::Instant` 围绕**单次调用**计时；`fib(30)` warmup 1 + 5 轮、`objchurn()` warmup 2 + 30 轮、`jsonchurn()` warmup 2 + 20 轮，各取中位数（单次均在毫秒级以上，无需缩小负载，fib 用满 n=30，未降级到 fib(27)）。

**安静机器代表轮**（load average ≈ 3.8，14:53）：

```
fib(30)     : median=60.0ms min=59.6ms max=60.5ms 返回值=832040（期望 832040）
objchurn()  : median=15.934ms min=15.334ms max=17.575ms 返回值=74850000（期望 74850000）
jsonchurn() : median=47.720ms min=47.000ms max=51.058ms 返回值=19343（字符串长度，恒定）
```

返回值全部正确（fib(30)=832040；objchurn=200×Σ3j=74,850,000；jsonchurn 字符串长度恒定 19343）。

**方差与环境噪声（重要）**：实验期间同仓库的 boa/deno spike 兄弟任务在并行编译，load average 一度 14→35。多轮测量结果：

| 轮次 | 1-min load（轮前） | fib(30) median/min | objchurn median | jsonchurn median |
|---|---|---|---|---|
| 安静轮1（13:37，首轮成功） | ~4 | 61.3 / 60.7 ms | 15.7 ms | 46.0 ms |
| 高载轮1（13:42） | 28.0 | 62.8 / 61.0 ms | 18.4 ms | 58.2 ms |
| 高载轮2（13:42） | 19.8 | 126.2 / 119.4 ms | 33.3 ms | 92.8 ms |
| 高载轮3（13:43） | 17.4 | 367.3 / 314.4 ms | 207.4 ms | 497.1 ms |
| **安静代表轮（13:53）** | **3.8** | **60.0 / 59.6 ms** | **15.9 ms** | **47.7 ms** |

结论：单线程性能地板稳定——**所有轮次 fib(30) 的 min 都在 59.6–63ms**，只要不撞上活跃编译，中位数即 ~60ms；跨引擎对比时应取同一安静窗口的数字。

## 4. 实验B 硬中断 —— PASS

**方法**：`set_interrupt_handler` 装一个由 `Arc<AtomicBool>` 驱动的 handler；Rust 起线程 sleep 200ms 后置位，handler 返回 true 即中断；被测 JS 为 `var t=0; while(true){ t++ } t`。

```
eval 被中断：Err(Exception)，Display="Exception generated by QuickJS"，JS 异常详情="InternalError: interrupted"
中断后同一 runtime+context 继续执行 40+2 -> Ok(42.0)（复用成功）
实际中断耗时 210.1ms（目标 ~200ms），宿主进程存活（本行由 Rust 打印）
```

多次运行中断耗时 203.9–210.1ms（macOS 线程 sleep 粒度 ~10ms，偏差符合预期）。要点：

- 中断以 **`InternalError: interrupted` 不可捕获异常**形式冒泡，Rust 侧拿到 `Err`；
- **同一 runtime+context 复用成功**（中断后立即 eval `40+2` 得 42）；
- 实践细节：中断标志必须复位（`flag.store(false)`），否则后续 eval 会被立即打断。

## 5. 实验C 内存硬上限 —— PASS

**方法**：`set_memory_limit(64 * 1024 * 1024)` 后执行 `const a=[]; let i=0; while(true){ a.push(new Array(10000).fill(1.1)); i++ } i`。

```
内存上限触发：Err(Exception)，Display="Exception generated by QuickJS"，JS 异常详情="InternalError: out of memory"
耗时 23.6ms；进程 RSS：开始 6.3MB -> 出错后 59.6MB（上限 64MB，应远小于吃光系统内存）
OOM 后继续执行 6*7：直接 -> Ok(42)；run_gc 后 -> Ok(42)
```

多次运行：触发耗时 23.5–160ms（随 CPU 竞争变化），出错时 RSS 稳定在 **59–61MB，被钉死在 64MB 上限以下**，进程存活，未吃光系统内存。OOM 后 runtime **无需重建即可继续执行**（`6*7=42`，gc 前后皆可）。引擎把自己的 JS 堆分配计入限额并在超限时抛 `InternalError: out of memory`。

## 6. 实验D 创建开销与常驻内存

**方法**：创建开销 = `Runtime::new + Context::full + eval("0") + drop` 一个完整周期 × 100 轮取中位数；RSS 用 sysinfo 读本进程，对比「持有前 vs 同时持有 10 个（runtime+context，各 eval 过并驻留一个 1 万元素数组）」。

```
创建一个 runtime（含 context+eval+drop）：median=51us min=50us max=112us（100 轮）
持有 10 个 runtime（每个 eval 过并驻留一个 1 万元素数组）RSS：59.6MB -> 61.2MB，边际增长 1.6MB（均摊 0.16MB/runtime）
```

（安静轮 create median 51–52us；高载轮中位数最高漂到 182us，min 稳定 50–55us。）

**冷进程补充证据**（`/usr/bin/time -l ./target/release/rquickjs-spike hold N`，两次重复）：

| 模式 | maximum resident set size（B / MB） | 相对 hold 0 边际 |
|---|---|---|
| hold 0 | 2,719,744 B = 2.59MB | — |
| hold 1 | 3,883,008 / 3,784,704 B ≈ 3.70MB | +1.1MB（含首次换入引擎静态 footprint） |
| hold 10 | 6,848,512 B（两轮一致）= 6.53MB | +3.94MB，≈0.39MB/runtime |

解读：进程内热堆测量（+1.6MB/10 个）偏低是因为 malloc arena 复用；冷进程口径下第 1 个 runtime ≈1.1MB、之后每个 ≈0.3–0.4MB。**"每用户沙箱"量级的常驻成本很低，且创建只要 ~50µs**，适合 screeps 类多租户按 tick 重建隔离的模型。

## 7. 实验E 安全速查 —— 默认无宿主能力泄漏

**方法**：裸 `Runtime::new + Context::full`（不注册任何 native 函数、不装模块加载器），JS 侧 `typeof` 探测 + 枚举 `globalThis` + 尝试动态 `import('std')`。

```
typeof 探测：{"process":"undefined","globalThis_process":"undefined","require":"undefined","fetch":"undefined",
"XMLHttpRequest":"undefined","Deno":"undefined","readFile":"undefined","readFileSync":"undefined","writeFile":"undefined",
"read":"undefined","write":"undefined","load":"undefined","importScripts":"undefined","quit":"undefined","exit":"undefined",
"os":"undefined","std":"undefined","WebAssembly":"undefined"}

动态 import('std')：blocked: could not load module 'std'
globalThis 上泄漏的宿主能力名："无"
```

`globalThis` 自有属性仅 70 个纯 ECMAScript 内建（Error/Array/JSON/Promise/… 加 atob/btoa/performance/queueMicrotask 引擎自带工具），完整清单见原始输出存档。注意两点：

- **WebAssembly 在本构建中也不存在**（typeof undefined，rquickjs 默认编译未启用 wasm），进一步收窄攻击面；
- `import('std')` 被"无模块加载器"拒绝（错误原文 `could not load module 'std'`），quickjs-ng 的 std/os 文件系统能力必须宿主主动接 loader 才可能暴露。

结论：**默认沙箱碰不到 process/require/fetch/文件系统**，宿主能力完全由宿主显式注入决定；配合实验B/C 的中断与内存上限，三个"恶意代码"向量（死循环、内存炸弹、能力逃逸）在本 spike 的默认配置下全部被覆盖。

## 8. 结论汇总（与程序输出一致）

```
RESULT engine=rquickjs fib30_ms=60.0 objchurn_ms=15.934 json_ms=47.720 create_runtime_us=51 rss_10_mb=1.6
CAPABILITY interrupt=pass memory_limit=pass detail="interrupt fired at 210ms (target 200ms), runtime-reuse-after-interrupt=ok; oom-limit killed at 24ms with RSS 59.6MB (limit 64MB); sandbox-clean: 宿主全局变量均不可见(typeof=undefined); import('std') 被拒绝"
NOTE base_rss=59.6MB total_run_s=2.2 method="median of runs per experiment A spec"
```

- 性能：fib(30) ~60ms、objchurn ~16ms、jsonchurn ~48ms（quickjs-ng 0.16.2 解释器，无 JIT，安静负载）。
- 硬中断：pass，约 200ms 精确命中，runtime 可复用。
- 内存硬上限：pass，64MB 处强制终止，RSS 被钉在上限附近，OOM 后 runtime 仍可用。
- 创建开销 ~51µs，10 个 runtime 常驻边际 ~1.6MB（热堆）/ ~3.9MB（冷进程）。
- 安全：默认零宿主能力泄漏。

## 9. 未尽事项 / 限制

1. **计时噪声**：兄弟 spike（boa/deno）并行编译导致 load 3.8→35，中位数最多漂移 6 倍；已用多轮测量 + min 地板（59.6–63ms 全轮稳定）交叉验证，跨引擎对比建议同窗口重测。
2. **RSS 为读取时点值**：实验C 的 59.6MB 是出错后立即读取值（数组仍被引用，接近峰值），未做连续采样；`/usr/bin/time -l` 的 peak RSS 作为冷进程口径补充。
3. **未启用 `parallel` feature**：跨线程使用多个 runtime 需该 feature（且 handler 需 Send）；本 spike 10 个 runtime 在单线程持有，未验证多线程并发场景。
4. **未测 `set_max_stack_size`**（深递归栈保护）与 async/AsyncRuntime（futures feature）——超出本次五项实验范围，如选型 rquickjs 需补测。
5. jsonchurn 的返回值 19343 是字符串长度（负载设计如此），已验证跨轮恒定。
