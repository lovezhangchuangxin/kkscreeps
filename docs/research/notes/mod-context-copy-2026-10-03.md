# Mod 上下文复制优化（2026-10-03）

承接 [成本归因与字段缓存](mod-attribution-2026-10-03.md)。预算、诊断和首轮缓存已提交为 `80ec78f`；固定性能夹具因原先被忽略而补充提交为 `543939e`。本片继续减少 Rust 候选桥的重复 Value 复制，未改 JS 链协议或资源额度。

## 实现与验证

旧读取先从候选取得拥有所有权的 state、克隆缓存 fields，再把它们传给 `json!`。serde_json 1.0.151 的表达式分支执行 `to_value(&$other)`，对已有 Value 再遍历复制。现在用 `Map::from_iter` 直接装配上下文，把已拥有的 state/fields 移入记录；缓存字段与固定 args 仍各自克隆，保证候选和处理器视图独立。

写回先校验目标字段，成功后用 `Value::take` 从 op 交付的 context 移走 state，避免另一次深克隆。缺失 state 仍写入 null；字段校验失败时不写 namespace。JSON 数据键、native 权威参数、next 前同步、返回后刷新、别名拆分及失败候选丢弃语义不变。V8 与 Rust 两端仍通过 serde_v8 转换，不共享可变内存。

新增真实链测试在 JSON/KKPV 两条通道依次写回 null、布尔、数值、文本、嵌套数组/对象及自有 `__proto__` 数据键，并在 after 和发布后核验。已有 12 个链测试继续覆盖 Mod process、跨 namespace、native transfer、引用刷新、取消、故障与重试。

全量 `pnpm run check` 通过：558 个 Rust、19 个 JavaScript 测试；8 个 Rust ignored；格式与 workspace/all-targets Clippy 通过。Python 脚本全套 11 测通过。固定上游 `34a630efa42908c117c19c25d2350fa2387bd633` 的兼容棘轮为 1854 passed / 153 failed / 907 skipped，零转红/转绿。

## 测量边界

使用 [前后交替探针](mod-attribution-probe-2026-10-03.py)：400 个 link，100 tick 预热、500 tick 采集，三次独立重复，共 24 个窗口。优化前原版/诊断模式使用同一个已验收 release；优化后使用 Clippy 清偿后的最终 release。每个模式跨版本/轮次核验包和预算身份，三个边界核验全部对象摘要，完整链四个计数最终均为 240000。

原先在 Clippy 检查前采集的探索结果因最终二进制摘要变化而重采，不用于本片结果。最终采集期间没有并发运行 cargo 构建/测试、JavaScript workspace 测试或兼容性棘轮；有元数据读取和一次短文档检查。诊断窗口与无插桩性能分开；各阶段是包含墙钟，不可全部相加。仍是桌面本机、短窗口、纯结算，不覆盖玩家、投影、持久化或网络，不建立性能硬门禁。

最终采集数据见 [原始报告](mod-context-copy-validation-2026-10-03.json)，验证与源码指纹在其 validation 字段中记录。

## 结果与后续方向

以下是三轮独立窗口指标的中位数；CPU 为进程所有线程的 core-ms/tick。

| 无插桩完整链 | 优化前 | 优化后 | 降幅 |
| --- | ---: | ---: | ---: |
| 墙钟 P50 | 33.957 ms | 28.972 ms | 14.68% |
| 墙钟 P95 | 35.652 ms | 30.406 ms | 14.71% |
| 墙钟 P99 | 37.607 ms | 33.027 ms | 12.18% |
| CPU/tick | 34.965 core-ms | 30.042 core-ms | 14.08% |

每轮墙钟 P99：优化前为 35.988 / 37.607 / 39.287 ms，优化后为 33.027 / 34.912 / 31.017 ms。native 和 empty 的 P50 都约 2 ms，不能据这几个短窗口推断它们有确定收益。上述降幅相对于已经包含字段缓存的基线，不与前一轮不同采集时段的百分比累加。

诊断完整链每 tick 的 host_read 从 7.585 降至 3.649 ms，host_write 从 3.490 降至 2.744 ms；预算启动/收尾合计仍约 0.665 ms。阶段中位数来自各自窗口、且包含计时范围不同，不用相加来宣称精确的收益占比。方向与本次消除 Rust JSON 重复复制一致。

改动保持现有链架构和候选发布机制。后续若继续优化，应先细分 op 读写中参数与返回值转换的成本；当前诊断的 op_read/host_read、op_write/host_write 差额只能提示边界成本，尚不能直接归因给某一项转换。整链换驱动、共享可变状态或减少同步次数仍需要独立语义验证与前后对照，本片不提供这些方向已可替换现状的证据。
