# G29.a 玩家类型生成交付记录（2026-10-06）

## 范围

`kkscreeps mod types` 从冻结计划确定性生成玩家面 TypeScript 声明：Mod 对象投影 interface（信封 + Public 必选/Owner 可选/ServerOnly 不生成）、意图参数类型与 `emit` 字面量窄化签名（可空参数为可选参数）、建筑绑定、按计划窄化的 `ModInstallApi`、`ModResourceName` 资源联合、内建类清单。`--check` 新鲜度门禁（缺失/过期/手改退出 2，注册失败 1，按字节对比且只读）；输出与报告都必须在包根之外（包内文件字节计入 code_digest → PlanHash，头部不含 PlanHash 避免自反失效）。现行契约见[玩家类型生成](../../architecture/mod-types.md)。

首片不做：官方 Screeps 全量 API 的 `.d.ts`、Room/Player/World 域意图（与装配共用的执行门拒绝）、IDE 自动配置、按包独立声明面（联合面 + 头部运行时裁剪提示）。

## 实现结构

- `kk-mod-api/src/typegen.rs`（622 行）：`player_declarations(plan)` 纯函数生成文本；`MOD_BUILTIN_PLAYER_CLASSES`（38 项）与玩家面运行时双份维护。信封键（id/room/x/y/pos/type/modType）恰声明一次——投影把信封最后写入，同名声明字段（位置字段）被等值覆写不重复出现。Enum 联合按 BTreeSet 序（与声明书写顺序无关）。TS 语法安全：非标识符字段/Record 成员名退化为引号键、枚举字面量转义、JSDoc `*/` 替换、意图参数类型名按段净化并对撞名（`a-b:c`/`a:b-c`）追加序号消歧。构造器类型为 `new (...args: never[]) => unknown`（运行时仅 `setPrototypeOf` 原型载体）；`ModBuiltinClass` 实例类型 `object`（strict 下 extends 可用）。
- `kk-mod-api/src/intent_gate.rs`（46 行）：`executable_gate(intent)` 与引擎装配（`kk-engine/src/settle/install.rs::check_executable_intents`）**共用**——域/合并/转换/授权/压制五项未接线形态同一文案同一口径，"能生成声明的计划"即"能装配执行的计划"。抽取自 install.rs 原内联检查，引擎测试断言的错误子串不变。
- `kk-cli/src/mod_types.rs`（200 行）：复用 mod inspect 的注册路径（发现 → 配置校验 → 选择展开 → 冻结 → `registered.plan`）。守卫先于一切：`.d.ts` 双段后缀、输出与报告都在包根外（词法归一消解 `..`，不创建任何目录——空目录留在 mods 根一级会让 discover_packages 把它当包读）、报告不得与声明同路径；被拒绝的路径不落任何文件含失败报告。`--check` 按字节对比（非 UTF-8 判 stale），只读不重写。`main.rs` 注册 `ModCommand::Types`。
- 夹具 `compat/fixtures/mod-typed/`：alpha（全 ValueKind 字段含 bool/f64/ref、public/owner/server-only 三态可见性、enum/array/map、意图+资源+建筑）与 beta（owner-collection 对象、可空参数意图）互不依赖；`player.js` 为按生成声明编写的玩家模块样例（extends 内建类 + bind + emit + queries）。

设计要点：生成只依赖冻结计划（无时间戳/随机数/绝对路径），同输入逐字节一致；`--select alpha` 与 `--exclude beta` 在互不依赖两包上产物逐字节一致（选择展开收敛到同一集合）；字段按声明序（重排字段是预期的过期信号）、枚举/类型按集合序。

## 复审

三路只读 subagent 复审（生成器正确性 / CLI 门禁与测试 / 文档与夹具），发现与清偿：

- 生成器路（建议阻断→已清偿）：高危 1 项——字段/Record 成员名、枚举值、参数类型名不做 TS 标识符与引号安全，合法计划（kebab 字段名、含引号枚举值、`a-b:c` 撞名）可产出语法非法声明且 `--check` 无法发现。已清偿：`ts_property` 引号键、`ts_string` 转义、JSDoc `*/` 替换、`args_type_names` 段化净化 + 序号消歧，单测逐项断言。中级 3 项已清偿：构造器实例约束与运行时原型载体用法不符（改 `=> unknown` 并在 e2e 补 extends+bind 用例）；非对象域拒绝是 install.rs 的平行弱化实现（抽 `intent_gate.rs` 共用，引擎测试子串不变）；Float 域注释缺失（补"浮点 min..=max"）。低级 5 项：撞名消歧（随高危清偿）、可空非 Record 参数 `| null` 冗余（签名仅对 Record 补拼）、建筑寻路 `{:?}` 改中文、单测覆盖缺口（bool/ObjectRef/Float/空目录段断言随本批补齐）、`check_suffix` 未用参数删除。
- CLI 路（不阻断，两项中级已随本批清偿）：守卫在 `create_dir_all` 之后执行且 `--check` 同样建目录（包内投毒路径会留下空目录破坏后续 discover_packages——测试实证了该连锁）；`--report` 无守卫且可与 `--out` 互相覆盖。已清偿：守卫先于一切且词法归一消解 `..`（`std::path::absolute` 不消 `..` 会绕过 starts_with，补 `lexical_absolute`）、报告守卫（.json/包外/不同路径）、按字节对比（非 UTF-8 判 stale）、check 不重写断言、投毒路径断言。确认项：root 不存在时 generate 阶段失败无绕过、String::new 哨兵安全（生成恒非空）、内置清单解析鲁棒、tsc 缺席 panic 符合不静默跳过纪律。
- 文档路（建议阻断→已清偿）：高危 1 项——"全 ValueKind 覆盖"失实（夹具无 bool 字段，bool 映射全仓库零覆盖）。已清偿：夹具 alpha 补 `armed: bool` 并在 e2e 断言 `armed: boolean;`。中级 3 项已清偿："字段按集合序"改为声明序表述；研究笔记行数回填最终值；单测覆盖描述与实际对齐（补测后成立）。低级 3 项：路径守卫"不落盘"表述（守卫重排后成立）；台账"最近已完成"行过时（已更新）；负例 tsc 仅为手工证据（负例钉入 `mod_types_tests`）。
