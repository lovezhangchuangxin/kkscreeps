# G06.a 运行 trace 交付记录（2026-10-06）

## 范围

`sim run --mod-trace` / `mod test --mod-trace` 开启可选、有界的 Mod 运行事件记录，报告新增 `mod_trace`（条目 + dropped + 复现说明）。事件两类：槽结果（Completed / Inactive{停用丢弃} / Declined{binding,code} / Fault{binding,kind,error}，带 tick/房间/目标/槽键/阶段）与回退生命周期（SettlementRetry / RealmRebuilt / AutoDisabled{mod_id,consecutive,disabled}）。此前诊断面只有最后一条故障（`mod_fault`）——正常拒绝与整轮丢弃→重建→缓存重试链路不可见。现行契约见[运行 trace](../../architecture/mod-trace.md)。

首片不做：CLI 过滤参数、场景 JSON 暴露停用阈值（sim 层 breaker 场景不触发自动停用，停用序列在 kk-runtime 阈值 1 测试覆盖）、`mod inspect` 输出 trace。

## 实现结构

- `kk-runtime/src/mod_trace.rs`（170 行）：`ModTraceEntry`/`ModTraceEvent`/`TraceLog`（`TRACE_CAP`=1024 截尾+dropped 计数；文本 200 字符截断）；`stage_label` 槽阶段、`fault_kind_label` 故障种类→与 `ModFaultKind` serde 同名的 snake_case 稳定串（与 mod_fault 报告可 join）。单测覆盖上限/截断/标签一致性。
- `kk-runtime/src/mod_vm.rs`：`trace: Option<TraceLog>` + `enable_trace`/`trace_enabled`（记录点门控）/`record_trace`/`trace_snapshot`/`slot_inactive`；trace 在 ModVm 容器上，**跨 realm 重建保留**。`ModAutoDisable` 新增 `mod_id`（停用来源，归责单口径）。
- 记录点（全部先 `trace_enabled()` 判空——关闭时无条目构造）：`embed/mod_chain.rs` 槽执行器（Ok 按 outcome 记 Completed/Inactive/Declined——Inactive 经 `ModRealm::is_inactive_slot` 判定停用丢弃；Err 记 Fault 后原路径留存 last_fault）；`embed/execution.rs`（自动停用决定 + 结算失败 SettlementRetry）；`embed.rs::rebuild_mod_realm`（needs_recovery→成功记 RealmRebuilt）。
- `EmbedEngine::enable_mod_trace`（装配前挂起、setup 应用）/ `mod_trace_snapshot`；`restore_checkpoint` 把挂起标志转移到替代引擎（续跑保持开启）；teardown 重置挂起标志。
- CLI：`sim run --mod-trace`、`mod test --mod-trace`（透传并在汇总报告记录该旗标）；报告 `mod_trace` 字段关闭时为 null，开启时含 note（"诊断快照，非确定性回放日志；复现=同场景+同包计划+同二进制重跑"）。
- 夹具：`compat/fixtures/mod-trace/`（gatekeeper：可通行/可扣押动作对，房间可见对象+玩家类 emit；breaker：link tick 前置抛错）与 `compat/fixtures/sim-mod-trace/`（两场景按 selection 选包；main.js 对未装配玩家面静默空转）。

关键口径：槽事件 tick=提交前世界时间（结算 tick N 记 N，提交后游戏时间 N+1——与 ModSettlementFault.trigger.tick 同口径）；故障绑定形态 `ns:handler.{id}`（handler 类）与 `{intent键}.process`（decline/process 类），与自动停用归责同一来源；一轮内事件序 槽故障→停用决定→缓存重试，重建在下一次结算入口。

## 复审

三路只读 subagent 复审（记录点与事件正确性 / 有界与隐私纪律 / 测试与文档一致性），发现与清偿：

- 三路共识高危 1 项——**检查点续跑丢失 trace 开启状态**：`restore_checkpoint` 用替代引擎整体替换 self，`mod_trace_pending` 挂起标志被丢弃，续跑静默失去 trace 且报告 note 误报"未装配"。已清偿：`embed/checkpoint.rs` 在替代引擎装配前转移挂起标志，checkpoint 注释的"不进检查点"清单补 trace 缓冲；CLI 新增续跑回归测试（上节）。
- 记录点路（建议阻断→已清偿）：中级 1——首测试 all() 对空条目恒真，补非空断言；低级 4——`SlotFault.kind` 用 Debug 变体名与 mod_fault 报告的 serde 名不一致（改 `fault_kind_label` 稳定映射+单测锁定）；停用命名空间槽记 Completed 误导（新增 `SlotInactive` 事件+`ModRealm::is_inactive_slot` 访问器+e2e）；挂起标志 teardown 不清（teardown 重置）；建议 3 项——`ModAutoDisable` 携带 `mod_id` 消除双口径（已做）、"infra" kind 分支不可达（改记 `chain` 并注明）、早退路径不记录缺注释（补注释）。正向确认：tick 口径/不重不漏/控制流零影响/stage_label 完备/trace 跨重建保留。
- 有界与隐私路（不阻断，2 项中级已清偿）：关闭路径条目构造发生在判空之前（"默认关闭零成本"声明不实）——重构为 `trace_enabled()` 门控 + 定位四元组只在开启时物化；检查点续跑（同上）。低级 1——复现 note 未列 executable_sha256（补全）。正向确认：最坏缓冲 ~1.3MB 可接受、隐私面无 args/state/fields/Memory（decline code 受宿主 1..=128 字符 ASCII 白名单约束）、报告面关闭时 null。
- 测试与文档路（有条件通过→已清偿）：高危同检查点续跑；低级 4——台账计划措辞与实际事件序不符（Fault→AutoDisabled→Retry→Rebuilt，本文件口径已按实际写）、"故障停用包"在 CLI 层不触发停用（措辞已改）、发生序断言只锁首次出现（改全序列相等）、README debug 构建（与 mod-typed/sim-mod-buildings 同款先例，保留）；建议 4——CLI 两轮 concurrency 不对称（已对称）、breaker 失败归因断言（已加 stage==runtime）、note 区分未装配（已改）、mod test 汇总记录 mod_trace 旗标（已加）。
