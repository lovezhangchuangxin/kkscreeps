# Mod 转换、拒绝与故障来源边界复审（2026-10-04）

复审范围是 a8708d9 后的三片未提交实现：[转换边界](mod-conversion-boundaries-2026-10-04.md)、[正常拒绝](mod-intent-decline-2026-10-04.md)、[故障来源](mod-fault-attribution-2026-10-04.md)。这些记录保留其原构建、指纹与测量，本片单独记录最终修复和验证；当前机制以 [Mod 处理链执行](../../architecture/mod-execution.md) 为准。用户原有的计划文档与链驱动实验不属于本次提交范围。

## 已确认并修复的问题

**P2：异常格式化先于原始故障留存。** 内层 beta 处理器 throw 带 message getter 的对象，getter 捕获一次非法绑定 read 的错误后返回正常文本。原实现先执行 getter，Rust 先留存 capability 故障、binding=None，随后 beta 的 handler 错误无法写入；toString 中触发另一已安装绑定的写入转换错误也能抢占来源。未捕获该故障的传播还会多次执行格式化钩子。整轮候选虽然仍失败，但诊断可能误导后续故障处置，且诊断期间仍能访问候选。

复现使用真实 V8 与两层 Mod 链，原实现断言失败：预期 beta:handler.inner，实际 None。日志与源码指纹在最终机器证据中保留。

修复将故障记录拆为先认领来源/备用文本、再补充一次文本。认领时关闭候选访问；更早的 Rust 故障不能被 SDK 改写，后续传播直接复用已有诊断。message 只读取一次，普通格式化抛错保留备用文本；最外层抛出诊断字符串，使 Rust 异常提取不重新进入原对象的 toString。预算超限仍优先返回 resource，不强行逐 Mod 归责。成功链没有新增 op；诊断补充只发生在故障路径，profiler 将两步都计入原 op_fault 阶段。

新增回归覆盖 message getter 与 toString 中的非法读、跨绑定 Symbol 转换，以及合法候选读/写/native 尝试。断言实际 Host 没有收到诊断期间的候选调用、格式化仅一次、来源与文本正确、能力已销毁；诊断启闭一致。

## 复审边界

另核对正常拒绝在 before/wrap/process/replace/after 的整动作恢复、跨 namespace 暂存、字段与位置信封恢复；先前故障和后续异常仍优先。内建 native 的 Declined 明确失败，不能发布部分写入。注册关闭门先于 getter 转换，转换期间没有 OpState/候选借用；转换失败不能冻结部分注册计划。runtime 诊断跨恢复保留、实际结算清除，非 Mod 故障不残留旧来源。未发现其他已确认的可操作问题。

已知未实现能力继续保留：内建动作局部恢复、重复异常停用、共享资源的逐 Mod 责任账本、持久日志/进程崩溃恢复。可信共享 Mod 的底层 op 不是不可伪造身份；诊断来源不能独自构成自动停用依据。此前无 Mod CPU、空 Mod 与尾延迟差异尚未关闭，不用本次复审推断架构整体性能达标。
