# 受击策略第一片：原生 TOUGH（2026-10-06）

基于 `520bbad`。补齐强化 TOUGH 的原生受击公式，为下一片 JS 受击策略建立默认行为与恢复基线。现行机制见[受击结算](../../architecture/creep-incoming-damage.md)，真实玩家场景见[TOUGH 夹具](../../../compat/fixtures/sim-tough-damage/README.md)，机器证据见[验收数据](n2c-tough-damage-2026-10-06.json)。公式依据固定 screeps-ok `34a630e` 所装载的 `@screeps/engine` 4.3.0 中 `_applyDamage`。

## 实现与复审

- 原生/JS 主伤害、批量与反击共享减伤前队列；最终在 creep 对象 tick 按身体顺序消耗现有耐久的承伤额度，总减免取整一次，再合并治疗、判断死亡及处理 CARRY 掉落。
- GO/GHO2/XGHO2 比例直接取内建 BOOSTS；无效强化、非 TOUGH 和已毁部件没有额外减免。未强化部件仍消耗身体前列承伤额度。
- `damage/tough.rs` 为纯计算模块，不改候选或队列，保留原始 i64 伤害低位；身体重分配、墓碑、库存及事件由既有应用器负责。
- 正常拒绝恢复原始队列；晚期写回失败撤销候选，缓存重试从已提交身体重新计算，Memory 与 Mod state 恰一次提交。没有新增持久化字段或 JS 槽。
- `applyDamage`/批量/反击 amount 均为减伤前伤害，攻击事件仍记录原始量；当前架构文档同步说明与既有 JS 护甲公式叠加、受击替换仍待开放，历史交付记录不追改。
- 原生与复用公共 SDK 的独立 flat-damage 包各有真实玩家场景；双方连续两轮攻击，受伤后保存退出、加载继续，核对下一轮剩余 TOUGH 耐久。
