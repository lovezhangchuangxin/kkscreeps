# N2c 第四片：JS 反击表（2026-10-06）

基于 `a2d82a1`，开放三个攻击槽的 `ctx.combat.setRetaliation`。JS 在执行前声明一次目标/反击量表，主攻击仍可由 native 中心、request 或自定义单体/群体伤害执行；反击按实际受击对象匹配并直接登记到原执行者，不递归攻击链。现行契约见[JS 反击策略](../../architecture/combat.md#反击)，机器证据见[验收数据](n2c-retaliation-policy-2026-10-06.json)。

## 实现与复审

- 未声明表时，native 与 JS 伤害保留此前各自的默认反击行为；空表禁用本动作反击，显式表替换全部默认反击，未命中表项无效果。
- 声明不消耗主攻击，但须在攻击执行前且最多一次；多个声明者、cancel/native/request/JS 伤害之后声明、治疗或非战斗槽声明均为故障，catch + decline 不能发布。
- 表沿批量伤害已有的有界 SDK 复制与可重入 op 转换，保留原始浮点校验、转换前/后能力检查和故障留存。按规范 ObjId 检查重复，整表有效后才移交不可变策略。
- native 主攻击保留功率/距离/安全模式和 rampart 选目标；只有进入伤害应用的实际 ID 触发反击。配置被保护 creep 不会误触发 rampart 的反击；被击毁的结构仍能产生声明的荆棘。显式反击不重新附加原生反击准入规则。
- 执行前为整表反击量与自伤预留 i64 累计表示域；直接引擎测试确认溢出不先扣结构耐久、登记事件或消耗 ID。JS 单体伤害也增加此前待伤害量的溢出检查。
- 共用伤害应用器维持结构摧毁 → HIT_BACK → 主攻击的事件顺序、延迟身体结算、治疗合并、死亡与库存路径；反击不会生成递归命中。
- 执行者已在原战斗快照中，主攻击目标由原目标集/首触日志覆盖；声明表不写其他世界对象。局部拒绝撤销主攻击和反击并保存此前双队列、转账及后续移动，晚期写回失败重用玩家缓存，反击致死、墓碑、Memory 和 namespace state 恰一次。
- 两个独立 JS 包通过公共 SDK 声明表后 request 原目标，保留相同主攻击。固定 7 和按未强化 ATTACK 基础功率 20% 计算的荆棘有不同计划身份；单选成功，双选在 mod inspect 报多 replace 冲突。
