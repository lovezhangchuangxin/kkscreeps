# A3 候选事务改造与验证

本次从 `6248546` 开始，先接入本仓进程资源采样，再改造引擎结算候选。方向依据 [ADR-014](../../decisions/ADR-014-contribution-plane.md)，前置核查见 [A 阶段核查](../../plans/a-stage-current-audit.md)。本记录说明本次交付及验证边界。

## 实现

`OwnedTickTxn` 统一拥有固定 TickInput、意图、房间候选、市场候选、事件以及玩家候选和 ID 游标。房间结算共用同一份 `TickState`；GCL、claim 检查与 ID 分配在方法返回前结束 RefCell 借用，不再让 Working 长时间借用外部 players/next_id。

通知保留与玩家房间集合重建移到候选准备阶段。共享句柄全部释放后，候选转换为不共享的 `PreparedTick`，发布函数只写回结算结果并推进世界时间与版本。发布前仍有规则持有共享句柄时返回错误，不复制一份候选继续提交。

公开的 `settle_room` 参数从独立 players/next_id 借用改为 `&TickState`；直接调用方提供拥有数据的候选，用 `into_parts` 取回玩家表与游标，失败时自行丢弃候选。仓库内的测试助手已迁移。引擎未新增 unsafe 或 VM 依赖；Rc/RefCell 仅供同线程候选访问，不提供跨线程房间调度。

房间规则仍局部借用 room。本次未接入 JS Mod 回调，未来接入时仍须结束房间可变借用再调用 JS；拥有事务不能替代这项重入约束。RawMemory、segments、CPU 桶仍在世界结算后由协调器提交，完整统一提交属于 A4。本次没有解决执行阶段基础设施故障的完整恢复、公开 Engine 字段的变异绕过或磁盘恢复。

## 性能采样与平台边界

perf-probe 新增当前进程全部线程的 CPU core-ms、每 tick 平均 CPU、tick 边界 RSS 及采样开销，阶段耗时补 p99。玩家数量接受 1..32，非法请求报错，避免悄悄缩小负载。资源采样不改变玩家 CPU 计费。

macOS 采样经实测，Linux 分支用项目工具链对 x86_64-unknown-linux-musl 做了独立编译检查，没有在 Linux 执行负载。CPU 包含采样与窗口内自检，RSS 峰值是边界样本最大值，可能漏掉 tick 内瞬时峰值；其他进程与中间件不在本次 CPU/RSS 统计内。

使用 [重复运行工具](../../../scripts/perf-baseline.py)，改造前后分别对 1/4/8/32 玩家各做五次独立 release 运行，每次预热 500、采集 3000 tick。原始数据包含二进制 SHA-256、系统、工具链、源码提交与工作区状态：

测量机器为 Mac16,12、Apple M4、10 个逻辑 CPU、24 GiB 内存，系统为 Darwin 24.6.0，Rust 工具链为 1.98.1。报告中的 git 状态来自运行时工作区，二进制身份以 SHA-256 为准；重现时需保留对应源码修改并重新构建。

- [改造前原始数据](a3-before-2026-10-02.json)：引擎为 6248546，已接入采样器和 p99，尚未改造候选。
- [改造后原始数据](a3-after-2026-10-02.json)：接入 A3 后的 release；本次修改尚未提交，工作区状态在报告内记录。

本地机器没有控制其他应用、频率或温度；改造前部分运行与开发编译活动重叠，墙钟不能据此作严格因果判断。负载每玩家独立小房间，自检只覆盖首房，长窗口含生命周期变化。本次不是官方私服/xxscreeps 三方对照，也未完成完整架构性能验收。

复跑旧版本时曾共用 Cargo 目标目录，导致一次复测链接旧依赖、报告缺少 p99；该组数据已丢弃。随后清理并重建 kk-engine/kk-runtime/kk-cli 的 release 产物，确认报告格式，再重新跑完整套件、bot 和性能测量。重复运行工具现在在每轮检查 p99 与进程采样字段，并保存中间原始数据；跨修订构建应使用独立目标目录，避免混用缓存。

提交前复查补充了每轮结束后的二进制哈希检查，防止最后一次运行期间替换二进制却产出完成报告。Python 回归覆盖旧报告第一轮拒收，以及最后一轮替换时只保留前三轮中间数据；两项均通过。
