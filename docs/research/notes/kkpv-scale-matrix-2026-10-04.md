# KKPV 双通道规模矩阵（2026-10-04）

外审登记三件中「≥5 样交错正式判读」与「C 批后 4p/8p kkpv 双通道复测」的
交付证据；「SharedKkpvBundle 地形钉住测试」见同日提交 ac3b248 的 embed 级
集成测试。本记录只登记本机合成负载的测量事实与判读边界。

## 工具与口径

`kkscreeps perf-probe`，warmup 50 + 采集 300 tick，玩家并发 2（引擎默认，
门禁逐报告核对），4/8/32 玩家（每玩家独立房间，采集/升级合成 worker，
无 Mod）× JSON/KKPV 两通道 × 5 轮，每次运行独立进程。两重交错：同一轮
内两通道顺序逐轮交换（偶数轮 json→kkpv、奇数轮 kkpv→json，近似抵消等
间隔线性漂移）；**规模顺序逐轮轮换**（4/8/32 → 8/32/4 → 32/4/8），
避免固定规模永远占据轮内同一位置造成跨规模比较的位置混杂，轮内序号
随归档。逐报告门禁：通道/规模/窗口/并发/debug 断言关闭/负载身份
（progress_delta 非正即拒绝）/相位样本数/RSS 采样数（=tick+1）/指标
有限非负/单次运行墙钟上限/二进制 SHA-256 跨运行不变。初次采集采用固定
规模序，评审指出 32p 恒居轮内末位的位置混杂后废弃重采，未入库。

```sh
cargo build --release -p kk-cli

# 采集完成后将输出整体归档为本目录的 kkpv-scale-matrix-windows-2026-10-04.json
```

主指标的通道间区间**全部无重叠**（含 4p/8p/32p 的 CPU、wall P50、RSS、
每玩家注入字节）。注入字节五次运行逐字节相同（min==max），是确定性量
不是采样量。

结算金丝雀（名义上通道无关相）：8p +1.2%、32p +0.9%，两通道区间重叠，
机器态可比；**4p 档 +11.5% 且区间不重叠**（json 0.062..0.064 vs kkpv
0.068..0.070）——结算相在 kkpv 臂系统性偏慢，候选解释是编码与共享束
带来的内存压力对后续结算相的二阶影响（规模越小占比越大），也不能完全
排除该档机器态漂移；4p 判读的不确定度因此加宽。主差值（+42%~+62%）
远超金丝雀偏离，方向结论不受影响。

## 判读

1. **32p 正式判读**：5 样交错下 KKPV 劣化 wall +12.6%（区间无重叠）、
   CPU +20.7%、每玩家字节 −89.7%（数值与 B.6 双样逐项吻合：11.6KB vs
   112.7KB）。方向与 B.6 双样结论（wall +19~24%、CPU +26%）一致，幅度
   偏窄——json 臂绝对值高于 B.6 会话（CPU 16.90 vs 16.2..16.7、wall
   6.60 vs 6.19..6.23）、kkpv 臂持平（CPU 20.40 低于其双样下界 20.5、
   wall 7.44 落在区间内），json 臂变慢更多使比值收窄；不把跨会话的
   比值差异归因为实现变化。RSS −4.7%（B.6 双样 −16%）：反转幅度更小
   但区间仍无重叠，方向维持。B.6 消费者缺口 6（双臂原始报告未归档）
   自本记录起闭合：30 个原始报告随批入库。
2. **4p 墙钟收敛**：B.6 判「4p 墙钟未收敛（噪声大）」，5 样交错+位置
   轮换后收敛为 +49.7%（区间无重叠）——小规模劣化是稳态事实，不是噪声。
3. **8p 首组数据**：+42.4% wall / +52.7% CPU / 字节 −77.8%，填补外审
   指出的「C 批后任何规模均无 kkpv 双通道数据」空档。
4. **规模规律**：CPU 亏损 4p→8p→32p 为 +62.0%→+52.7%→+20.7%，wall 同序
   +49.7%→+42.4%→+12.6%（单调收窄，位置混杂已由轮换均衡）；每玩家字节
   优势同序 −65%→−78%→−90%（单调扩大：信封随注册房数线性增长而私有束
   近似常数）；RSS 在 8p→32p 之间发生交叉反超。**在 4..32p 范围内
   CPU/wall 未出现回本点**。
5. **相位归因**：project 相（Rust 投影+编码）相对劣化最大（+19%~+74%，
   规模越小越突出），run 相（JS 消费）+15%~+41%——与 B.6 残余 ~20% 的
   归因（双趟投影、列式编码与 JS 解码 vs 原生 JSON.parse）方向一致；
   收敛手段维持归 C/D 批，不在本记录范围内实施。4p 金丝雀的通道间差
   提示内存压力的二阶影响也应纳入收敛时的观测面。
6. **与 Mod 负载数据的关系**：双玩家 Mod 闭环独立采集
   （[mod-player-review-2026-10-04.md](mod-player-review-2026-10-04.md)）
   得 KKPV 慢 ~25-30%（CPU 0.427 vs 0.331）——不同负载口径（有 Mod、
   逐轮状态核验计入进程 CPU），方向与本矩阵一致：小规模下 KKPV 更慢。

## 结论边界

- 默认通道维持 JSON：本矩阵在 4..32p 全档给出 KKPV 的 CPU/wall 劣化与
  字节/RSS 收益，未支持切换；不据此宣称 KKPV 路线失败——其确定收益
  （每玩家注入字节、大规模 RSS、代际共享）在带宽受限部署与更大规模下
  才兑现，成本收敛（投影/编码/解码）是已登记的 C/D 手段。
- 本机合成负载、每玩家独立房间、无 Mod、无共享房竞争、无网络下发；
  官方私服与 xxscreeps 对照仍后置（P2 登记）；跨会话的比值不可比
  （见判读 1），复跑以金丝雀与区间判读。
- native/empty 尾延迟差异维持「未归因、不声称零回归」登记；V8 堆内
  滞留的量化（长窗 + 压力形态）维持登记，钉住测试只锁 Rust 侧下界与
  完整性。
