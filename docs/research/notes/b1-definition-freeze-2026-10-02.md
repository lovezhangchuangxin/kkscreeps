# B.1 定义校验与计划冻结

本片在 `0fa131a` 的基础上新增 `kk-mod-api`，落实[领域与投影设计](../../designs/domain-projection.md)的 B.1。它是可测试的独立描述层，尚未改变生产引擎或玩家沙箱；不是完整 Mod 支持。

## 实现

稳定键以 namespace:name 表示，类型、字段、意图、规则、槽位与处理器按键归一化。冻结器检查重复定义、命名空间归属、引用/schema 版本、字段默认值、数值边界和关联约束。schema 深度在复制和递归值校验之前检查。

规则覆盖不按注册先后决定。单方覆盖可直接采用，多方覆盖须显式选择来源；未选中的贡献也须通过值校验。冻结规则存为平坦数组，装配时解析句柄，读取时按索引访问。

处理器按同一入口、同一种 kind 的依赖拓扑排列；稳定键决定无依赖节点的次序。无附加处理器生成 Native，否则生成 Chained，唯一 replace 或 native 为中心，After 列表已逆序。依赖环、未知引用及多个 replace 在冻结时拒绝；本片不执行回调。

计划指纹使用 SHA-256，覆盖规范化描述、有效规则、执行顺序、生成的类型/字段目录、投影版本与来源摘要。JSON 对象键排序，浮点负零保留。冻结计划只提供不可变访问，整数句柄限定在生成它们的计划和类型内。

link 描述提供 15 项默认规则：初始/最大生命、容量、冷却、建造成本、损耗率及 RCL 0..8 配额。数值来自现有 `kk-core`，测试与玩家常量 dump 对照。建造成本受当前工地 `progress_total: u32` 表示限制；冷却系数受房内最大距离乘法限制，实际状态相加仍需接线时校验。Store 采用有界映射，允许缺少 energy 键。

### 复查修复

复查确认两处问题，先以失败测试复现，再修复：

1. 字段句柄只有下标，传入另一类型时会取到其同下标字段。句柄现在携带所属类型，`get_field` 拒绝错配；跨计划使用仍须在作业/视图边界核对指纹。
2. link 意图描述要求 resourceType 存在，但现有结算只依赖 id 与 amount。Record 现在独立声明可省略成员，link 的 resourceType 可省略或为 null；新增测试也确认可省略不会自动允许 null，未知成员和无效 optional 声明仍被拒绝。

修复后工作区测试为 412 通过、0 失败、5 忽略，包含 20 项集成测试、1 项 schema 单测及 1 个文档示例。Clippy、格式与链接检查通过。完整 screeps-ok 仍为 1854 通过、153 既有失败、907 跳过，相对 P2 报告的逐用例新增回归为零。没有修改运行接线、兼容地板或豁免。

测试覆盖注册顺序、多个类型的字段身份、规则选择、未知/重复定义、数值范围与有限值、关联约束、权限声明、字段默认值/限额、类型版本、处理器排序/依赖环/替换冲突、意图作用域及来源摘要变化。完整套件验证默认行为保持，不代表尚未接入的 Mod 或投影通路已通过。

## 后续接线要求

B.2 将声明的绑定连接到 link 初始化、建造、容量、预检、转移和冷却实现，并验证所有消费者使用同一有效规则。`required_bindings()` 是安装要求，当前声明不能替代实际实现的核对。link 工厂的源码摘要仅覆盖描述工厂，运行接线时须加入真实 native 和玩家代码摘要。

已有对象上的扩展字段与候选更新由 B.3 接入；授权编码、KKPV、共享句柄和惰性包装器由 B.4/B.5 完成。JS 装载、重入及 VM 状态恢复仍在 C，持久化在 E。本片不宣称热更新、共享直读、性能收益或磁盘恢复保证。
