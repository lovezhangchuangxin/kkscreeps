# Mod 写入转换直接计时（2026-10-03）

承接已提交 `1df66bd` 的 [上下文复审修复](mod-context-review-2026-10-03.md)。本片补齐写入转换的直接计时和 getter 预算验收，不改变 JSON 载荷形态或反序列化规则。

## 实现与验收

能力核验通过后取得可选诊断句柄；在不持有 OpState/候选借用的情况下，围住真实 serde_v8::from_v8 调用记录 write_from_v8。TryCatch 创建/销毁、Rust 错误文本格式化、绑定检查与领域写回在此阶段之外。它包含 getter 执行及其嵌套 op，不能称为纯 JSON 转换耗时；转换失败也计入尝试，错误数由 op errors 记录。关闭诊断时不采集时钟。

CLI 诊断报告升为 v3。报告门保留历史 v1/v2 校验，v3 完整链要求每槽各六次 read_to_v8 / write_from_v8；任一阶段缺失或次数、错误数、耗时类型异常都拒收。

Host 子进程矩阵同时运行诊断关闭/开启两个版本：getter 嵌套读、嵌套写、吞掉嵌套候选故障、吞掉转换故障与非法绑定，共十个窗口。除原成功/失败语义、after/native 执行、能力销毁，还核验嵌套/失败的转换与 host 写入次数及 op 错误数。非法绑定不启动转换，转换失败不进入 host 写回。

真实资源矩阵新增 getter 死循环的 CPU 与墙钟两例：CPU 限额 10 ms；墙钟例使用 CPU 2 s、墙钟 30 ms，以区分两类限制。父进程保持 10 s 外层期限；两例均确认资源错误而非永久挂起。

## 测量边界

使用既有 [交替探针](mod-attribution-probe-2026-10-03.py)，原版为复审通过的同一 release（有 v2 读转换计时），新版本增加 v3 写转换计时。400 link，100 tick 预热、500 tick 采集、三轮 24 窗口；包/预算身份、全部对象摘要和四个链位计数必须一致。诊断窗口与无插桩窗口分开，采集期间不运行构建、测试、兼容或 bot 套件；允许短文本读取及文档编辑。

本片旨在取得可核验的转换成本，普通运行收益不作预期。诊断有计时开销；桌面负载未控制、窗口短，纯结算不代表玩家、投影、持久化或网络闭环。

首次启动的采集与尚未结束的兼容棘轮重叠，已主动中止，partial 与日志仅存入本机 /tmp；没有计入本片结果。最终采集在确认全部套件结束后重新开始。

## 结果与后续验收

[原始报告与验证](mod-write-conversion-validation-2026-10-03.json) 保存最终 24 个窗口、源码/二进制指纹及 validation 字段。原版与新版本分别按 v2/v3 校验；三个边界的全部 link 状态摘要一致，完整链四个计数终值均为 240000。新版本各转换阶段在每个采集窗口均为 1200000 次，全部 op 错误数为零。

新版本三轮诊断阶段的中位数：

| 阶段 | ms/tick | 边界 |
| --- | ---: | --- |
| read_to_v8 | 4.535 | 实际读取序列化 |
| write_from_v8 | 8.786 | 实际写入反序列化，包含 getter 及其嵌套 op |
| host_read | 2.905 | 候选读取与封套构造 |
| host_write | 2.722 | 领域比较/校验及 namespace 写回 |
| op_write | 12.063 | 包含转换、领域写回、能力检查及 op 包装 |

固定夹具没有自定义 getter，写入转换约为领域写回的 3.2 倍，为后续反序列化优化提供直接证据。旧版本不包含 write_from_v8，不拿旧 op/host 差额替代直接计时，也不把相互包含的阶段相加。

无插桩完整链 P50 的三轮中位数为 27.094 → 27.342 ms，进程 CPU 为 28.088 → 28.699 core-ms/tick。P99 每轮分别为原版 29.728 / 28.859 / 28.096 ms、新版本 40.271 / 28.451 / 42.705 ms；旧版本诊断窗口也出现 45.854 / 28.914 / 44.645 ms 的尾延迟。保留全部波动样本；当前短窗口不足以确定原因或确认尾延迟稳定性。本片不建立性能提升结论，后续优化验收须扩大无插桩窗口与重复次数。

全量检查通过：561 个 Rust、19 个 JavaScript 测试，9 个 Rust ignored，格式/Clippy 通过；Python 全套 14 测通过。release 兼容棘轮为 1854 passed / 153 failed / 907 skipped，零转红/转绿。TooAngel/Overmind/WASM 完成 2000/2000/10 tick，均无硬中断、惩罚跳过或 missing API；既有 Overmind 的 1 个 console-error tick 与 TooAngel 的路径错误日志仍在。

## 本片复审清偿

确认一项 P2：单份报告支持 v1/v2/v3，但重复采集没有核验同一端的诊断版本一致性，汇总仅枚举首份阶段。受控子进程将新端第二轮 v2→v3 时，修复前成功报告静默省略 write_from_v8；v3→v2 则以 KeyError 失败。此问题不影响已保存的 24 窗口（各端版本稳定），影响采集门和后续诊断结论的可靠性。

基线与前后对照现在共用诊断身份核验：同一采集组版本/阶段变更立即拒收并保留此前 partial；不同二进制仍可使用不同版本。汇总入口也先检查阶段身份。新增四个测试覆盖两方向漂移、不同二进制版本可共存、同版本阶段漂移及直接汇总拒收。修复后 Python 全套 18 测通过，重新运行全量检查仍为 561 个 Rust、19 个 JavaScript 通过，9 个 Rust ignored。运行时与 release 二进制未因本次门禁修复改变，既有棘轮、bot 与测量证据仍使用其原构建指纹。
