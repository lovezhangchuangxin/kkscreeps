# Mod 热路径成本归因与字段缓存（2026-10-03）

承接 [密集 Mod 纯结算基准](mod-budget-review-and-perf-2026-10-03.md)。本片新增默认关闭的包含计时，先测量再减少重复字段解析；不改变处理链、事务提交或默认资源额度。当前未提交，基线仍为 `471ac1d`。

## 实现与验收边界

`ChainProfiler` 记录整槽、JS 调用、预算启动/结束、Deno op 和 Rust host 候选访问，CLI/重复采集脚本通过 `--profile` 开启。普通运行不安装 op metrics、不读取阶段计时时钟。统计只保存累计次数与纳秒；预热后 reset，恢复沿用同一诊断句柄，记录全部尝试而非提交账本。

Deno 0.412 的同步慢 op 指标包装包含参数反序列化、host 与返回序列化；快 op 同样有包含计时，但错误事件不等于完整业务故障数。报告中的 errors 是 Deno 错误事件数，非 op 阶段只记次数/耗时。各阶段存在包含关系，不能相加；op 减 host 仍包括绑定校验、包装和插桩开销。fixture 不发生嵌套 op，也没有用户 getter。此诊断不提供逐 Mod 计费或 GC 的独立归因。

runtime 只在一次 `ModChainContext` 能力内缓存已解析目标字段。无变更写入仍比较完整字段，改变值继续走原领域校验；字段改写和 native 入口都让缓存失效。namespace state 不缓存，next 前同步、内层返回后刷新、JS 引用保持及 sticky fault 不变。缓存不跨对象、槽、tick 或失败重试。

新增验收检查诊断开关下全部目标状态等价、预热排除、每槽六读六写和一次 native 的准确计数、op 错误事件、候选能力释放、窗口 reset 及错误诊断句柄密封。现有嵌套写入、native transfer、Mod 对象、跨 namespace、引用/别名、取消、非法写入和失败恢复测试继续覆盖缓存失效。

## 测量

[交替探针](mod-attribution-probe-2026-10-03.py) 保存原 release、仅加插桩但尚未缓存的 release 和优化 release，分别对比无插桩性能和诊断阶段。400 个 link，100 tick 预热、500 tick 采集，每组独立运行三次；链模式交替前后顺序，另外运行 native/empty 对照，共 24 次。没有并发运行本片构建、测试或兼容性套件。三个边界核验全部对象，跨二进制摘要一致；每个链位最终均为 240000 次，诊断每窗口 200000 槽、1200000 次读和写。

原始数据与二进制 SHA-256 见 [采集记录](mod-attribution-validation-2026-10-03.json)。这是本机探索性对照，不替代上一片五轮长窗口基准；桌面应用与频率未控制。采集只含纯结算，未测玩家执行、投影、存储或网络。

| 无插桩模式 | 优化前 P50 ms | 优化后 P50 ms | 优化前 P99 ms | 优化后 P99 ms |
|---|---:|---:|---:|---:|
| native | 1.954 | 1.905 | 2.209 | 2.177 |
| empty | 1.898 | 1.898 | 2.200 | 2.154 |
| chain | 36.940 | 33.207 | 38.638 | 37.660 |

各项为三次运行该指标的中位数。chain P50 下降 10.1%，进程 CPU 从 37.968 降至 34.219 core-ms/tick，下降 9.9%。native/empty 差异在本地噪声范围，不解释为优化收益。优化后 chain 三次无插桩 P99 为 34.733 / 37.660 / 38.419 ms；插桩的最后一轮 P99 达 67.217 ms，保留原样，不宣称长尾稳定改善。

| 诊断包含阶段 | 缓存前 ms/tick | 缓存后 ms/tick |
|---|---:|---:|
| host read | 7.999 | 7.525 |
| host write | 6.989 | 3.461 |
| host native | 0.890 | 1.066 |
| op read | 15.154 | 14.898 |
| op write | 15.957 | 12.410 |
| op native | 0.918 | 1.096 |
| JS 整槽调用 | 35.471 | 31.794 |
| 预算启动 + 结束 | 0.680 | 0.657 |

各阶段先按窗口累计耗时除以 tick，再取三次中位数。候选访问合计约 15.88→12.05 ms；主要节省出现在无变更写入的完整字段比较。native 包含缓存失效/释放，因此不能把阶段迁移当成 native 算法退化。op 合计减 host 合计仍约 16 ms，SDK/JS 调用剩余约 3.4 ms，预算约 0.7 ms；这些差值仅用于定位，不作为纯序列化或 GC 的精确账单。

下一步优先减少候选上下文构造中的重复 Value 复制及跨语言转换，保留目前同步契约。当前证据不支持移除预算检查、增加默认额度或以房间并行代替热路径优化。

## 对照身份门禁复审修复

复审发现交替探针只核验 chain 身份；改变 empty 包摘要或 native/empty 的报告预算时，旧脚本仍会输出 `complete: true`。现改为按模式保存包与预算身份，跨版本和重复轮次统一检查，变化即失败并保留未完成记录。不同模式的包身份允许不同。

[脚本回归测试](../../../scripts/tests/test_mod_attribution_probe.py) 用受控子进程报告覆盖稳定身份、跨版本包变化、三个模式的预算变化、后续轮次变化和失败后的输出状态；新四测在修复前复现四处失败，修复后通过。与既有 Mod 报告门合计八测通过，Python 脚本测试全套十一测通过。已重新核对保存的 24 个真实样本，每个模式均只有一组身份，因此本片的性能数值无需重采。原采集和 validation 指纹保持历史值，修复验收另记于采集文件的 review_fix_validation 字段。
