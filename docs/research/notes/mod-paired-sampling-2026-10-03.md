# Mod 成对采集工具（2026-10-03）

承接 `6772e8f` 的写入转换计时与重复报告门禁。本片扩展测量工具，为后续写入反序列化优化保留足够的无插桩对照；不改变 Mod 载荷、候选提交或资源预算。

## 实现

[维护脚本](../../../scripts/mod-perf-compare.py) 默认 500 tick 预热、3000 tick 采集、五轮三模式，允许调整窗口/规模与子进程期限。逐轮交换两端先后，模式轮换，每对相邻执行；可单独追加诊断窗口和旧端诊断构建。与基线门共用单报告和诊断身份核验，另检查跨端的全部对象状态、包/预算和二进制指纹。

每次子进程前清除临时报表，防止成功退出但没有新报表时复用旧窗口。已有成功文件或 partial 拒绝覆盖；失败、超时、状态或身份漂移只保留此前已验证窗口。

每轮 P50/P95/P99/CPU 都保留，另列每对 after−before、after/before 和各自中位数，不能把成对倍率中位数与独立中位数之比混用。零基线保留差值，倍率为 null。诊断阶段只在相应端按自己的阶段集合汇总，不混入普通窗口。

## 验证

受控子进程覆盖非默认负载、运行顺序、两端 v2/v3、包/预算沿用门、状态与二进制漂移、缺失新报表和超时后的 partial、重复/不完整对、零基线、非法选项及已有证据保护。真实 release 冒烟使用两房各三 link，预热二 tick、采集三 tick、两轮，共 16 窗口，普通与诊断均成功，旧端 v2、新端 v3。

## 扩大窗口的局部对照

真实无插桩采集：400 link，预热 200 tick、采集 1000 tick、五轮，共 30 窗口。使用此前保存的 v2 release 与本片 v3 release；二进制与上片写入转换采集相同。本片增加采集窗口和重复轮次，仍低于正式验收的 500/3000；未控制桌面负载，也不运行玩家/投影/存储/网络。

## 复审清偿

确认一项 P2：开始时的 exists 检查不能保护长窗口内后来出现的同名 output，成功汇总的 write_text 会覆盖它；两个采集进程也可能在首个窗口之前同时进入并互相改写 partial。受控子进程在第二个窗口创建“original evidence”，修复前最终报告覆盖它且不报错，回归断言失败。

采集前现在以同目录临时文件的独占硬链接占用 partial；同路径竞争者不能启动子进程。partial 逐次完整写入临时文件后原子替换，写入失败保留上一份有效证据。成功报告也独占发布，后来出现的 output 保持原内容，当前全部有效窗口留在 partial。增加并发占用、迟到 output 与写入中断三个测试，Python 全套 27 测通过；真实 release 冒烟再次完成 16 个窗口。没有修改游戏二进制，原 30 窗口数值及其原采集指纹保留，复审后的工具指纹另记在 review_validation。
