# 基础检查点与冷恢复交付记录

本批落实完整玩法计划 N4 的前置片：保存当前完整已提交状态，公开 runtime save/load 与 sim 重启续跑。现行数据清单、版本与失败边界见[基础检查点](../../architecture/checkpoints.md)。不包含定期调度、数据库、输入日志、确定性回放、自动迁移、热更新或 outbox。

## 实现与复查

- 世界以房间顺序二进制信封保存全部对象/地形/事件，扩展字段独立保存；核验跨房 ID 唯一性、坐标、地形、时钟与游标，重建派生缓存。
- 引擎保存玩家账户/完整 CPU 桶/Memory/segments/通知、市场/游标、事件、Mod state 与计划身份；恢复复用 Mod 对象与扩展字段校验，不通过推进隐藏 tick 修补载荷。
- runtime 保存原工作者子集和模块字节、包/配置/选择/预算/冻结选项、停用与故障计数；替代分片全部验证后才切换。回收旧 Mod realm 遵守 V8 Enter/Exit 栈，拒绝越过其他活跃分片切换。
- 单文件 v1 信封包含完整载荷与 SHA-256；文件同步、rename 后同步父目录。替换前失败保留旧文件，替换后错误不能被解释成“必定还是旧文件”；无跨进程写锁，限定一个发布宿主。
- sim metadata 保存场景/模块/CLI 二进制身份、alias 与最初断言起点；续跑不重放放置、不重置 Memory，ticks/提交轮数指本次增量。检查点保存失败保留真实最终状态并返回 I/O 退出码。

复查修正了成功 `Committed` 状态被错误拒绝保存、保存 I/O 错误被标成 setup_failed/零提交，以及同线程替代 VM 回收旧 VM 的栈序问题。有限浮点往返显式启用 float_roundtrip；文件格式与房间布局从本批起按持久版本维护。

## 验证

定向测试覆盖完整权威清单往返、两房两玩家与多个官方 JS 包、JSON/KKPV 两条通道、停用掩码、自动停用计数、命名资源/冻结规则/私有扩展、玩家模块和缓存重置、开放轮次拒绝、缺包/改代码/选择漂移/非法载荷保留旧分片、文件发布阶段错误/真实子进程直接退出（遗留临时文件）和 CLI I/O 故障。

实际线程费用、Date/随机与墙钟输入具有非确定性。完整续跑比较用固定停跑回充轮验证 CPU 状态；真实 CLI 子进程重启的玩法参考比较单独排除实测 CPU 桶费用差异，不能把这种验收说成任意 bot 确定性回放。文件发布验收证明完整版本选择，不是实机断电或网络文件系统耐久基准。

最终命令、二进制身份、全量检查与兼容门禁统计见[机器记录](basic-checkpoints-2026-10-05.json)。
