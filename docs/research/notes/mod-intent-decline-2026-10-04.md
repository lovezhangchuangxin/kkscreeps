# Mod 自有动作正常拒绝（2026-10-04）

接续 [转换边界片](mod-conversion-boundaries-2026-10-04.md)，两片均为 a8708d9 后的工作区改动，本片不重写上一片原始证据。现行机制见 [Mod 处理链执行](../../architecture/mod-execution.md)。

## 选择与范围

正常业务拒绝不能等价于异常：此前 Mod 只能 throw，导致整个分片的候选失败并重建 VM。新增 SlotOutcome::Completed/Declined，Err 保持异常语义；API 使用 `return api.decline(code)` 或导入 decline。返回工厂标记才表示拒绝，普通返回对象与返回码保持既有解释，throw 标记也仍是故障。

首片只开放自有对象意图。其写面限制为当前对象字段与 Mod namespace state，没有 native、事件、玩家或 ID 分配写面。runtime 只保存当前对象字段，state 暂存到成功后；拒绝丢弃暂存 state，沿领域写入门恢复字段与位置索引，保留此前动作结果。该路径不复制房间或整轮共享候选。支持在任何链位拒绝，包括中心已执行之后的 wrap/after。

内建 link native 可以改目标对象以外的状态，不能套用单对象恢复。现阶段使用 decline 明确返回故障，不把未回滚的写入当正常拒绝。纯 Rust callback 尚未提供 Declined，整槽宿主接口已分型；这些边界不能被描述为已实现。直接 ModRealm 返回结局而不掌握领域恢复，其他可信宿主需自行满足回滚契约。

拒绝不重建 VM，模块全局继续保留；持久 state 与对象候选撤销。玩家本轮执行完成、Memory/CPU 候选正常发布，执行费用不退款；未新增逐意图计费模型或玩家拒绝事件。下一步重复异常停用需要单独的故障归因与冻结计划处置设计。

## 回归判据

- 同对象三个有序动作，中间拒绝，前后成功动作仍生效；JSON/KKPV 两通道一致。
- 两个 Mod 在拒绝动作中写目标位置和 namespace state，恢复字段/信封坐标；已初始化与尚未初始化的 namespace 均恢复到动作前状态。
- before、wrap 进入前/退出后、process、replace、after 拒绝；部分已写回候选也整次撤销。
- wrap 捕获内层拒绝仍中止后续写回；拒绝后的异常、先被捕获的转换故障优先，使整轮失败并进入恢复门。
- 直接处理器诊断入口拒绝使用正常拒绝；过期/错误绑定的拒绝 op、非法 code、throw 标记、Promise 均不转成成功；普通对象/数字返回仍 Completed。
- 拒绝保留健康 realm，连续动作的模块全局调用次数递增，候选能力退出后销毁；诊断启闭均验证。
- 内建 link transfer/tick 不接受 decline，不发布部分 native 写入。

验证命令、源码与构建指纹记录于 [机器证据](mod-intent-decline-validation-2026-10-04.json)。


## 验证与性能

全仓检查通过：570 个 Rust 测试（10 个忽略）、19 个 JavaScript 测试，格式与 Clippy 通过。Release 的宿主/完整链测试 21 个通过。固定版本 screeps-ok：1854 passed / 153 failed / 907 skipped，相对逐用例基线零转红、零转绿。

[成对原始报告](mod-intent-decline-perf-2026-10-04.json) 共 18 个完整窗口：1 房间、400 link、100 warmup、500 采样 tick、3 次重复，前后臂序交替。采集期间没有并行运行构建、测试或兼容套件；全部状态与链位计数门禁通过。旧端是本片开始前已完成转换边界修复的 release 二进制，SHA-256 为 `389772c65c549c51c0f8392e68b97e29ac0d45ad2c51adf907787f93b1603463`；两端指纹见机器报告。

下表是每对 after/before 比值的中位数，不能与独立两端中位数的比值混用。

| 模式 | P50 | P99 | 进程 CPU/tick |
|---|---:|---:|---:|
| native | 1.01377 | 1.02642 | 1.01412 |
| 空 Mod | 1.01024 | 1.03182 | 1.00122 |
| 完整链 | 0.99983 | 0.76772 | 0.99194 |

完整链 P50 几乎不变，CPU 约下降 0.81%；本片没有性能优化目标，不据短采样作优化归因。native 的 P50/CPU 三对均偏高（约 1.38%/1.41%），需后续定位，不能自动归为噪声或声称零回归。完整链旧端的 P99 有尖峰，短采样下降不能替代之前尾延迟问题的验收。这组固定夹具测的是 link 结算，未测新自有动作局部恢复的成本，更不代表生产端到端负载。
