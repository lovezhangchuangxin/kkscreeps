## 实现与复审

- 新增对象 tick 槽 `builtin:creep.receiveDamage`，内建槽增至 14 个；默认 TOUGH 先生成数值候选，native 中心保持该值，成功链选值后不再次减伤。未扩展路径不进入 JS。
- `ctx.incoming` 允许多次读写以组合 before/wrap/replace/after。目标字段和战斗查询为脱离副本，世界/队列仍由既有最终应用器写入；攻击阶段的伤害 consumed 约束没有扩大到受击数值候选。
- 固定输入区分 raw/default/pendingHeal；来源从当前房间正值攻击事件提取，最多 256 项，数量与未归因量按全部来源计算。来源对象查询为当前候选，不承诺历史快照。只在 Hosted 路径扫描事件，没有新增持久化账本。
- Number 安全整数域由 SDK、原始 op 和引擎多层检查；过大的输入直接拒绝，原生 i64 队列保留。最终伤害/治疗使用 i128 中间算术，避免极大值相抵或纯治疗溢出。
- 五位置正常拒绝丢弃数值/state 并回退默认 TOUGH，保留此前攻击/治疗/移动；免疫显式选择零值。非法能力和本次调用的故障不能用 catch + decline 发布；字段副本修改在成功写回时拒绝。
- namespace state 在整链成功后移交候选，晚期写回失败沿玩家缓存与新 realm 重算；坏 replace 停用后 native 回退与健康钩子组合，护盾消耗恰一次。真实进程冷启动不依赖 VM 模块全局。
- 两个独立包仅通过公共 SDK 实现活跃 TOUGH 护甲与按目标 ID 的可恢复护盾；四种内容选择的 PlanHash 各异，双投影结果一致。Git 暂存导出验证新增夹具完整入库，没有依赖被忽略的本地文件。
