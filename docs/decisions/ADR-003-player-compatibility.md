# ADR-003 玩家侧体验零差异是最高优先级约束

- **日期**：2026-09-27
- **状态**：已接受

## 背景

本项目的全部性能优化都发生在玩家看不到的内部（序列化格式、存储引擎、进程拓扑、调度方式）。但玩家社区积累了十年的存量脚本和对官方行为的依赖（包括一些官方自己都没写进文档的行为），是本项目不能破坏的资产。

## 决策

内部可以任意优化，但**玩家侧体验必须与官方一致：游戏脚本 API 零变动、零差异**。这条红线的优先级高于一切性能优化。具体细则：

1. **完全 1:1 复刻的部分**：全部 API 面（约 340+ 方法/属性、443 个全局常量）、游戏循环语义（指令延迟结算、冲突动作优先级、被覆盖动作仍返回成功码）、CPU 经济（预算桶公式、每条指令 0.2 计费、超时惩罚）、存档语义（2MB 上限、惰性解析）、CommonJS 模块系统、lodash 3.10.1；
2. **寻路结果逐点一致**：通过 FFI 直接复用官方的 C++ 寻路源码，不自己实现（等价但路径选择不同的算法会造成玩家可观察的差异）；
3. **附加能力默认关闭**：任何超出官方的功能（比如 ESM 模块入口、测试辅助全局对象）做成显式开关，默认关闭，严格模式下零差异；
4. **计费口径一致**：存档解析在官方是按实际耗时计入玩家 CPU 的；我们增量化后实际耗时趋近于零，但计费仍按"官方等价工作量"虚拟收取——玩家付的账不变，省下的是服务器自己的开销；
5. **官方 bug 的处理**：行为测试套件（screeps-ok）覆盖到的官方行为全部复刻；没覆盖到的官方 bug，若被证明有玩家依赖，逐例登记后复刻。

## 验收关卡（不做完不算兼容）

- screeps-ok 行为测试（2897 个以官方为基准的用例）进 CI 持续跑（见 [ADR-006](ADR-006-screeps-ok-ci.md)）；
- 真实开源机器人代码（社区主流 bot）在本地沙箱原样可跑；
- 官方客户端/渲染器可正常连接游玩。
