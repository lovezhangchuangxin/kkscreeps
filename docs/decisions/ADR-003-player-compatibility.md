# ADR-003 默认玩家行为兼容优先于性能优化

- **日期**：2026-09-27
- **状态**：已接受

## 背景

玩家脚本依赖官方 API、指令时序、对象生命周期和计费规则，其中还包括未在文档中完整说明的行为。改变内部表示、存储或调度时，需要保护这些可观察的行为，避免已有脚本因重构而失效。

## 决策

默认 vanilla 配置保持官方玩家 API 和游戏行为，兼容性要求优先于性能优化。“零差异”是验收目标，不表示当前实现已达到完整兼容。

服主显式启用的玩法 Mod 可以改变规则，须发布能力与内容版本。这一范围由 [ADR-007](ADR-007-mod-system.md) 和 [ADR-014](ADR-014-contribution-plane.md)明确；默认玩法与 Mod 分别验收。

### 1. 保持玩家可观察的契约

核对 API 名称、参数、返回值、错误与属性，以及指令延迟、覆盖、竞争和最终状态。Memory、segments、CommonJS 与 lodash 3.10.1 等运行环境也属于契约，不能只比较世界快照。

CPU 经济包括预算桶、停跑、超时惩罚和附加指令费用。费用须按动作类型及收集方式核对；免费动作、同名覆盖、数组累计和撤销的处理不同，不能概括为“每调用一条指令收取 0.2”。字符串限制须说明字符计数单位和写入路径，不能把“2MB”当作所有 Memory 写入的统一字节保证。

覆盖范围、来源与当前差异见[兼容性要求](../designs/compatibility.md)。API 数量以采用版本的盘点为准，不在本决策中固定旧统计。

### 2. 寻路结果逐点一致

优先通过原生接口复用官方 C++ 寻路实现，不另写一个仅保证同样最优的替代算法。目标归一、矩阵、回调时序、异常、预算和同成本路径选择都须对照验证；复用搜索源码本身不足以证明玩家接口兼容。

当前原生接口与玩家接线的区别见[寻路回调设计](../designs/pathfinder-callback.md)。

### 3. 附加能力默认关闭

ESM、测试辅助全局和其他超出官方的能力通过显式开关启用，不能计作默认兼容能力。模拟模式中的辅助入口与正常服务器的玩家环境分别验证。

### 4. 保持优化后的计费政策

Memory 等操作减少实际成本后，仍以官方等价工作量保持其经济语义，虚拟计费是已接受的政策方向。具体模型须定义公式、基准、误差和适用范围，区分玩家账单与服务器实际资源成本。

当前尚无完整、已校准的虚拟计费模型，不能声称已经做到“玩家付的账不变”。实际计时与写回机制见[沙箱说明](../architecture/sandbox.md)。

### 5. 官方 bug 与测试期望

保留套件覆盖的官方行为；未覆盖但有证据表明玩家依赖的官方 bug，逐项登记依据与影响。若套件期望和锁定版本源码或上游实跑冲突，先核实版本、适配器与复现场景，不能仅为通过测试实现相反行为。

## 验收

完整兼容需要分别提供以下证据：

- 锁定版本的 screeps-ok 全量报告及逐用例回归检查，规则见 [ADR-006](ADR-006-screeps-ok-ci.md)与[验收工具](../../compat/README.md)。
- 社区真实 bot 在实际推进结算的世界中运行，并验证游戏进展；环境加载测试不能替代玩法验收。
- 官方客户端可连接游玩，自建客户端按协议与功能另行验收。

测试通过数下限是回归保护，不是全部 API 正确的证明。性能结果还须确认双方做了可比的工作，不能通过减少预算、跳过功能或弱化兼容要求取得。
