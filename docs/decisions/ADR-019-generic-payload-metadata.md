# ADR-019：Generic 不可变载荷与紧凑读取元数据

- 日期：2026-10-10
- 状态：接受；已实现，性能对照与完整门禁结果以[接手台账](../plans/mod-next-batches.md)及[研究记录](../research/11-mature-performance-optimization.md)为准。

## 问题与证据

固定 50 玩家×6 成熟房中有 39600 个初始 Generic 对象。实际 tick 采样发现，视野归属、NPC 分类、建筑配额与对象 tick 分派为了少数字段反复构造完整 JSON 树；共享块编码也有较大成本。候选深复制在该窗口的采样占比小于这些重复解析，优先处理跨消费者的载荷读取成本，不同时重构整个候选或调度机制。

## 决策

`GenericObj.data` 使用 `GenericData`：不可变原始 JSON 文本与一个惰性紧凑元数据缓存放入同一 Arc 载荷。候选克隆共享该载荷；所有写点通过 `String::into()` 构造新载荷并整体替换 `data`，没有可原位修改文本的接口。旧世界与链快照保留旧载荷，候选内读取新载荷，不需要独立 revision 或手动清缓存。

缓存只保存 `type`、`structureType`、`owner`、`observeRoom`、结构类型键是否存在，以及衰减读取门的 `nextDecayTime`/`hitsMax`。首次读取沿用 `serde_json::Value` 的解析与数值读取语义，然后释放完整树；无效 JSON/非对象缓存为无元数据。转义键、重复键的最后值、null/错误类型和移动类型的键存在优先级保持原行为。缓存不含权限决策、规则默认值或目录派生物，不随 Mod 计划冻结而改变。

视野、归属、NPC 分类、配额、类型分派与移动类型读取使用该缓存；真正操作动态字段、库存、伤害或编码对象时仍解析原始完整载荷。衰减只有在到期或耐久上限需要同步时构造可写树，其他动态字段原样保留。

## 保存与扩展边界

二进制 data 字段继续编码为 u32 长度加原始 UTF-8 文本，与 String 编码逐字节一致；变体 tag 和版本不变。元数据是可重建的派生物，不进入房间快照、完整检查点或输入日志。解码创建新载荷，首次使用重建缓存；不需要持久格式迁移。

Generic 的动态字段、资源键与 Mod 建筑依然完整保存在原始文本中；独立 Mod 对象、扩展字段目录、JS SDK 和权限裁切没有收缩。所有 Generic 创建/写回入口都必须构造新的不可变载荷；跨房迁移与失败重试使用现有候选发布规则。

## 取舍与后续

选择 Arc 是为了共享不可变载荷并保留跨线程读能力；当前房间结算仍串行，不能据此宣称并行已实现。紧凑缓存增加少量常驻字段及引用计数开销，端到端 CPU/RSS 对照决定是否保留该方案。它不会消除投影中完整动态记录的解析和编码，也不等于世界候选写时复制已经实现。

没有选择全量 JSON 字符串与 Value 树双存：会使每个对象常驻成本显著增长。没有直接新增 rampart 等多种枚举：先验证跨消费者重复解析收益，避免为类型化一次改动投影、规则、Mod 写面与持久版本。后续原生热类型仍可独立评估，不禁止通用动态路径。

验收包含缓存解析边界、旧载荷隔离、撤销与提交、observer/归属刷新、衰减时钟与未知动态字段、原 String 字节锁、检查点恢复、Mod 双通道与兼容性棘轮。性能仍只采集用户指定的 50×6 成熟房场景。

2026-10-10 保留核验：同负载旧→新→新→旧短窗，两对相邻整体 wall P50 均约下降 17%、CPU 约下降 3%/6%，据此保留；峰值 RSS 未证明稳定下降、xxscreeps 正式目标仍未达成。范围与全部不利样本见[ABBA 记录](../research/11-mature-performance-optimization.md#2026-10-10-补记端到端-abba-核验与保留决定)。
