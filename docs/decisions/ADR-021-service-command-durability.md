# ADR-021：周期检查点上的命令确认屏障与恢复下限

- 日期：2026-10-12
- 状态：拟议，作为[服务三批方案](../plans/service-playable-batches.md)的实施选择；尚未实装或验证。
- 关系：细化 ADR-014 的候选输出、ADR-017 的后台域与 ADR-018 的周期检查点生产姿态，不将逐拍输入日志改为生产默认。

## 问题

普通游戏进度允许回到最近周期检查点；外部命令一旦被确认完成，或 outbox 已在接收端施加副作用，就不能假定同样的回滚仍安全。仅把世界、消费游标、outbox 一起保存尚不够：若后续恢复自动跳过损坏的最新检查点，可能回到确认之前，重复命令或让已经发出的效果失去来源。

输入日志 v2 只有 Memory 摘要，不能用结算回放恢复完整玩家状态。依赖重新执行玩家代码也不能推导成完全相同的外部效果。需要分别定义接收、游戏应用、耐久完成与外部投递。

## 拟议选择

1. 普通 tick 保持周期完整检查点；实时房间帧/普通 console 可在内存提交后发布，重启由新 runEpoch 明示回滚并全量重同步。
2. 有界 inbox 将命令身份、顺序与原始载荷耐久保存后才确认 received。received 承诺可找回，不承诺已生效；它与逐拍游戏输入审计日志独立。
3. 世界/Memory、命令消费水位、结果、代码版本与待输出形成同版服务提交。最终 completed/rejected 和持久输出投递都等待完整检查点的耐久发布；低频命令触发额外保存，可合并同一批，但不强制普通 tick 每拍写盘。
4. 在外部最终确认或发送之前，原子耐久发布独立的 effects 最新状态：恢复锚点/屏障身份/命令水位及各 sink 投递确认。检查点先同步，effects 后同步，两步之间不发生不可撤销对外动作；第二步失败进入耐久故障，不发最终成功。
5. 恢复不得低于 effects 的下限。允许选锚点本身或携带同屏障身份且水位足够的后继版本；锚点固定保留，更高锚点确认后才释放。下限文件不明、锚点损坏且无合格后继时停服，不能把退到更早状态包装成正常恢复。
6. outbox 稳定 ID、接收端幂等/去重和持久 ack 分别实现。发送后 ack 保存前的崩溃会重发同 ID，不承诺非幂等接收端的 exactly-once。ack 最新值独立于可回滚检查点，恢复过滤已投递条目；fence 与 ack 更新由同一所有者串行发布。

## 保证与代价

普通游戏进度仍可能丢失最近保存后的窗口；已经耐久确认的命令效果与已授权投递的输出不允许自动回滚。未耐久的玩家表达式可能在重启后重新执行，JavaScript 实际执行一次不是保证。成功条件是对外确认、恢复水位与接收端副作用语义一致。

额外成本随控制命令/副作用频率增长：完整检查点、effects 同步与暂停时间；因此 inbox/outbox/单拍命令数量受限，实时数据不进耐久 outbox。先用 native 文件与模拟 sink 证明协议，不引入数据库、消息系统或全量事件溯源。文件同步失败、物理介质丢失和人工灾难回滚不能被上述协议消除；人工旧状态恢复须建立新分支并核对外部效果。

## 未采用的方向

| 方向 | 未采用原因 |
|---|---|
| 受理或内存应用后就确认已生效 | 崩溃可能丢失被确认的效果，界面和客户端会误判 |
| 发送 outbox 后再补检查点 | 外部已经施加副作用，恢复可能完全缺少该输出身份 |
| 确认耐久后仍任意退到旧检查点 | 可能跨越已经观察的命令与副作用，造成重复或不一致 |
| 每拍完整检查点或全量 Memory 日志 | 常态写放大与空间成本过高，违反当前轻量周期持久化姿态 |
| 只存最新代码文件，启动时覆盖游戏检查点 | 代码版本、Memory、命令游标来自不同时刻，破坏一致恢复 |
| 宣称无条件 exactly-once | 发送结果未知时只能重试或放弃；接收端去重与业务确认不可省略 |

状态字段、格式迁移、命令流去重、发布顺序与崩溃矩阵统一见[服务三批方案](../plans/service-playable-batches.md#4-s2耐久命令确认与-outbox)。实现证据补齐前，本 ADR 仍为拟议；不能由文档状态推导已获得上述保证。
