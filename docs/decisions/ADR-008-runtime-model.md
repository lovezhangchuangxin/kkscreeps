# ADR-008 执行模型与资源管理

- **日期**：2026-09-27
- **状态**：已接受；协调与提交边界随后由 ADR-013/014 细化

## 背景

核心架构确定后，需要明确玩家执行、房间结算、实例回收、失败处理、速率控制与工具接口。以下八项是采用的设计方向，具体实装范围须结合后续决策和架构文档阅读。

## 决策

### 1. 分开管理玩家执行、房间活动与实例寿命

| 问题 | 要求与边界 |
|---|---|
| 玩家是否执行 | 按默认玩家契约与预算规则决定；不能仅因玩家没有房间对象就跳过，因为代码仍可能操作 Memory 或账号级 API |
| 房间是否结算 | 按房间活动、到期状态与跨房输入判断；休眠和唤醒补算须与逐 tick 参考执行对照 |
| 实例是否保留 | 每玩家一个专属线程和 V8 实例，未收到命令时等待；回收策略须明确触发条件及全局状态丢失行为 |

目标服务器每 tick 按上游队列规则覆盖应执行的注册玩家，再按预算等规则决定实际执行；当前嵌入接口只运行调用方请求的玩家，尚不是完整服务器队列。

原方案参考上游约三分钟空闲回收的策略，当前 `evict_idle(duration)` 由调用方提供时长，没有自动三分钟调度器。闲置按最近一次命令发送记录，不等同于玩家没有游戏对象或动作。

销毁 V8 会丢失玩家持久全局变量，因此实例回收不能笼统描述为“玩家不可感知”。线程栈、V8 堆、共享载荷与调度开销分别计量，实例数量上限由真实负载验证，不能由单实例实验断言几百个线程无压力。具体接口见[沙箱说明](../architecture/sandbox.md)。

### 2. 同步协调、数据并行与后台 I/O

tick 协调使用同步流程，玩家 V8 在线程内执行；就绪房间计划通过 Rayon 线程池并行处理。网络与检查点 I/O 放在后台执行域，避免把外部等待混入结算顺序。

当前嵌入入口仍逐玩家等待结果，房间结算也串行执行。每个玩家有独立线程不等于已经并发派发。并行化须按 [tick 契约](../architecture/tick-contract.md)定义依赖、候选与合并，后台任务只能消费已提交版本。

### 3. 结算失败保留已提交状态

结算在候选状态中进行，失败时丢弃未发布结果并保留旧版本。后续决策将最初的房间回退要求扩展为整轮协调：不能发布成功房间后再单独重试失败房间，跨房与全局状态也须保持一致。

当前房间、玩家结算状态及市场使用候选；引擎结算段返回错误后进入 `NeedsRecovery`。协调器缓存结算失败轮的玩家执行结果与 TickInput，重试复用缓存，避免再次运行玩家代码。V8 全局不随世界回退；世界发布后的 CPU 提交通信失败也不具备跨线程原子回滚。

工作副本、缓存与验证都有资源成本。双缓冲本身不能保证跨房、跨线程、外部副作用或磁盘事务；完整故障边界见 [tick 契约](../architecture/tick-contract.md)及 [ADR-013](ADR-013-architecture-review-coordinator.md)。

### 4. 负载驱动的 tick 速率与保护上限

目标服务器允许 tick 时长随负载增长，并提供速率配置与保护上限。原方案参考 xxscreeps 的 abandon timeout，在严重拖延时停止最慢玩家以保护整体推进。

这种处置可能改变玩家执行结果，须定义触发条件、计费、已产生指令及兼容模式，不能自动视为默认玩法等价。当前嵌入引擎由调用方请求推进，没有完整服务器节拍与最慢玩家处置调度器。

### 5. 保留可替换的沙箱执行接口

采用执行接口是为了隔离协调逻辑并支持固定结果的测试实现，不是为了增加另一种 JS 引擎。真实与测试执行器应进入同一结算通路；依赖方向由运行协调层连接玩家沙箱与引擎，kk-engine 不依赖 deno_core。

当前接口与模块边界见[总体架构](../architecture/overall.md)，玩家运行结果分类见 [ADR-013](ADR-013-architecture-review-coordinator.md)。

### 6. 世界生成分阶段实现

M1 从预生成地形与场景摆放起步，完整官方地形生成放在 M4。配置导入和场景构造不等同于已经移植官方生成算法，具体验收见[路线图](../roadmap.md)。

### 7. 存储在真实负载基准后选型

M1 不接游戏数据库，M2 比较 redb 与 libmdbx 后再决定。已有微基准不替代真实检查点、恢复、平台支持和持久性验证；当前两者均未接入游戏持久化，见[存储架构](../architecture/storage.md)。

### 8. 适配器与本地模拟共用嵌入接口

screeps-ok 适配器通过创建世界、注入代码、运行玩家和读取状态来调用引擎。这些能力同样供本地模拟使用，避免另建一套结算实现。

接口共用不意味着完整开发套件已经交付。当前调用方式见[验收工具](../../compat/README.md)，目标模拟、测试与调试流程见[开发套件设计](../designs/dev-kit.md)。
