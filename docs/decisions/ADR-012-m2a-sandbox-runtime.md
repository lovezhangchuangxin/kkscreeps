# ADR-012 玩家运行时与 JavaScript API 层

- **日期**：2026-09-29
- **状态**：已接受；运行协调与投影演进见 ADR-013/014

## 背景

M2A 接入真实玩家沙箱和核心 API，并达到 2A 的阶段门槛。本记录确认 API、指令与数据接口的职责划分；实现过程与历史数字保留在方案和报告中。

## 决策

### 1. 兼容与隔离约束

默认玩家行为满足 [ADR-003](ADR-003-player-compatibility.md)，玩家不能访问内部控制面或跨越隔离边界。内部表示、传输、存储与调度可以优化，但须验证可观察行为与安全边界。

这两项是开发要求，不是一次评审即可证明的完整保证。加载期捕获函数可减少玩家原型修改对内部调用的影响，仍须核对属性、宿主入口和原生执行路径。

### 2. 玩家 API 在 prelude 中对照实现

玩家对象、参数处理与 JavaScript 属性语义在 `kk-runner/src/prelude/game/` 实现，Rust 宿主提供计算、诊断和执行控制等原语。这样便于对照 instanceof、lodash 谓词、Store 下标访问与原型修改等玩家行为。

对象包装保存 ID，许多 getter 通过 `rawData(id)` 查询当前投影；跨 tick 的旧引用和对象消亡按具体 getter 验证。并非所有字段都是同一种惰性查询，不能从包装机制推导全部引用行为已经一致。

### 3. 指令经四个步骤进入结算

| 步骤 | 职责 |
|---|---|
| 玩家预检查 | 读取当前投影，检查参数、归属、距离等条件 |
| 闭包收集 | 按对象或动作收集、覆盖、累计与撤销指令，维护玩家可见附加费用 |
| 执行结束导出 | 经 JSON 信封导出运行结果与写回候选 |
| 宿主清洗 | 校验字段、绑定玩家身份、生成 IntentBatch 并进入结算 |

沙箱可见费用与宿主按最终清单计费分别核对；免费动作、覆盖、累计和撤销不能概括为每次调用统一收费。普通 loop 异常被包装器捕获后，若写回成功，此前收集的指令仍可导出；硬中断或写回失败时不导出指令。丢弃指令不等于取消计费：普通写回错误仍生成费用候选，预算中断与主动 halt 的账单规则不同。表达式错误分类与 loop 异常分别核对，不能把所有失败都当作同一结局，见[沙箱说明](../architecture/sandbox.md)。

### 4. 数据接口分步演进

M2A 使用玩家 JSON 投影，在扩大 API 前先建立世界来源接口、版本化地形缓存与房间版本句柄。ADR-013 明确这一顺序，ADR-014 进一步要求共享二进制、私有视图、惰性包装和扩展字段目录整体设计、分步接入。

当前 RoomVersionHandle 仅记录房间名、世界时间和内容版本，不持有房间数据，也不固定旧版本的存活期。WorldSource 与版本缓存不等于玩家已通过共享二进制读取整个世界，生命周期与权限仍按[快照契约](../architecture/snapshot-contract.md)验证。

### 5. 查询投影在 Rust 中维护

嵌入查询的契约形状由 Rust 投影生成，不在 TS 适配器额外转换出另一套定义。管理查询的 snapshot 与玩家读取的 world_json 是不同出口，字段、缺省值和权限分别核对；不能把二者都描述为 world_json。

### 6. 分别验收行为与 bot 环境

screeps-ok 检查通过数下限与逐用例回归，豁免须明确归因。TooAngel、Overmind 与合成 WASM 夹具检查环境回归；固定世界运行不能代替实际游戏进展验证。

2A 的门槛为至少 40%，阶段已达成。2B 的完整玩法、存储和通过率门槛仍按[路线图](../roadmap.md)验收（2026-10-09 起路线图把 95% 调整为中间检查点、99% 为后续覆盖目标，最终收口以路线图现行版本为准），不能把 2A 完成写作全部 API 完整兼容。

### 7. 建立性能观测入口

EmbedEngine 记录投影、玩家运行、结算和整轮墙钟耗时，perf-probe 提供可复跑夹具。正式三方对照仍须按[性能验收方案](../architecture/performance-acceptance.md)固定工作量、核对实际动作与状态，并保留原始数据。

初期 perf-probe 的动作未真正进入有效范围，后来在双房验证中修正；[A6 报告](../../compat/reports/perf-a6.md)属于早期观测记录，不能直接作为当前有效负载的收益证明。
