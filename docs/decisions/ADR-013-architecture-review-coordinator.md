# ADR-013 运行协调、提交与实例生命周期

- **日期**：2026-09-29
- **状态**：已接受；全域候选与并发实施随后由 ADR-014 细化

## 背景

架构复审复现了部分提交问题：玩家 Memory 与 CPU 桶提前更新，而世界结算失败后仍保持旧时间。另一项问题是把单线程的 V8 Enter/Exit 栈约束泛化成所有玩家之间的全局逆序销毁，限制了闲置实例回收。

复审还要求明确宿主控制入口、结算时间输入和投影演进顺序。原始探针与争议核实见[架构复审笔记](../research/notes/architecture-review-2026-09.md)，其中路径与代码形态属于当时版本。

## 决策

### 1. 引入运行协调层

玩家派发、结果收集、失败分类、重试和提交从 kk-engine 移到协调层，以 kk-runtime 为正式落点。玩家执行只产生 RunResult 候选，包含指令、Memory、CPU、运行结局与控制台；真实和测试执行器实现同一接口，kk-engine 不依赖 V8 或 deno_core。

目标是世界与玩家持久状态在统一提交点发布。有定义的玩家异常与宿主、线程通信故障分别分类；失败重试不能泄漏提前写入的玩家状态，也不能重新执行已运行的同轮玩家代码。

### 2. 先建立世界来源与版本接口

API 大规模扩展前建立 WorldSource、地形版本缓存与不可变房间版本句柄，减少读取层对旧传输表示的直接依赖。具体布局、生命周期和收益按端到端实验验收。

ADR-014 随后要求整体设计共享投影协议，分步实现；这细化了本条“先立接口、再验证布局”的顺序，不能解读为先重复优化 JSON、以后另改一套协议。

### 3. 按线程管理 V8 生命周期

Enter/Exit 栈约束属于线程局部；不同玩家线程没有全局逆序销毁要求。闲置回收支持任意符合条件的实例，退出时仍可按创建逆序清理，并保留跨线程乱序销毁验证。

一实例一线程减少同线程多实例的栈管理问题，仍须在所属线程完成清理并等待线程退出，不能据此忽略资源回收错误。

### 4. 宿主控制句柄私有化

移除玩家全局中的内部控制入口，Rust 持有 beginTick、endTick、runLoop 等函数的私有 V8 句柄。段间装配上下文在加载后删除，运行时使用已捕获闭包，避免玩家清除指令、替换内部世界或篡改生命周期调用。

这缩小了玩家可达控制面，不证明全部沙箱逃逸风险已消除；默认全局、原型修改与原生调用仍须分别检查。

### 5. 显式记录结算输入

墙钟等输入通过 TickInput 传入，首次执行采样，重试和重放使用记录值。签名仍使用墙钟时间，但同轮共用采样值与上游逐动作 Date.now 存在可观察边界，见[兼容性要求](../designs/compatibility.md)。

确定性针对已提交状态、指令和显式输入的结算，不保证重新执行任意玩家 JS 得到相同结果。

### 6. 实施顺序与 CPU 时钟

完成 2A 后实施运行协调与正确性修复，再建立来源和版本接口、验证双房双玩家场景，随后扩大 API。结构整理、前置接口和双房验证分别保存阶段记录，不把原批次安排当作当前待办。

线程 CPU 计费不得晚于 M3 多用户承载；ADR-014 将其与 RunJob 注入/执行合并、有界并发安排为并行实施方向。当前 getUsed 和执行预算仍使用墙钟，切换须核对抢占、暂停与附加费用，不能仅称为无影响地更换时钟。

## 当前实现与保证边界

kk-runtime 已连接真实沙箱与结算，宿主控制句柄已私有化，WorldSource、版本标识和地形缓存已有实现。当前 RoomVersionHandle 不持有房间数据，不提供旧版本存活保证。失败轮保留玩家结果与 TickInput；错误重试请求不清除缓存，停跑回充也作为候选处理。

世界结算在候选中进行，失败保留旧状态；市场也已纳入候选。V8 全局不会回退，世界发布后的 CPU 提交通信失败不回滚世界，执行阶段基础设施故障、panic 和磁盘恢复没有完整原子保证。详细范围以 [tick 契约](../architecture/tick-contract.md)为准，不能把阶段完成写成完整事务已经实现。
