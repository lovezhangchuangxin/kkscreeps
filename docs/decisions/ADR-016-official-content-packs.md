# ADR-016 官方玩法以可选内容包交付并验证公共 SDK

- **日期**：2026-10-05
- **状态**：已接受；内容选择装配与官方玩法迁移尚未实现
- **前置**：[ADR-007](ADR-007-mod-system.md)、[ADR-014](ADR-014-contribution-plane.md)、[ADR-015](ADR-015-mod-chain-execution.md)

## 背景

用户确认希望开发者通过独立 JS Mod 轻松创造完整玩法，并进一步要求参考 xxscreeps：项目自身的一部分游戏内容通过 Mod 提供，让服主选择内容，也用真实官方玩法验证 Mod 系统。

本地 xxscreeps `5ff0d1a6` 的 `packages/xxscreeps/mods/classic/index.ts` 聚合内容包；logistics、chemistry、combat 等包分别声明依赖和 game/processor/schema 等贡献。当前本项目虽有公共贡献契约，仍在宿主冻结时固定加入 builtin 贡献，并直接执行许多原生规则；内容可选择性尚未形成完整通路。

## 决定

### 1. 分离基础宿主、游戏内容与玩法预设

基础宿主负责 VM、候选事务、ID/索引、编码、存储和通用领域操作。官方玩法按有版本与依赖声明的独立内容包交付；玩法预设选择并配置这些包，包含完整默认玩法、精简玩法和自定义组合。

选择内容须同时影响对象/资源目录、规则与处理器、玩家 API/常量、服务及客户端贡献。未选内容不能经隐藏的原生结算继续生效；相互依赖的内容不能任意关闭。

### 2. 官方内容实际使用公共 JS SDK

一部分官方游戏内容直接以独立 JS 包实现，并逐步增加覆盖。官方包与第三方包使用相同的注册、事务、预算、权限和恢复契约；不能以官方身份绕过校验或依赖私有 Rust 业务入口。正式内容包与开发者模板/样例分别维护，前者纳入常规玩法与组合测试。

Rust 保留默认实现及通用加速能力。加速接口应按相同权限和数据契约提供给其他包；具体默认算法仍须能替换。把专用原生玩法套一个 JS 注册壳不能单独证明作者可用 JS 创造完整玩法，也不能作为官方 JS 内容验收。

### 3. 默认兼容保持，选择与身份可追溯

完整默认预设保持 [ADR-003](ADR-003-player-compatibility.md) 的玩家契约；精简和自定义配置发布实际能力与内容身份。预设展开结果、实际包字节与配置、贡献计划和执行策略共同标识世界。

“零第三方 Mod”允许包含官方 JS 内容，因而不保证零 JS 调用。Native 直调保证仅适用于中心实际为 Rust native 且没有 JS 扩展的入口。默认预设回归、原生与 JS 等价实现对照、第三方增量开销分别测量，不复用旧“无 Mod”名称宣称新配置零开销。

### 4. 内容变更与故障停用分别处理

新建世界按预设展开依赖、校验冲突后冻结；已有世界移除或升级内容须检查对象、字段、库存、玩家状态与依赖，明确迁移、导出或删除策略，在安全边界整体发布，失败保留旧世界与计划。

当前运行时故障停用保留 schema、有效规则和数据，只屏蔽处理器；它不等价于卸载内容。故障策略不能自动删除世界数据。实施契约见[内容包设计](../designs/content-packs.md)。

## 实施与验收

复用已有 Mod 宿主和冻结计划，先以自有对象生命周期及生产建筑做真实官方 JS 内容包，再逐族迁移默认内容。未迁移的固定内建依赖登记为过渡范围；每个已迁移包验证不选择时无残留行为，第三方可通过公共 SDK 实现同类内容。

包依赖/组合、缺省不启用、默认兼容、正常拒绝、异常/超时、保存恢复和版本迁移分别验收。完整保存恢复与客户端能力随对应阶段实现，未通过前不计作已交付。切片见[完整玩法计划](../plans/mod-complete-gameplay.md)。

## 与既有决策的关系

ADR-007 的 JS 作者目标、ADR-014 的统一贡献契约及 ADR-015 的链执行机制保留。本决策细化内容交付与作者验收，并调整“全部默认玩法固定由 Rust 实现”的语言分工：部分官方内容由 JS 实现，Rust 基础宿主和可选 native 实现保留。它不要求一次性重写所有默认玩法。
