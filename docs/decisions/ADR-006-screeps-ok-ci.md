# ADR-006 用 screeps-ok 持续检查行为兼容

- **日期**：2026-09-27
- **状态**：已接受

## 背景

默认玩家行为必须与官方一致，但 API、边界条件与未文档化行为无法仅靠人工对照保证。项目需要可重复执行的行为测试，并在每次修改后检查回归。

## 决策

接入 screeps-ok，以锁定版本的官方行为为对照。从 M1 起在 CI 持续执行完整套件，已经通过的行为不能无说明地回退。失败须定位到源码、适配器或已登记差异，修复新增回归；完整兼容仍以 [ADR-003](ADR-003-player-compatibility.md) 的独立验收要求为准。

上游版本由[准备脚本](../../scripts/setup-screeps-ok.sh)锁定，不把旧用例数量作为长期常量。变更上游、官方依赖或适配器时，重新核对基准和覆盖范围。

## 实施要求

1. 先独立复现上游基准，再依赖其结果；版本与报告应可追溯。
2. 适配器的玩家执行进入真实沙箱及结算，不用测试专用返回值替代游戏行为。
3. capability 如实声明可启用的测试组；true 不是该组全部通过，false 导致的跳过也不是兼容证明。
4. 对套件缺少的 CPU 预算、中断、halt、WASM 等关键行为另建测试与验收，不能从其他用例通过推导这些能力正确。
5. 失败预期、跳过与回归豁免分别登记，不以增加跳过范围提高兼容性声明。

## 当前回归检查

[CI 工作流](../../.github/workflows/ci.yml)构建 release 引擎与适配器后执行完整回归脚本。门禁检查报告更新时间、总用例数、通过数下限，并与 `HEAD~1` 入库报告逐用例比较；基线已通过用例不能失败、跳过或缺失，除非显式豁免。

上游套件尚有本项目未通过的用例，因此套件非零退出码不直接等于新增回归。`expected_failures` 不自动豁免回归；通过数下限不能替代逐用例检查。具体配置、基线限制与运行命令见[验收工具](../../compat/README.md)。

## 选择依据与限制

初期评估发现，套件包含真实官方引擎对照、精确断言和重要边界行为，值得采用；同时存在单维护者、适配器对 driver 内部实现耦合、关键行为覆盖不足等风险。采用后仍须锁版本、复现结果、核对断言与补充缺口，不能把套件当作完整官方规范。

详细规模、实验数字与当时的加固建议保存在[初期质量评估](../research/notes/screeps-ok-evaluation-2026-09-27.md)。这份记录是历史证据，不代表其中的补测已全部完成。
