# ADR-005 开发套件与服务器共用同一个引擎二进制

- **日期**：2026-09-27
- **状态**：已接受（方向确立，细节见设计文档）

## 背景

Screeps 玩家通常在本地写代码，上传到服务器测试。社区现有的本地测试方式二选一：

- **模拟对象（mock）**：在测试框架里伪造一套 `Game` 对象，速度快，但伪造的引擎不是真引擎——指令结算、冲突裁决、寻路行为都是假的，"本地测试通过、上服翻车"是常态；
- **本地私服**：行为真实，但要拉起官方那套多进程加中间件，一个 tick 一秒起步，跑一千个 tick 的集成测试要约 17 分钟。

"快"和"真实"不可兼得的根源是官方引擎本身就是重负载的多进程系统。

## 决策

提供本地开发套件（`kkscreeps sim` / `test` / `watch` / `deploy`），**模拟器就是服务器本身的同一个二进制**，以无网络、内存即存储的方式运行。能力包括：场景即代码（声明地形、初始单位、双机器人对战）、固定随机种子保证可复现、任意历史时刻的回放与断点续跑、每 tick 的 CPU 与预算桶报告、可选的实时观战页面。

测试辅助功能（沙箱内的 `test` 全局对象等）只在显式开启模拟模式时注入，正常服务器不存在——遵守 [ADR-003](ADR-003-player-compatibility.md) 的零差异红线。

## 理由

1. 单二进制、进程内运行使"快"（目标一千个 tick 秒级完成）与"真实"（同一引擎、同一沙箱、同一 API）第一次兼得；
2. 事件的完整记录（快照历史 + 指令日志）让"我的爬爬虫为什么往左走"这类问题可以直接取任意时刻的状态与指令来回答；
3. 同一份工具也是我们自己的开发回归工具（与 screeps-ok 互补：它管官方语义一致性，开发套件管真实场景行为）。
