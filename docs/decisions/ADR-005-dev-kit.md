# ADR-005 开发套件与服务器共用引擎二进制

- **日期**：2026-09-27
- **状态**：已接受

## 背景

模拟 Game 对象便于单元测试，却不能验证真实指令结算、冲突和生命周期。启动完整私服能运行真实规则，但依赖准备与长场景执行成本较高。项目需要一种直接复用服务器运行和结算机制的本地测试方式。

## 决策

提供 `kkscreeps sim / test / watch / deploy`，以同一引擎二进制支持服务器与本地模拟。模拟模式不依赖网络服务，世界使用内存存储；玩家 API、沙箱与结算规则共用生产实现。

目标能力包括场景初始化、双 bot 对战、断言、CPU 与预算桶报告，以及观战、历史回放和断点续跑。测试辅助全局仅在显式开启的模拟模式下注入，默认服务器遵守 [ADR-003](ADR-003-player-compatibility.md)。

## 理由与限制

共用实现可减少模拟器与服务器的规则分叉。开发套件检查真实场景进展，screeps-ok 检查官方行为对照，两者互补。

固定随机种子有助于复现，但任意玩家代码还可能依赖时间、随机数和持久全局；回放须记录所需输入、状态版本与恢复边界。快照和指令日志不能自动恢复完整 V8 堆。

固定场景中上千 tick 秒级完成是性能目标，须通过基准测量。当前命令入口和能力边界见[开发套件设计](../designs/dev-kit.md)，本决策不表示完整工具已交付。
