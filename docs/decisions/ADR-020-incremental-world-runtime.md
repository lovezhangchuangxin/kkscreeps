# ADR-020 以受控变化集、紧凑房间存储与依赖调度重构内核

- 日期：2026-10-11
- 状态：**拟议，作为本轮推荐方案；尚未实施或验证性能收益**
- 输入：用户要求性能全面超过 xxscreeps、内存更低、同等灵活的 JS Mod，允许必要的任意架构改造
- 关联：[目标架构](../architecture/performance-target.md)、[实施与验收](../plans/performance-rearchitecture.md)、[源码依据](../research/12-performance-critical-path-review.md)

## 背景

`525ec789` 前的共享块、常驻对象、row-dirty 与预编码显著降低开销，但保留了全量投影框架、JS 索引重建与全局玩家屏障。既有静默短窗 CPU 已接近平价，wall 仍落后；内存优势尚不能保证在继续增加缓存和真实 Mod 场景下保持。

继续只替换容器或增加线程不足以构成全面领先方案。全量克隆并行无收益的实验也不能支持一开始全面引入昂贵持久数据结构；需要从写入口、变化传播和可测的紧凑首域逐步建立新底座。

## 推荐决定

1. 保留 Rust/V8、分层单进程内核、玩家隔离、默认行为兼容和全域原子发布；不保留现有对象树/线格式/固定线程与三相屏障作为不可变约束。
2. 权威写入统一经过带 savepoint 的事务接口，产出保守完备 ChangeSet；视图、编码、索引与增量校验使用同一来源。
3. 以冻结 schema 编译动态布局，逐域迁移到房内紧凑页/槽；保留通用动态值和合法 Mod 回退。内存、权限投影和持久化格式分离。
4. 公开地图静态版本常驻，私有视图稀疏且按权限分组；字段/空间索引增量更新。先复用 full 编码，再引入有基线身份的 patch。
5. 拆玩家/ID/namespace 等共享状态的依赖，按房输入与语义依赖双就绪执行候选；保留原操作观察顺序、时间输入边界及扩展后的失败状态机，不能只靠末尾排序；最终统一提交。计算与预编码共享资源预算，队列与快照保留有界。
6. 任意合法 Mod 保留通用有序执行；首版所有 JS handler 保持有序 realm。局部 JS 是独立研究项，capability 不足以约束模块全局；必须有实际隔离/状态作用域机制才可开放，不能通过限制旧能力或复制可变模块全局获得并行。
7. 以完整默认 JS preset 和真实 Mod 对照验收，覆盖少核/多核、容量和服务范围；不以默认 native 路径替代扩展性能证明。

## 与既有 ADR 的关系

- ADR-001/002/003/007：语言、玩家 VM、默认兼容与 JS 作者目标保留。
- ADR-004/008/013：细化房间任务、状态所有权、统一发布与预算；目标执行顺序从全局三相演进为受依赖约束的任务流，现行失败语义不撤销。
- ADR-011/019：允许替换热路径 RoomObject/Generic 表示；ADR-019 的不可变文本仍是迁移期和动态回退方案，不要求把所有 JSON 保持为永久主存。
- ADR-014/015/016：保持贡献领域、整链 next/decline 观察顺序和真实官方 JS 内容；批量宿主调用与局部资格是新增优化机制，不把包分成“高性能但不能扩展”与“可扩展但不验收”。
- ADR-017/018：服务域与周期检查点权威保持；变化集不是新的事件溯源或耐久承诺。

以上是拟议演进关系，不把未完成机制改写为现状。若局部实验否定数据结构或调度实现，调整参数/实现并记录，不自动放弃三个目标或缩小 Mod 能力。

## 未采用为前置的替代路线

| 路线 | 本轮不作为前提的原因 |
|---|---|
| 推倒全部引擎重写 | 难以维持现有兼容与恢复证据，且无法逐片归因；采用可替换后端迁移 |
| 全项目统一 ECS | 尚无随机读写、动态字段和事务成本证据；只采用有收益的数据布局 |
| 每房一个 realm/线程/Actor | 固定开销和全局语义困难；房间是任务及存储单元，不是永久 OS 资源单位 |
| 任意 JS 自动并行或投机重跑 | 共享模块全局与外部副作用不能靠 Rust 候选回滚；采用有序通用路径 |
| 暴露权威 buffer 实现零拷贝 | 字段权限及可写 backing store 风险；授权派生视图有合法 copy fallback |
| 扩大堆或固定更多线程 | 没有减少工作量且可能破坏内存、少核容量目标 |

## 验收口径（2026-10-11 用户收敛）

三目标保留；性能验证锚定 50×6（B0）单一场景，开发与批次验证用分钟级短窗（进程内交替 A/B、多短窗取中枢），长窗只在最终验收出现；B1–B7 登记场景按需抽查或随部署里程碑，Linux 少核与 72h 长跑属部署线。不为验证等待数小时拖慢开发迭代。本文目标数值以[计划](../plans/performance-rearchitecture.md)收敛版为准。

## 代价与验证

最大成本是迁移规则写入口、动态布局与字段语义、Mod 实际消费者和确定性共享状态，而非更换 map。需要短期双后端诊断，但生产不永久双写。候选页、撤销日志与缓存元数据可能造成内存回退，必须在首个代表性类型族就否决不合算实现。

方案参数、性能数字、页大小、wire 形态和局部 VM 策略均由分阶段实测确认。最终最低门槛和主攻目标见实施计划；本 ADR 不证明已领先或保证任意 JS 工作负载的固定倍率。
