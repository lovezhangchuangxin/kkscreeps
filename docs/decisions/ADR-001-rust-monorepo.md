# ADR-001 用 Rust 与 Cargo workspace 重构服务端

- **日期**：2026-09-27
- **状态**：已接受

## 背景

官方服务端使用多个 Node.js 进程及数据库、缓存组件。调研发现，世界投影复制、进程间编码、查询扫描与存储写入是候选成本来源。部分结论来自源码机制，部分来自局部实验或负载估算，不能据此确定整个服务端的瓶颈比例。

项目需要在保持默认玩家行为的前提下，重新设计数据表示、调度与存储边界。原有游戏逻辑和数值表提供对照依据，移植仍须逐项验证生命周期、动作顺序和异常行为。

## 决策

在 kkscreeps 仓库使用 Rust 重构完整游戏服务端，以 Cargo workspace 组织引擎、世界、沙箱、存储与工具模块。Rust 工作区与前端的 pnpm 工作区共存于同一仓库。

## 理由与限制

Rust 可用类型化数据、连续布局和进程内接口减少重复转换，便于明确所有权与提交边界。独立模块也使结算测试不必启动完整服务端。

Rust 代码没有托管垃圾回收，但玩家 JavaScript 仍在 V8 中运行，仍有垃圾回收与宿主开销。xxscreeps 的重写经验支持重新设计架构的方向，其性能声明不能直接作为本项目收益证明。

数值表、规则和寻路实现可以作为移植输入；复用源码不自动保证玩家可见结果相同，资产与第三方代码还须核对各自许可。整体收益以[端到端性能验收](../architecture/performance-acceptance.md)为准。
