# ADR-001 用 Rust + cargo monorepo 从零重构服务端

- **日期**：2026-09-27
- **状态**：已接受

## 背景

官方服务端是 Node.js 多进程架构（5 个以上进程）加 MongoDB、Redis 两个中间件，私服版还带着 lokijs 单文件数据库。它的问题有据可查：

- 官方 2017 年博客承认"托管商提供的最强数据库服务器已 100% 饱和"，被迫把世界拆成分片；
- 私服官方推荐配置就要 2 核 2GB 内存，社区有过内存泄漏导致整机被吃满的记录，官方的缓解办法是让进程每小时重启一次；
- 官方服的 tick 时长 2~5 秒，慢的根本原因不在游戏逻辑，而在架构：进程间所有数据都转成 JSON 文本、每 tick 把整个房间的状态做全量快照、必须等所有玩家的代码跑完才开始处理任何房间。

同时，游戏逻辑本体其实很小：约 1.7 万行 JavaScript 加 1 千行 C++ 寻路。

## 决策

在 kkscreeps 仓库用 Rust 从零实现完整的游戏服务端，用 cargo workspace（monorepo 形态）组织代码。

## 理由

1. 最大的开销来自架构而非逻辑，重构架构就能拿到数量级收益——原引擎作者的 TypeScript 重写项目（xxscreeps）声称同样的世界快数个数量级（定性声明，另有一条社区实测记录，无正式基准），已是强有力的旁证；
2. Rust 在此之上再叠加三项收益：没有垃圾回收停顿、没有 Node.js 进程壳的开销、数据编码布局在编译期确定；
3. 工程规模可控（1.7 万行逻辑的对照移植），而且大量资产可以直接搬：数值表、指令校验规则、寻路 C++ 源码、玩家 API 层。
