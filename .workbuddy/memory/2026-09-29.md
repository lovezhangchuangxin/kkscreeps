# 2026-09-29

## kkscreeps 架构深评（应刻晴要求）

对项目做了全量架构调研与评审。事实基线：Rust 代码 31,195 行（crates/，不含 spikes）、测试 271 个、提交 114 个、文档 52 份 / 7,457 行；screeps-ok 通过率地板 1308/2914（44.9%）。

### 调研结论（关键事实，后续别再重新挖）

- **数据面与文档不符**：设计说"房间快照二进制 + 共享内存直读（约 2ns）"，实现是 `kk-runner/src/sandbox.rs:292` 每 tick `serde_json::to_string(world)` 拼进 `execute_script` 源码字面量，JS 侧 `game.js:402` `__jsonParse` 解析、`wrapObject` 重建全部游戏对象。即每玩家每 tick 一次全量世界 JSON 往返——正是 ADR-004 列为官方 1 号开销的"整包复制"的同性质形态。kk-schema 的二进制快照（room.rs:642）存在但只用于持久化/embed，未用于沙箱直读。
- **三个 crate 是"文档里的存在"**：kk-storage（3 行）、kk-backend（3 行）只有文档注释；kk-pathfinder 有 2,299 行完整实现 + 官方 C++ FFI + 黄金测试，但**零依赖者**（`grep -rn "kk-pathfinder" --include=Cargo.toml` 只有 workspace 声明）。
- **Sandbox trait 是装饰性的**：`impl Sandbox for` 全仓只有一处——`ScriptedSandbox`（测试假实现，kk-engine/src/sandbox.rs:39）。生产路径走 `EmbedEngine` + `tick_with_intents`，绕过 trait 直接 `use kk_runner::{EvalReport, PlayerThreads, SandboxConfig}`（kk-engine/src/embed.rs:15）。根因是 trait 签名定成 `WorldView<'a>{ world: &'a World }`（同步、借整个 typed world），真沙箱需要的是 JSON/二进制投影 —— 形状对不上，于是长出了第二条并行通道。kk-engine 的 Cargo.toml 仍依赖 kk-runner，故"单测不必拖 V8"是靠不用 trait 实现的，不是靠 trait。
- **无存储抽象**：kk-storage 无 trait，无任何 Cargo.toml 依赖它。Engine 直接内持 `World`（settle/mod.rs:529）。tick-contract 承诺的 RoomPatch / 临时 ID / 确定性合并均未实现。
- **并行未落地**：全仓无 rayon 依赖。房间按名字序串行（mod.rs:630-641）。两阶段提交已实现（全部房 clone 结算成功才统一写回，632-644），这部分做对了。
- **索引做了，但只覆盖坐标查询**：index.rs 每 tick 重建，`at(x,y)` 接口。按坐标的查询都走了索引；但"按 owner/类型找对象"仍是全表扫描，例如每 tick 计算 safemode_holders 要扫全世界的房间（mod.rs:609-619）。
- **二进制 schema 是手搓的**：`kk_schema!` 声明宏生成布局 + encode/decode，v1，`UPGRADE_CHAIN` 是空数组占位（room.rs:655）。调研笔记里反复引 rkyv（14x 对比）却没用它做快照——这个 plan→实现 的偏离没有 ADR 记录。最贵的一点：格式一旦冻结就是负资产。
- **代码集中度**：kk-engine 14,678 行 = 全仓 Rust 的 47%，且同时装结算规则、intent 清洗、embed 适配器、Sandbox trait 四类关切。

### 给刻晴的建议（按杠杆排序）

1. 数据面（rkyv 或真正的共享缓冲）落地前，不要用那 80x 微基准对外宣称架构收益——performance-acceptance.md 自己也是这么写的。
2. kk-pathfinder 立刻接进引擎（引擎现已具备结算真实移动，寻路是玩家 API 层的高价值块）。
3. 存储 trait 现在就定义（哪怕只有内存实现），别等 M2 之后再往 Engine 里回填。
4. Sandbox trait 要么让 embed 走它、要么删掉；二选一。
5. 拆 kk-engine：kk-intent / kk-settle / kk-host（适配器）分开，对齐 tick-contract 的阶段划分。
